# E3 baseline — archived 2026-08-02, before the scenario depth-clearance fix

A byte-for-byte copy of E3's three manuscript-facing tier CSVs, as they stood at
commit `54c51e86b7f1fb94e7373e3db5cda92cb831605a`, taken BEFORE Phase 19.3's
synthetic scenario depth-clearance fix regenerates tier 2.

## Why this exists

Every synthetic scenario generated by `generate_board_trajectory` /
`generate_real_rig_trajectory` allowed board corners to protrude through the
water surface. That put the residual on the refractive/pinhole hinge in
`compute_residuals` (the pinhole continuation guard added to fix the `7e0cb90`
absorbing-region defect), which made first-order optimality unreadable as a
convergence diagnostic for every affected experiment
(`.planning/phases/19.3-scenario-geometry-and-convergence/19.3-SEED.md`).

E3 was **added to Phase 19.3's scope after planning** (Amendment A, user-approved
2026-08-02). It was absent from the seed's blast-radius table, but
`e3_derived_quantities` calls `generate_real_rig_trajectory`, so its tier-2
Newton-iteration diagnostics are geometry-dependent. Plan 19.3-05 measured the
resulting movement: **134 mismatched cells** in `newton_iterations.csv`.

That file is the evidence behind **MF-01** (`newton_iterations.csv` measures the
wrong Newton loop). Archiving it before regeneration is what makes the
before/after pair available to MF-08.

**This is not an accuracy defect.** What was broken is the
optimality-as-convergence-diagnostic, not the calibration result. Do not read a
moved E3 number here as evidence the old numbers were wrong — only that the
geometry generating the scenario is corrected.

## What is copied here, and what is not

Copied (small, no `git_sha`/high-entropy content, well under the 1000 KB
`check-added-large-files` limit):

- `code_constants.csv` — tier 1, declared solver constants. **Not**
  geometry-dependent; expected to be unmoved by the re-run.
- `newton_iterations.csv` — tier 2, Newton-iteration diagnostics.
  Geometry-dependent; **expected to move** (134 cells, measured by plan 19.3-05).
- `cpr_grouping.csv` — tier 3, camera/frame-count derived P and group counts.
  **Not** geometry-dependent; expected to be unmoved by the re-run.

**Not** copied: `e3_provenance.json`. It is a minimal sidecar record whose
`environment.git_sha` field is a 40-hex string that `detect-secrets` reads as a
high-entropy hex string — the same reason the E2 precedent
(`experiments/archive/e2-2026-07-30-pre-pnp-guard/`) excluded `benchmark.json`.
`cpr_grouping.tex` is a rendered fragment of `cpr_grouping.csv` and is
retrievable the same way. Retrieve either with:

```bash
git show 54c51e86b7f1fb94e7373e3db5cda92cb831605a:experiments/results/e3_provenance.json
git show 54c51e86b7f1fb94e7373e3db5cda92cb831605a:experiments/results/cpr_grouping.tex
```

## Why it is NOT under `experiments/results/`

`tests/unit/test_experiments_provenance.py` globs `experiments/results/` at
collection time and asserts every discovered artifact carries its provenance
record. Archived copies placed there would be swept into that gate as if they
were live results. This directory is deliberately outside that glob.

## How to use it

After the depth-clearance re-run, diff each regenerated tier CSV against the copy
here:

- `newton_iterations.csv` — movement is **expected** and is the point of the
  re-run. MF-08 reconciles it; MF-01 is re-resolved against it.
- `code_constants.csv` and `cpr_grouping.csv` — movement is **a finding, not a
  nuisance**. Neither is geometry-dependent, so a moved value means something
  unexplained changed. Record it and carry it to plan 19.3-10; do not regenerate
  it away. The queue captures E3's `--check` output BEFORE its `--force`
  precisely so this comparison survives regeneration.

Do not delete this directory until MF-08 is written and the manuscript's numbers
have been reconciled.
