# E1 baseline — archived 2026-08-02, before the scenario depth-clearance fix

Byte-for-byte copies of E1's three manuscript-facing CSVs as they stood at commit
`3d23ddd757d474e974d10d96bccd506d7b564f78`, taken BEFORE Phase 19.3's synthetic
scenario depth-clearance fix.

## Why this exists

Every synthetic scenario generated by `generate_board_trajectory` /
`generate_real_rig_trajectory` allowed board corners to protrude through the
water surface. That put the residual on the refractive/pinhole hinge in
`compute_residuals` (the pinhole continuation guard added to fix the
`7e0cb90` absorbing-region defect), which made first-order optimality
unreadable as a convergence diagnostic for every affected experiment
(`.planning/phases/19.3-scenario-geometry-and-convergence/19.3-SEED.md`).
Phase 19.3 derives a real depth-clearance floor (D-19.3-01) and re-centres
board poses on the board centre rather than a corner (D-19.3-19), then
re-runs E1 (and E4, E5, E6, E7) against the corrected geometry.

**This is not an accuracy defect.** The evidence gathered before the fix
shows reconstruction accuracy is not distinguishable between the
high-optimality and low-optimality groups (D-19.3-11's rationale); what was
broken is the optimality-as-convergence-diagnostic, not the calibration
result. Do not read a moved E1 number here as evidence the old numbers were
wrong — only that the geometry generating the scenario is corrected.

## What is copied here, and what is not

Copied (all small, no `git_sha`/high-entropy content, well under the 1000 KB
`check-added-large-files` limit):

- `exp1_parameter_errors.csv` — §3 focal drift, RMS px, per-camera parameter
  errors
- `exp2_depth_generalization.csv` — depth-generalization RMSE / signed-error
  curves
- `exp3_xy_vs_z_anisotropy.csv` — XY-vs-Z anisotropy ratios

**Not** copied: `e1_benchmark_refractive.json` and
`e1_benchmark_nonrefractive.json`. Both are `assemble_benchmark_record`-shaped
records whose `environment.git_sha` field is a 40-hex string that
`detect-secrets` reads as a high-entropy hex string — the same reason the E2
precedent (`experiments/archive/e2-2026-07-30-pre-pnp-guard/`) excluded
`benchmark.json`. Retrieve them with:

```bash
git show 3d23ddd757d474e974d10d96bccd506d7b564f78:experiments/results/e1_benchmark_refractive.json
git show 3d23ddd757d474e974d10d96bccd506d7b564f78:experiments/results/e1_benchmark_nonrefractive.json
```

## Why it is NOT under `experiments/results/`

`tests/unit/test_experiments_provenance.py` globs `experiments/results/` at
collection time and asserts every discovered artifact carries its provenance
record. Archived copies placed there would be swept into that gate as if
they were live results. This directory is deliberately outside that glob.

## How to use it

After the depth-clearance re-run, diff the regenerated
`exp1_parameter_errors.csv`, `exp2_depth_generalization.csv` and
`exp3_xy_vs_z_anisotropy.csv` against the copies here. Any movement is
expected to be attributable to the depth-clearance/re-centring fix and to
fall inside E1's measured 5-seed band (D-19.3-17) — anything else is a
defect. Do not delete this directory until MF-08 is written and the
manuscript's numbers have been reconciled.
