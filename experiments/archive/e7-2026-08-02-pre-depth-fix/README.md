# E7 baseline — archived 2026-08-02, before the scenario depth-clearance fix

Byte-for-byte copies of E7's six manuscript-facing files, as they stood at
commit `f9843972a879d95b87cbff66f06cc37c54e522c3`, taken BEFORE Phase 19.3's
synthetic scenario depth-clearance fix.

## Why this exists

Every synthetic scenario generated by `generate_board_trajectory` /
`generate_real_rig_trajectory` allowed board corners to protrude through the
water surface. That put the residual on the refractive/pinhole hinge in
`compute_residuals` (the pinhole continuation guard added to fix the
`7e0cb90` absorbing-region defect), which made first-order optimality
unreadable as a convergence diagnostic for every affected experiment
(`.planning/phases/19.3-scenario-geometry-and-convergence/19.3-SEED.md`).
E7's `"realistic"` scenario call (via `create_scenario`) is affected by the
depth-floor change even though its 1.031 m standoff itself is untouched,
because `synthetic.py:822` calls `generate_real_rig_trajectory(depth_range=
(1.1, 2.0))` — the shallow range D-19.3-04 will reject once the floor is
enforced. Phase 19.3 derives a real depth-clearance floor (D-19.3-01),
re-centres board poses on the board centre rather than a corner
(D-19.3-19), and re-runs E7 against the corrected geometry.

**This is not an accuracy defect.** The evidence gathered before the fix
shows reconstruction accuracy is not distinguishable between the
high-optimality and low-optimality groups; what was broken is the
optimality-as-convergence-diagnostic, not the calibration result. Do not
read a moved E7 number here as evidence the old numbers were wrong — only
that the geometry generating the scenario is corrected. Recall also
[[e7-refined-arms-are-seed-unstable]] and [[e7-shared-vs-percamera-is-a-
tendency]] — E7's shared-vs-per-camera comparison is already known to be
seed-sensitive (>10 mm) independent of this fix, so any before/after read
here must be framed against E7's measured 10-seed band (D-19.3-17), not a
single-seed diff.

## What is copied here, and what is not

Copied (all small, no `git_sha`/high-entropy content, well under the
1000 KB `check-added-large-files` limit):

- `interface_ablation.csv` — the R4.2/R4.3 ablation table (48 rows: 4 arms x
  12 cameras)
- `interface_ablation_conditioning.json` — conditioning / singular-value
  spectrum, height-distance correlation (67 KB; no `git_sha` field — this
  file predates `assemble_benchmark_record`'s schema and is listed in
  `SELF_DESCRIBING_JSON` in `tests/unit/test_experiments_provenance.py`)
- `e7_trace_shared_fixed.csv`, `e7_trace_shared_refined.csv`,
  `e7_trace_percamera_fixed.csv`, `e7_trace_percamera_refined.csv` — the
  four arms' optimizer trace panels

**Not** copied: `e7_benchmark_shared_fixed.json`,
`e7_benchmark_shared_refined.json`, `e7_benchmark_percamera_fixed.json`,
`e7_benchmark_percamera_refined.json`. Each is an
`assemble_benchmark_record`-shaped record whose `environment.git_sha` field
is a 40-hex string that `detect-secrets` reads as a high-entropy hex string
— the same reason the E2 precedent
(`experiments/archive/e2-2026-07-30-pre-pnp-guard/`) excluded
`benchmark.json`. Retrieve them with:

```bash

git show f9843972a879d95b87cbff66f06cc37c54e522c3:experiments/results/e7_benchmark_shared_refined.json

git show f9843972a879d95b87cbff66f06cc37c54e522c3:experiments/results/e7_benchmark_percamera_refined.json
```

## Why it is NOT under `experiments/results/`

`tests/unit/test_experiments_provenance.py` globs `experiments/results/` at
collection time and asserts every discovered artifact carries its provenance
record. Archived copies placed there would be swept into that gate as if
they were live results. This directory is deliberately outside that glob.

## How to use it

After the depth-clearance re-run, diff the regenerated
`interface_ablation.csv`, `interface_ablation_conditioning.json` and the
four `e7_trace_*.csv` files against the copies here. Any movement is
expected to be attributable to the depth-clearance/re-centring fix and to
fall inside E7's measured 10-seed band (D-19.3-17) — anything else is a
defect. Do not delete this directory until MF-08 is written and the
manuscript's numbers have been reconciled.
