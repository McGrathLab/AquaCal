# E5 baseline — archived 2026-08-02, before the scenario depth-clearance fix

A byte-for-byte copy of E5's manuscript-facing CSV, as it stood at commit
`aa4c92e4f063c75493c1d4c64cfde555636270be`, taken BEFORE Phase 19.3's
synthetic scenario depth-clearance fix.

## Why this exists

Every synthetic scenario generated by `generate_board_trajectory` /
`generate_real_rig_trajectory` allowed board corners to protrude through the
water surface. That put the residual on the refractive/pinhole hinge in
`compute_residuals` (the pinhole continuation guard added to fix the
`7e0cb90` absorbing-region defect), which made first-order optimality
unreadable as a convergence diagnostic for every affected experiment
(`.planning/phases/19.3-scenario-geometry-and-convergence/19.3-SEED.md`).
`experiments/e5_index_sensitivity.py:188` and `:468` hardcode the shallow
`depth_range=(1.1, 2.0)` and will raise `ValueError` under D-19.3-04 until
updated. Phase 19.3 derives a real depth-clearance floor (D-19.3-01),
re-centres board poses on the board centre rather than a corner
(D-19.3-19), and re-runs E5 against the corrected geometry.

**This is not an accuracy defect.** The evidence gathered before the fix
shows reconstruction accuracy is not distinguishable between the
high-optimality and low-optimality groups; what was broken is the
optimality-as-convergence-diagnostic, not the calibration result. Do not
read a moved E5 number here as evidence the old numbers were wrong — only
that the geometry generating the scenario is corrected.

## What is copied here, and what is not

Copied (small, no `git_sha`/high-entropy content, well under the 1000 KB
`check-added-large-files` limit):

- `index_sensitivity.csv` — the refractive-index sensitivity sweep table

**Not** copied: `e5_provenance.json`. It is a minimal sidecar record whose
`environment.git_sha` field is a 40-hex string that `detect-secrets` reads
as a high-entropy hex string — the same reason the E2 precedent
(`experiments/archive/e2-2026-07-30-pre-pnp-guard/`) excluded
`benchmark.json`. Retrieve it with:

```bash
git show aa4c92e4f063c75493c1d4c64cfde555636270be:experiments/results/e5_provenance.json
```

## Why it is NOT under `experiments/results/`

`tests/unit/test_experiments_provenance.py` globs `experiments/results/` at
collection time and asserts every discovered artifact carries its provenance
record. Archived copies placed there would be swept into that gate as if
they were live results. This directory is deliberately outside that glob.

## How to use it

After the depth-clearance re-run, diff the regenerated
`index_sensitivity.csv` against the copy here. Any movement is expected to
be attributable to the depth-clearance/re-centring fix and to fall inside
E5's measured 5-seed band (D-19.3-17) — anything else is a defect. Do not
delete this directory until MF-08 is written and the manuscript's numbers
have been reconciled.
