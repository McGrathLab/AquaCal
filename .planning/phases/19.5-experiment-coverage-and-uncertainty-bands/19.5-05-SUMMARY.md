# Phase 19.5 Plan 05: E5 Seed Band CLI Summary

**Added a `--seeds` band mode to E5 (index sensitivity) that varies the SEED across the existing `N_ASSUMED_BAND` index sweep, writing artifacts under distinct filenames so it can never be mistaken for E5's pre-existing index band — the exact confusion D-19.3-17 demoted E5's accuracy claim over.**

## Performance

- **Duration:** ~25 min
- **Tasks:** 2 completed
- **Files modified:** 2 (1 created, 1 modified)

## Accomplishments

- `experiments/e5_index_sensitivity.py` gained `E5_SEED_BAND_KEY_COLUMNS`, `_run_seed_band`, a `--seeds` CLI flag, and `_validate_e5_args`, wired into `main`'s dispatch as `_validate_e5_args -> --check -> --seeds -> --smoke -> _run_full`.
- `_run_seed_band` reuses the EXISTING `run_band` (the index band) unmodified inside a `runner(seed)` closure passed to `experiments._io.run_seed_band` — no new band-execution machinery, matching the shared primitive's intended reuse.
- The band writes ONLY `index_sensitivity_seed_band.csv` and `e5_seed_band_provenance.json`; the committed single-seed `index_sensitivity.csv` / `e5_provenance.json` are unreachable from the `--seeds` path (verified by test and by code inspection — `_run_seed_band` never references either filename).
- The sidecar carries `solver_config["seeds"]`, the pre-existing `n_assumed_band`, and a new `scope` string that states in the artifact itself which quantity the band bounds (seed noise) and which it does not (index sensitivity) — discharging D-19.5-05's distinguishability requirement directly in the file, not just by convention.
- `tests/unit/test_e5_band_mode.py` created with the three required classes (`TestCli`, `TestBandMode`, `TestSingleSeedPathUnaffected`), all at `--smoke` scale, all passing.
