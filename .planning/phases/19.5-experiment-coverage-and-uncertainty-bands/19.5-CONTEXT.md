<decisions>
## Implementation Decisions

### D-19.5-01 — Scope is Tier A + Tier B + the E2 band; the basin study is OUT (user, 2026-08-05)

Presented as four selectable groups; the user took three. Tier A is the zero-runtime work
(COV-01, COV-02, COV-08), Tier B the overnight sweeps (COV-03, COV-04, COV-05, COV-06), plus the
E2 replicate band (COV-07). The Stage-2 basin-of-attraction study was offered and declined.

Do not reintroduce the basin study as "while we're in there" scope. If R4.3 turns out to need
empirical backing after the revision drafts, that is a new phase.

### D-19.5-02 — Cheap-first, then ONE risk-first queue (user, 2026-08-05)

Land and verify every zero-runtime item first, then assemble **all** remaining solves into a
single overnight queue under one frozen git sha, following 19.4's `rerun_19_4.sh` pattern.

Rejected alternatives, recorded so they are not silently reopened: a single queue for everything
(longer blind period, no early wins) and interleaving runs as each plan completes (risks the
per-cell `git rev-parse` SHA split that D-19.4 warns about).

**Binding consequence:** commit nothing during the production run. A per-cell `git rev-parse`
splits an artifact's recorded SHA — this is a recorded project lesson, not a hypothetical.

### D-19.5-03 — Experiment scripts only; any hook takes the inert D-32/E3 pattern

COV-02 (FD accuracy) is the one requirement that might want a library-side diagnostic. If it
does, it takes the pattern E3's Newton instrumentation established under D-32: an opt-in flag,
off by default, proven bit-identical to current production output when unset. A hook that cannot
meet that bar is a signal to solve COV-02 entirely inside `experiments/` instead.

Rationale: every published number in `experiments/results/` was regenerated at `2a623f9` and
committed at `0ffbe15`. A non-inert `src` change invalidates that baseline and forces another
full re-run this milestone cannot afford before 2026-08-21.

### D-19.5-04 — The 19.4 fix is the enabler, and it must be re-verified before the queue launches

`generate_camera_array` now returns `water_zs` holding one shared `height_above_water`, so the
grid family's clearance floor is seed-invariant and `GRID_DEPTH_RANGE` is correct by
construction. That is what makes COV-03/COV-04 (E6 seed band and camera-count axis) possible at
all — previously only 29 of 500 seeds were legal, because a calibration draw *and* a holdout draw
both had to clear a frozen floor.

**This was verified at source during scoping, but a prelaunch gate must re-verify it
empirically** — a legality probe over the intended seed list, at each intended `n_cameras`,
before any long stage runs. E4 is the sharper risk: it sweeps `n_cameras` ∈ {8, 12, 16}, giving
up to six independent legality draws per seed.

### D-19.5-05 — Band scope must be stated in the artifact, not just inferred

Every band this phase produces states what it varies and what it therefore bounds. Three are
already known to need the caveat spelled out:

- **COV-07 (E2)** varies the calibration/holdout split on fixed real data. It bounds **split
  variance, NOT measurement variance**. This wording is required in the artifact and in any MF
  entry quoting it.
- **COV-08 bootstrap** resamples the 7,762 committed inter-corner comparisons from one
  calibration. It bounds **metric sampling variance only** — it is not a calibration band and
  must never be presented as one.
- **COV-05 (E5)** must not be confused with E5's existing `n_assumed_band`, which varies the
  assumed refractive index at a single seed and bounds nothing about seed noise. This is exactly
  why D-19.3-17 demoted E5's accuracy claim.

Precedent for why this matters: MF-08 records two separate occasions where a decomposition of
pure noise was nearly published, and a third is recorded in memory as the project's most
recurrent error.

### D-19.5-06 — D-19.3-17 still governs; a band earns a claim, nothing else does

A single-seed before/after supports no accuracy claim however plausible the delta and its
mechanism look. When a band lands, the claim it licenses is bounded by that band and stated with
its n. Where a band is not obtained, the requirement is discharged by saying so plainly — "no
accuracy claim, and here is why" is a passing outcome, not a failure.

### D-19.5-07 — Report what is measured, including nulls and non-significance

Pre-committed: `nfev` ships beside any wall-clock figure (MF-03); optimality is quoted to **one**
significant figure and never finer (it varies ~2x run to run); a band that turns out wide is
reported wide. COV-08's E7 focal/standoff analysis may well come back showing no clean
degeneracy signature in the `refined` arm — that is a reportable result and must not be
retried until it looks better.

### D-19.5-08 — The queue is the orchestrator's job, not an executor's

Per CLAUDE.md: executors that background a long run and return have stalled — five of six did so
in 19.4. Every executor gets a **targeted** test command covering only its own files and an
explicit instruction not to run the full suite or the production queue. The orchestrator runs
the unfiltered `pytest tests/` at the post-merge gate and executes the queue itself.

### Claude's Discretion

- How to decompose COV-01..COV-09 into plans and waves, and how many.
- Seed counts and seed lists per experiment, subject to the runtime budget below. E6 measured
  ~85 min/seed; E2 measured 48-87 min/run. The user has not set a wall-clock ceiling, so the
  planner should propose one and surface the total.
- Whether COV-02's reference Jacobian is Richardson extrapolation, a much tighter step, or both,
  and which problem size it runs on.
- Whether the E4 repeat (COV-06) is the three 100-frame cells or a different subset. Note the
  full grid measured 214 min in 19.4 and three E4 cells peak at 11.3 GiB.
- File layout and naming for new artifacts under `experiments/results/`.

<specifics>
## Specific Ideas

Concrete starting points surfaced during scoping. None is binding on the planner beyond the
requirement text; they exist so the planner does not re-derive them.

- **COV-01** extends E3 tier 3 (`build_cpr_grouping_df`), which already builds a sparsity pattern
  and groups it structurally with no solve. Today it covers N ∈ {3, 8, 12, 13, 16}. The
  `fd_reduction` column already shows the effect: 2.5 at 3 cameras, ~42 at 12x100, ~100 at
  16x200, with `n_groups` pinned at 13 (no intrinsics) / 17 (with intrinsics) throughout. The
  dense→sparse boundary constant is already asserted in `code_constants.csv` as
  `dense_threshold_elements = 500000000`.
- **COV-08 (E7 half)** is pure re-analysis: `interface_ablation_band.csv` already carries
  `focal_drift_pct`, `standoff_m`, `water_z_error_mm` and `camera_height_drift_mm` per camera,
  per arm, per seed, across ten seeds. MF-05 analyzes only `camera_height_drift_mm`. WP6 planned
  the focal/standoff pairing as the refine-ON deliverable and it was never reported.
- **COV-08 (bootstrap half)** resamples `experiments/results/reconstruction_errors.csv`.
- **COV-07** needs `--seed` threaded in `e2_real_rig.py` (currently parsed and logged only, with
  an explicit warning at line 588 saying so). The dataset ships its own `config.yaml`; the seed
  that matters reaches `split_detections` via `config.seed`, wired in Phase 16-06.
- **COV-03/COV-04** run through `e6_generalization_sweep.py`, which already takes `--seed` and
  writes a `seed` column. Its 14 configurations cost ~85 min in total, so ~6 min per
  configuration; three extra `n_cameras` configurations is a small marginal cost on top of a
  seed sweep.
- **E6 exits 0 even when every configuration fails.** Check `status` counts, never the exit code.

</specifics>
