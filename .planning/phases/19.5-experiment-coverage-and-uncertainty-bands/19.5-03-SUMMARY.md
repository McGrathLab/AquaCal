## Decisions Made
- **`n_seeds` redefinition (found during Task 2's real-data run).** The plan's acceptance criteria required "Every row has `n_seeds == 10`". My first implementation defined `n_seeds` as the count of seeds with a *computable* (non-NaN) per-seed correlation, which gave `n_seeds == 0` for both `fixed` arms — their `focal_drift_pct` is identically 0 in every seed (intrinsics_source is `ground_truth_fixed`, never refined), making Pearson correlation mathematically undefined (0/0), not merely near-zero. I revised `n_seeds` to count every seed *present* for the arm in the band (always 10 here), with undefined-correlation seeds contributing to neither sign count and correctly weakening the sign test to `p_one_sided = 1.0` (verdict `no_signature`) rather than being silently dropped. This is a Rule 1 fix (the code's initial behavior did not match the plan's own stated acceptance criterion, and the corrected behavior more accurately represents what "ten committed seeds" means for a structurally-zero-variance arm) — documented here rather than left implicit, and tested with a new `test_constant_focal_drift_counts_seeds_but_gives_no_signature` case.
- **Silenced the expected numpy `RuntimeWarning: invalid value encountered in divide`** from computing correlation on a zero-variance column, via `np.errstate(invalid="ignore")` — this is a known, already-handled (`pd.notna` check) case, not a signal of a real numeric problem elsewhere in the run.
- Followed the plan's `design_decision` verbatim: placed both files under `experiments/` (not `.planning/phases/19.5-.../`) because COV-09 requires a citable committed artifact.

## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 1 - Bug] `n_seeds` undercounted seeds with a structurally-undefined correlation**
- **Found during:** Task 2 (running the CLI against the real committed band)
- **Issue:** `focal_standoff_association`'s first implementation dropped NaN correlations entirely from `per_seed_corr`, so `n_seeds` for both `fixed` arms came back `0` instead of `10` — violating the plan's explicit acceptance criterion "Every row has `n_seeds == 10`". The NaN is not a data-quality problem; it is the correct mathematical result of correlating a column with zero variance (`focal_drift_pct` is exactly 0 in every `fixed`-arm row across all ten seeds and twelve cameras, because those arms never refine intrinsics).
- **Fix:** Redefined `n_seeds` as the total count of distinct seeds present for the arm in the input DataFrame (always 10 for this band). `per_seed_correlation` now keeps a `NaN` entry for undefined seeds rather than omitting them. Sign counts (`n_seeds_negative`/`n_seeds_positive`) and the sign-test denominator both use this total `n_seeds`, so an undefined-correlation seed correctly contributes to neither sign and weakens the test toward `no_signature` rather than vanishing from the record.
- **Files modified:** `experiments/e7_focal_standoff_analysis.py`, `tests/unit/test_e7_focal_standoff.py`
- **Verification:** New test `test_constant_focal_drift_counts_seeds_but_gives_no_signature` asserts `n_seeds == 3`, `p_one_sided == 1.0`, `verdict == "no_signature"` for a hand-built all-zero-variance frame. Full 14-test suite passes. Real-data CLI run confirms all four arms in `e7_focal_standoff.csv` report `n_seeds == 10`.
- **Committed in:** `3ae527c` (Task 2 commit)
