**Proposed wall-clock ceiling: 26 hours.** No ceiling was set by the user; this is the planner's
proposal, surfaced so the number is visible before it is spent. The machine is otherwise idle
during the run, and 26 h of unattended machine time against a 16-day runway is affordable.

**Why 5 seeds and not 10.** A ten-seed unanimous sign test gives p = 2^-10 one-sided; a five-seed
one gives p = 2^-5 = 0.031, which still clears 0.05 one-sided. Below five, nothing is claimable —
three seeds cap out at p = 0.125. Five is the floor for a claim and the ceiling for the budget.
This tradeoff must be stated in the MF entries plan 11 writes, exactly as MF-05 states its own.

**Why E2 gets three and not five.** D-19.5-05 already narrows E2's band to split variance on fixed
data. Three runs support a stated range with n=3; they do not support an interval, and the artifact
must not present one. Seed 42 reproduces the committed record, so the stage also buys a
reproducibility check for free.

**If the ceiling is exceeded**, the orchestrator stops after the currently-running stage completes
and reports which stages landed. Risk-first ordering exists precisely so that the highest-value
stage — `e6_band`, carrying both COV-03 and COV-04 — is banked first.

**Why `e6_band` is first and not the cheapest stage.** It is the longest, it carries two
requirements, and it is the only stage running brand-new code (the `--seeds` band and the
`cameras` axis from plan 06). If it has a defect, the ABORT PROTOCOL requires aborting and
restarting the whole queue from stage 1 — that must happen at hour 1, not hour 18.

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Queue script -> git working tree | A multi-hour unattended process runs against a tree whose sha every artifact records |
| Stage exit code -> success verdict | E4 and E6 record failures as rows and can still exit 0 |
| Frozen sha -> artifact provenance | Any commit during the run splits the recorded sha across artifacts |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-19.5-09-01 | Tampering | A commit landing mid-run, splitting an artifact's recorded `git_sha` | mitigate | `rerun_19_5.sh` performs no tree-mutating git operation (asserted by grep); the ABORT PROTOCOL header restates the prohibition; `gate3_git_sha_consistency` catches a split after the fact |
