**#10 — CORRECTED 2026-08-07, same day.** An earlier version of this SUMMARY read the 14,949
guards on E1's *non-refractive* baseline as evidence the baseline did not converge, and concluded
the E1 band must be written as **upper bounds**. **That was wrong, and it was wrong because it
re-derived a question MF-08 had already answered.**

MF-08 § "E1's 14,949 degenerate observations are bookkeeping, not contamination" establishes that
at `n_water = 1.0` the refractive model reduces to pinhole, so `water_z` cannot affect any
projection while still gating the domain test. It is an **exact null direction**: sweeping `water_z`
over 1.5 m leaves the cost constant to 13 significant figures while the guard count climbs
0 -> 374 -> 5,572 -> 14,949, and the n=1.333 control moves cost by five orders of magnitude over
the same sweep, so the probe is not blind. Re-running both arms with `water_z` pinned at ground
truth reproduces every non-refractive number to ~4 significant figures (deepest-point Z-RMSE
248.267 -> 248.221 mm) while driving the guard count to **0** and optimality from 9e+02 to 5e-01.

So the `xtol` terminations and the 9e+02 optimality are symptoms of an unconstrained null
direction, not a failure to fit. **The refractive-vs-non-refractive comparison is unaffected by the
guard**, and this FAIL is not evidence for an upper-bounds reading. If plan 11 writes "upper
bounds" it needs a different reason than this gate.

## Findings for plan 11

1. **E4's noise floor** (above) — a candidate MF entry in its own right.
2. **E5 is insensitive to small index error.** Across the full swept range of +/-0.010 in assumed
   index, reconstruction MAE moves 0.0040 mm while seed-to-seed sd at each point is 0.0205 mm — the
   effect is buried in seed noise by ~5x. RMSE is the same story (0.0071 mm against sd 0.0396 mm).
   Reprojection RMS is not even monotone in delta_n. Only scale bias responds cleanly, and its full
   +/-0.010 swing (0.0362 -> 0.0607 %) is about two standard deviations of seed noise, while the
   bias at the *correct* index is 0.0483 % — larger than the change the error produces. Scope: one
   synthetic geometry, 30 frames, assumed index varying against fixed truth. **This is a null and
   plan 11 Task 3 exists to keep it from evaporating between CSV and prose.**
3. **E5 may now re-qualify for a banded claim.** It was demoted under D-19.3-17 for varying the
   assumed index rather than the seed. That gap is what this band closes.
4. **E1's 97-178x band has no committed regenerating artifact — found 2026-08-07, BLOCKING for
   plan 11.** MF-08 states the spread "regenerates from `experiments/results/exp1_band.csv`". It
   does not. The deepest-point ratio is built from raw `z_rmse_mm`, which lives only in
   `exp3_xy_vs_z_anisotropy.csv` — **seed 42 only**, 16 rows, no `seed` column
   (248.267 / 1.938 = 128.1x, exactly MF-08's seed-42 row). `exp1_band.csv` is the 10-seed
   artifact but carries `signed_mean_mm`, `rmse_mm` and `scale_factor` only, where `rmse_mm` is a
   **scale-corrected** residual: computing the ratio from it gives **1.1-2.9x**, a different
   quantity by two orders of magnitude.

   So no committed file holds a 10-seed band of the quantity the abstract's headline ratio uses.
   This is precisely what `gate4_band`'s standing FAIL on `exp1_band.csv` has been signalling, and
   it re-frames that FAIL from recording-only bookkeeping to a live provenance gap on the paper's
   most prominent number. **Plan 11 must not write an MF entry citing `exp1_band.csv` for
   97-178x.** Either E1's band mode must also emit `z_rmse_mm` per seed, or the entry must state
   that the band is not regenerable from committed artifacts and name what would make it so.

## Issues Encountered

**`gate3_git_sha_consistency` is blind to the run it certifies.** It PASSed reporting consensus
`2a623f9` — a 19.4-era sha — because `_collect_all_json_paths` walks a fixed legacy set
(`e4_cells/*/benchmark.json`, `e6_configs/*.json`) that excludes this phase's sidecars entirely.
Provenance was therefore verified by hand: of 114 files written in the run window, **92 carry the
frozen sha `2a2f0fa` and none carries any other**. The 22 without one are E2 calibration outputs
that have never carried provenance. The gate needs widening; as it stands it offers false assurance.

**The two seed-band gates were stale at five seeds** and FAILed artifacts that are correct. Fixed in
`8093547`, which then broke seven five-seed fixtures in `test_rerun_gates.py` — they build the seed
list inline rather than importing the constant, so a grep for `_E6_EXPECTED_SEED_COUNT` found no
callers. Fixed in `fbf89d5`, which also corrected
`test_full_queue_seed_list_returns_30_results`: it claimed to probe "the full queue seed list" while
using five seeds, and nothing tied it to the queue's actual list.

**Plan 10's own acceptance criteria carried the same staleness** — five seeds, 30 probe
combinations, a 26 h ceiling — and were corrected to 6 / 36 / 30 h.

**The suite could not be green before the commit.** `test_no_results_dir_modified` and
`test_splice_repeat_test_never_writes_into_committed_results_tree` both assert
`git status --porcelain experiments/results/` is empty, which uncommitted production output cannot
satisfy. Plan 10's step order (suite green, *then* commit) is unsatisfiable as written for these
two tests. They pass after the commit.

**The in-run E2 gate FAIL was an invocation artifact, not a defect.** The queue called the checker
with the band directory as its root, so the committed baseline resolved inside a tree the stage had
just `rm -rf`'d. Run as the plan prescribes, against `experiments/results`, the gate PASSes.

**E4's per-cell `benchmark.json` are overwritten by repeat 2**, so repeat 1's per-stage detail
survives only in `repeat_stdout.log` — which is why that log is committed against the `*.log` rule.
