## THIS PLAN IS THE ORCHESTRATOR'S. DO NOT DELEGATE IT TO A SUBAGENT.

CLAUDE.md, D-19.5-08 and RESEARCH Pitfall 1 all say the same thing: an executor that launches a
multi-hour job and returns has stalled permanently. Five of six executors died this way in phase
19.4, including ones handed a literal poll-loop recipe. The tool's own "you will be notified when
it completes" message is true for the orchestrator and false for a subagent, so prompt hardening
cannot fix it.

The queue is launched detached and polled by the orchestrator:
```
nohup bash experiments/rerun_19_5.sh > experiments/rerun_19_5.log 2>&1 & disown
```
Never `run_in_background`. Never inside a subagent's turn.

<binding_constraints>
1. **Commit nothing between the launch and the queue's completion.** A per-cell `git rev-parse`
   splits an artifact's recorded sha. This is a recorded project lesson, not a hypothetical.
   That includes documentation commits, SUMMARY writes into a tracked path, and STATE updates.
2. **Never edit `src/` or `experiments/` mid-run.** A `src` defect means ABORT and restart the
   whole queue from stage 1. `bash experiments/rerun_19_5.sh N` resume is for infrastructure
   failures only — reboot, sleep, process kill.
3. **Exit codes are not evidence.** E4 and E6 record failures as rows. Read the `status` column
   counts from the written CSVs and the `GateResult`s from `check_rerun_gates.py`.
4. **A quiet log is not a dead run.** Check the process listing before concluding anything. Every
   python invocation in the queue is `python -u`, so a genuinely-progressing stage produces output.
5. **Wall-clock ceiling: 30 hours** (plan 09's runtime budget). If exceeded, stop after the
   currently-running stage completes and report which stages landed. Risk-first ordering means
   `e6_band` — COV-03 and COV-04 — is already banked.
</binding_constraints>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Unattended multi-hour process -> git working tree | Every artifact records the sha the tree carried when it was written |
| Stage exit code -> success verdict | E4 and E6 record failures as rows and can still exit 0 |
| Subagent return text -> evidence of completion | A stalled subagent's text is indistinguishable from a successful one |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-19.5-10-01 | Tampering | A commit landing mid-run and splitting the recorded sha | mitigate | Binding constraint 1; acceptance criterion asserts no commit between launch and completion; `gate3_git_sha_consistency` verifies after the fact |
| T-19.5-10-02 | Repudiation | A stalled subagent reporting the queue as running | mitigate | The queue is never delegated; the orchestrator launches with `nohup ... & disown` and polls with bounded commands |
| T-19.5-10-03 | Repudiation | An all-failed E6 band reported as successful | mitigate | Per-seed `status` counts read out of the CSV and recorded verbatim; exit codes explicitly rejected as evidence |
| T-19.5-10-04 | Tampering | A mid-run `src` edit producing artifacts from two different code states | mitigate | ABORT PROTOCOL: a `src` defect means abort and restart from stage 1, never a midstream edit or a resume |
| T-19.5-10-05 | Denial of Service | The queue overrunning and consuming runway needed by Phases 20-22 | accept | 30-hour ceiling stated and approved at the Task 1 checkpoint; risk-first ordering banks the highest-value stage first |
