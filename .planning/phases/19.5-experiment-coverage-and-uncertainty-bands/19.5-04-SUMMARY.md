## Decisions Made
- Ran three separate `cluster_bootstrap` calls (RMSE, MAE, signed mean), each with an independently-seeded child `Generator` spawned from one `SeedSequence(seed)`, instead of widening `cluster_bootstrap`'s signature to a multi-output statistic. This keeps the pure function exactly as specified in the plan (`statistic` returns one float, `cluster_bootstrap` returns a 1D `NDArray`) at a measured full-run cost of 24.4s for `n_resamples=10000` -- comfortably inside the plan's 300s ceiling, so the 3x recomputation of `reconstruction_statistics` per resample was not worth trading away signature simplicity for.
- Matched E3's provenance sidecar shape (`experiment`, `schema_version`, top-level `seed`, `solver_config: {"seed": seed}`, `environment: capture_environment()`) so the repo-wide provenance gate in `tests/unit/test_experiments_provenance.py` (which discovers every `schema_version`-carrying JSON under `experiments/results/` and checks `environment` keys and `solver_config["seed"]`) picks up the new artifact automatically -- verified live (`test_experiments_provenance.py -k "reconstruction_bootstrap or Environment or Seed or SelfDescribing"`: 74 passed, 6 skipped).
- Used `POINT_ESTIMATE_RTOL = 1e-9` for the `point_estimate_matches_real_rig_metrics` cross-check. Verified the actual relative difference against the committed `real_rig_metrics.json` is exactly 0.0 for RMSE and ~2.15e-16 for MAE (float roundoff), so this tolerance is not a coincidentally-loose pass -- it reflects genuine bit-level agreement between `reconstruction_errors.csv` and the published metrics, both derived from the same E2 run.
