## Decisions Made

- **Band-mode `--smoke` config set trimmed to 2 configurations** rather than the full smoke axis set (which would be 8 rows/5 scenes via `build_smoke_configurations(include_cameras_axis=True)`, also added as general-purpose infrastructure but not used by `_run_seed_band`'s smoke path). Rationale: measured per-configuration smoke-scale solve cost (~30s) makes the full set exceed the plan's 500s pytest budget at 2 seeds (5 scenes x 2 seeds x ~30s ≈ 300s for the band alone, before Task 1's 46 tests and TestSingleSeedPathUnaffected's own cost are added — an earlier attempt at the full 5-scene smoke band ran over 5 minutes for a single test method before being killed). `_band_smoke_configurations()` still exercises everything the acceptance criteria require: the shared baseline scene and the new cameras-axis scene, at both seeds, in isolated directories.
- **`tests/unit/test_e6_band_mode.py`'s real `--smoke --seeds` invocation is run exactly once**, via a module-scoped pytest fixture (`band_run_dir`), and every `TestBandMode`/`TestSeedIsolation` test reads from that one run's artifacts rather than re-invoking `main()`. This differs from `tests/unit/test_e1_band_mode.py`'s pattern (which calls `main()` separately per test) because E1's `"ideal"` smoke scenario is far cheaper than E6's real 12-camera-scale smoke solve; E6's own module docstring already establishes that a real `--smoke` invocation is normally verified by the plan's shell `<verify>` block rather than by pytest, and this fixture-sharing approach is the pragmatic way to satisfy the *new* mandatory isolation-test requirement without violating that established cost discipline.
- **`TestSingleSeedPathUnaffected`'s dispatch tests use monkeypatched stubs** (`_run_smoke`, `_run_seed_band`) instead of a real `--smoke` invocation, for the same cost reason — they prove `main()`'s branching logic without paying for a real solve.

### Auto-fixed Issues

**1. [Rule 1 - Bug] `_run_seed_band`'s smoke path used the full smoke axis set initially, which was too slow for the pytest budget**
- **Found during:** Task 2, while writing `tests/unit/test_e6_band_mode.py`
- **Issue:** The plan's Task 2 action describes `_runner` as running "E6's existing per-configuration loop over `build_axis_configurations(include_cameras_axis=True)`" without specifying a smoke-scale reduction. A first implementation used `build_smoke_configurations(include_cameras_axis=True)` (8 rows / 5 distinct scenes) for the `--smoke --seeds` path; a direct test run exceeded 5 minutes for a single test method (still running when killed) and a separate standalone measurement showed one E6 smoke-scale configuration solve alone costs ~30-31s — 5 scenes x 2 seeds x ~30s ≈ 300s+ for the band alone, which combined with the rest of the test file would have blown the plan's own 500s acceptance-criteria budget.
- **Fix:** Added `_band_smoke_configurations()`, a 2-configuration (1 baseline + 1 cameras-axis) reduced set used only by `_run_seed_band`'s `smoke=True` path. `build_smoke_configurations(include_cameras_axis=True)` (the fuller 8-row/5-scene set) remains available as general-purpose infrastructure but is not what `_run_seed_band` calls for `--smoke`.
- **Files modified:** `experiments/e6_generalization_sweep.py`
- **Verification:** `tests/unit/test_e6_band_mode.py` (14 tests) now completes in 98.78s; the combined suite with `test_experiments_e6.py` (60 tests) completes in 114.39s, both under the 500s budget.
