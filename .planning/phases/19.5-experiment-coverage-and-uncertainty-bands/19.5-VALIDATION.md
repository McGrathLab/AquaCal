# Phase 19.5 — Validation Strategy

> Per-phase validation contract for feedback sampling during execution.

**Shape of this phase, and what it means for validation.** Almost all work lands in
`experiments/`, which is **not** part of the installed package (`pyproject.toml` scopes discovery
to `where = ["src"]`). It is nonetheless well covered: fourteen `tests/unit/test_e*`/
`test_experiments_*`/`test_rerun_gates`/`test_seed_band_io` files already exist, including
per-experiment files for E1, E3, E4, E5 and E6 and band-mode files for E1 and E7. Every new
helper this phase adds is a **pure function** and must be unit-tested as one; the production
solves themselves are validated by `--smoke`, `--check` and the queue gates, not by pytest.

---

## Test Infrastructure

| Property | Value |
|----------|-------|
| **Framework** | pytest (`[tool.pytest.ini_options]` in `pyproject.toml`; one custom marker, `slow`) |
| **Config file** | `pyproject.toml` |
| **Quick run command** | `python -m pytest tests/unit/test_experiments_provenance.py tests/unit/test_rerun_gates.py tests/unit/test_seed_band_io.py -v` |
| **Full suite command** | `python -m pytest tests/` — **orchestrator only** |
| **Estimated runtime** | quick ~20 s; `-m "not slow"` ~26 min; unfiltered 56–88 min (measured, phase 19.4) |

**Executor rule, binding (CLAUDE.md § "Never let a subagent background a long run and return").**
No executor runs the full suite, `-m "not slow"`, or any production-scale calibration. Five of
six executors stalled on exactly this in phase 19.4. Each executor gets a targeted command over
only the files its plan touches, and is told plainly that the orchestrator owns the suite and
the queue.

---

## Sampling Rate

- **After every task commit:** the targeted unit command for that task's files.
- **After every plan wave (orchestrator):** `python -m pytest tests/ -m "not slow"`.
- **After the production queue completes (orchestrator):** unfiltered `python -m pytest tests/`.
  Never during the queue — commit nothing during a production run, or per-cell `git rev-parse`
  splits an artifact's recorded SHA.
- **Before `/gsd:verify-work`:** full suite green.
- **Max feedback latency:** 60 s for per-task commands.
