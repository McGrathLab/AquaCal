## The corrected preserve list — nine paths, derived from the driver, not from prose

`.planning/RETURN-HANDOFF-2026-08-20.md` §2 is the document a planner is most likely to copy, and
its `tar` invocation is **wrong in both directions**: it names `experiments/results_linux32gb`,
which does not exist and never did (the string occurs exactly once in the whole tree, inside a
comment at `experiments/_run_manifest.py:382`), and it omits `experiments/results_e2_invocations`,
`experiments/results_e2_timing` and `experiments/results_e2_memory` — all three real output
trees, holding 119, 6 and 6 files respectively in attempt 1's preserved output.

The authoritative list comes from the driver's own variables
(`run_experiment_suite.sh:264-272`, `:304`, `:309`, `:397-407`) — six output trees plus three
state artifacts:

    experiments/results
    experiments/results_e2_band
    experiments/results_e2_invocations
    experiments/results_e2_timing
    experiments/results_e2_memory
    experiments/results_e4_repeat
    experiments/run_experiment_suite_state.7005a27.tsv
    experiments/run_experiment_suite_state.7005a27.failures.txt
    experiments/run_experiment_suite_state.7005a27.stagelogs

The three E2 `benchmark.json` files live in separate trees on purpose: *"Three E2 runs sharing one
directory would overwrite each other's benchmark.json and the surviving file would silently be
whichever ran last"* (`run_experiment_suite.sh:267-270`). Collapsing them would destroy exactly
the distinction the driver built.

The RETURN-HANDOFF's own good rule survives and is kept: *if any path in that `tar` does not
exist, do not drop it silently — report which trees are missing, because that is itself a finding
about what the run produced.*
