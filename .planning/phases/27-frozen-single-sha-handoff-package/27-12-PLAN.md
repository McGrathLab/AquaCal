<objective>
ROADMAP criterion 2, first half: **the driver runs successfully against a clean checkout of the
frozen sha** — and D-05 puts that verification **on the Linux target**, because it is the only
venue that can catch a Linux-only failure. This closes Phase 26's P26-D-35, which deferred
Linux-side portability verification to exactly here.

This plan does the parts that come before any real computation: clone, build, confirm, dry-run.
Plan 27-13 does the short real stage, the gate roll-up and the smoke pass.

**The highest-value single check in this plan is pre-flight's frameset identity check**, because
it is the only thing that covers the blind spot `--smoke` cannot: a wrong `--config` path or a
bad production YAML. It exercises, on the real data, all of D-09/D-10 (path-kind agnostic),
D-11 (the committed image-set config) and D-12 (the repointed default) at once.

Purpose: prove the frozen sha is runnable where it will run.
Output: `27-ONTARGET-VERIFICATION.md`.
</objective>
