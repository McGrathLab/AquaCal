<objective>
Capture the two pieces of environment provenance the run manifest cannot already record.

**D-13 — the lockfile as a RUN ARTIFACT, not a pre-freeze commit.** `_run_manifest.py` already
emits `python_version`, `numpy_version`, `scipy_version`, `opencv_version`, `opencv_build`,
`installed_distribution_version`, `cpu_model`, `cpu_count_logical`, `ram_total_bytes`, `os`,
`kernel`, `machine`, `git_sha`, `git_describe` and `git_dirty` — every version that moves a
number. The lock adds only the transitive set (matplotlib, pandas, tqdm), which is worth
recording but not worth a freeze-window commit and a forced second tag. **Do NOT tighten
`pyproject.toml`'s pins** — that file is the shipped package's contract, and pinning NumPy
exactly there degrades AquaCal for every pip user to serve one internal run.

**D-14 — record BOTH thread regimes.** The pin applies to stages the pool runs 4–5 wide; the
four `serial_alone` timing stages (`e4`, `e4_repeat`, `e2_timing`, `e2_memory`) are left at the
library default, because every historical measurement was taken unpinned and pinning them would
silently change what is being timed. **If the manifest does not record both regimes and which
stages each covers, the numbers become uninterpretable.**

Purpose: make Phase 29 able to answer "what produced this number".
Output: a lockfile emitter modelled on `_run_manifest.py`, and two new manifest keys.
</objective>
