<objective>
Build the standalone `benchmarks/` runner (BENCH-05, D-12/D-13): a pure aggregator
(`benchmarks/aggregate.py`) that reads every `benchmark.json` under a directory tree,
concatenates them into a tidy `pandas.DataFrame`, and emits a CSV plus a LaTeX table fragment
— computing nothing the pipeline did not already record — and a sweep runner
(`benchmarks/sweep_runner.py`) that drives the cameras x frames grid through
`run_calibration_from_config`. Both are written and unit-tested against fixtures in this
plan; actually executing the real sweep (48-87 minutes per 13-camera run) is explicitly out of
scope for this phase (see Hard Constraints).

Purpose: BENCH-05 is the paper's table-production harness. Keeping it in `benchmarks/` rather
than an `aquacal` CLI subcommand avoids expanding the shipped package's public API surface
immediately before the Phase 22 release cut (D-12). The aggregator's `schema_version` refusal
(D-04) is the load-bearing correctness property: a sweep spanning days and a code change must
never silently blend two incompatible record shapes into one CSV.
Output: `benchmarks/aggregate.py`, `benchmarks/sweep_runner.py`, unit tests with fixture
`benchmark.json` files (including one deliberately mismatched `schema_version`).
</objective>

`"stages"` contains only the stage keys a given run actually executed.

runs the full pipeline and returns a `CalibrationResult`, writing `output_dir/benchmark.json`
as a side effect when `config.save_benchmark` is true (default).
