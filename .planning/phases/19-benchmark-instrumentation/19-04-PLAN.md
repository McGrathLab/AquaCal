<objective>
Declare `psutil` as a new optional `[bench]` dependency extra and create
`src/aquacal/io/benchmark.py` with two pure, never-raising capture functions:
`capture_environment()` (BENCH-04's environment block: versions, OS/CPU, best-effort git SHA)
and `capture_peak_memory()` (BENCH-02's opt-in peak-memory reading, platform-dispatched to a
zero-polling OS high-water-mark read wherever one exists). This plan does not touch the
pipeline or any config flag — it only builds and unit-tests the capture primitives that
Plan 19-05 wires into `run_calibration_from_config`.

Purpose: `psutil` 7.2.2 is already installed in the dev environment but undeclared in
`pyproject.toml` (D-01) — declaring it as an extra rather than a core dependency keeps a
benchmarking aid from becoming a hard install requirement. `tracemalloc` cannot see the
dominant ~3.6 GB `.toarray()` Jacobian allocation (a NumPy C-level allocation, invisible to
Python-heap tracking), so it is fallback-only and must be labelled honestly (D-01, D-02).
Output: `pyproject.toml`'s `[bench]` extra; `capture_environment()` and
`capture_peak_memory()` in `src/aquacal/io/benchmark.py`, covered by unit tests including
forced-missing-dependency paths.
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|--------------|
| `subprocess.run(["git", "rev-parse", "HEAD"])` | Local-only, no attacker-controlled `cwd` or arguments; `cwd` is always resolved from `__file__`, never user input |
| `/proc/<pid>/status` read | Reads only the current process's own status (`os.getpid()`), never an externally-supplied PID |
| New optional dependency `psutil` | Supply-chain surface for a new PyPI package |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|------------------|
| T-19-04-SC | Tampering (supply chain) | `psutil` install via the new `[bench]` extra | accept | Package Legitimacy Audit in 19-RESEARCH.md already verified `psutil` `[OK]` via `slopcheck` (17-year-old, top-100 PyPI package, `github.com/giampaolo/psutil`); disposition Approved, no blocking checkpoint required per the gate protocol (only `[ASSUMED]`/`[SUS]` packages require one) |
| T-19-04a | Tampering | `subprocess.run` git call | mitigate | `cwd` resolved only from `__file__`, never from user input; wrapped in `try/except` + `timeout=5` |
| T-19-04b | Information Disclosure | `/proc/<pid>/status` read | accept | Only ever reads the current process's own PID (`os.getpid()`); no cross-process information exposed |
| T-19-04c | Denial of Service (accidental) | Background polling thread on the untested-platform fallback | mitigate | Explicit `start()`/`stop()` bracketing scoped tightly around the measured region; documented as a fallback exercised only when neither Windows nor Linux zero-poll mechanisms exist |
