Wire everything Plans 19-01 through 19-04 built into `run_calibration_from_config`: thread
`diagnostics_out=SolverDiagnostics()` through the pipeline's four `least_squares`-backed call
sites, add the two opt-in config flags (`save_benchmark`, `benchmark_memory`), and implement

`output_dir/benchmark.json` — problem shape, per-stage solver diagnostics, P/group-count/FD
reduction, solver configuration in force, accuracy copied from the already-computed
`DiagnosticsData`, environment, and (opt-in) **per-stage** peak memory. This is the phase's
central integration plan (BENCH-02, BENCH-03, BENCH-04) and depends on every prior plan's
contract.

**D-18 (locked, post-plan-check): peak memory is recorded PER STAGE, not once per run.** The
first version of this plan narrowed BENCH-02's "peak memory **per stage**" to a single
whole-run reading taken once at the end. That was a scope reduction against the requirement
text and is corrected here. Because `capture_peak_memory()` (Plan 19-04, revised) is now a
cheap, stateless, zero-poll read safe to call at any number of points, this plan calls it once
at EVERY existing stage boundary already marked by `_time_block`/`_time_stage`, and attaches
the reading directly inside that stage's own block in `benchmark.json`'s `"stages"` — never as
a single detached top-level number pretending to answer a per-stage question. Each reading is
labelled honestly as "cumulative peak as of the end of this stage" (the OS high-water mark is
monotonic and non-resettable, so it cannot be a stage-local independent peak), and each stage
also records a `delta_bytes_since_previous_boundary` — the actual answer to "which stage drove
the peak," which is the question the paper asks. A top-level whole-run peak is still recorded
separately, since that is the number quoted in prose.

Purpose: BENCH-04 requires a machine-readable performance record per run, for real-rig and
synthetic runs alike, that a downstream sweep (BENCH-05, Plan 19-06) can aggregate without
recomputing anything. D-04's `schema_version` and D-05's never-fails environment capture make
this record trustworthy across a multi-day sweep spanning code changes.
Output: `output_dir/benchmark.json` written by every `run_calibration_from_config` call when
`config.save_benchmark` (default `True`) is set, with correctly-labelled per-stage memory
attribution when `config.benchmark_memory` (default `False`) is also set.
</objective>
