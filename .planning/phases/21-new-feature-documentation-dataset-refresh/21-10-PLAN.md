## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Zenodo -> every AquaCal user's machine | `load_example` downloads and extracts a 4.4 GB archive from a third-party host |
| manifest.json -> integrity guarantee | The manifest md5 is the reader's only integrity check on the download |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-21-10-01 | Tampering | archive integrity for every downstream user | mitigate | The `checksum` value is transcribed from the pre-upload computation **and** independently confirmed against Zenodo's own md5 display in plan 21-09; Task 2 then proves the whole path end to end from a cold cache, so a wrong value fails here rather than on a user's machine |
| T-21-10-02 | Spoofing | pointing the manifest at the wrong record | mitigate | Automated verify cross-checks all three values against `21-ARCHIVE-MANIFEST.md` and asserts `zenodo_record_id != 18645385` and `size_bytes > 3 GB`; the old 164 MB record cannot pass |
| T-21-10-03 | Tampering | zip extraction path traversal | accept | `download_and_extract` uses the stdlib `zipfile` on an archive we produced ourselves in plan 21-07 and whose md5 is pinned in the manifest; a traversal entry would require the pinned checksum to also match. Hardening `extractall` is a library change out of scope for this phase — recorded, not silently ignored |
| T-21-10-04 | Denial of service | executor stalling on a 4.4 GB download | mitigate | Task 2 is `checkpoint:human-action`, `autonomous: false`, with an explicit do-not-run-from-an-executor banner and `nohup … & disown` |
| T-21-10-05 | Repudiation | irrecoverable cache loss on a failed download | mitigate | The existing cache is moved aside, not deleted, and removed only after verification passes |
| T-21-10-SC | Tampering | package installs | mitigate | Nothing is installed |
</threat_model>
