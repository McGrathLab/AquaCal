  <action>
Create the directory `scripts/` (new — D-11; no `scripts/__init__.py`, it is not package code)
and write `scripts/extract_frames.py` with a module docstring stating that it is a data-prep
utility, not public API, and that it is the producer of the Zenodo `real-rig` archive frameset.

CLI surface (argparse, `build_arg_parser()` + `main(argv) -> int` + `if __name__ == "__main__":
sys.exit(main())`):
  - `--video-dir` (required, Path): directory of `*.avi` files, one per camera.
  - `--out-dir` (required, Path): destination root; per-camera subdirectories are created under it.
  - `--step` (int, default 30): every Nth frame. Default 30 per D-09.
  - `--cameras` (optional, comma-separated): restrict to a subset; default is every `*.avi` found.
  - `--limit` (optional int): stop after N written frames per camera. **Smoke-test aid only** —
    the production run in 21-06 must not pass it.

Camera-name derivation: the camera id is the filename stem up to the first `-`, e.g.
`e3v829d-20260210T104839-105301.avi` -> `e3v829d`. Sort camera ids with `natsort.natsorted` (or
`sorted`, since ids are fixed-width) so the run order is deterministic.

Body: build ONE `VideoSet({camera_id: str(avi_path)})` covering every selected camera, then loop
`for frame_idx, frames in vs.iterate_frames(step=args.step):`. Maintain a per-camera monotonic
write counter `written[cam]` and write each non-`None` frame with
`cv2.imwrite(str(out_dir / cam / f"frame{written[cam]:04d}.png"), frame)` — **`.png` with no
extra flags is lossless by default; do NOT pass `IMWRITE_JPEG_QUALITY` or any compression flag
that changes pixel values** (D-07/D-08). Increment `written[cam]` after each successful write.
Create `out_dir / cam` with `mkdir(parents=True, exist_ok=True)` before the loop.

Verify `cv2.imwrite` returned `True` for every write; on `False`, log the path and return exit
code 1 immediately.

Guards (these exist because Git Bash's Anaconda-base `python` returns `None` from
`VideoCapture.read()` on these AVIs — a silent empty extraction is the failure mode to prevent):
  - After the loop, any camera with `written[cam] == 0` -> log
    `"ERROR: camera %s produced 0 frames — is this the AquaCal conda env?"` and return 1.
  - If the per-camera written counts are not all equal, log each count and return 1 unless
    `--allow-ragged` is passed. (Extrinsic videos are synchronised and must be equal; intrinsic
    videos have differing lengths, so the 21-06 intrinsic pass will pass `--allow-ragged`.)

Logging: `logging.basicConfig(level=logging.INFO, format="%(message)s")`. Emit one INFO line per
camera on completion (`"<camera>: wrote N frames"`) and a final summary line
`"TOTAL: <n_cameras> cameras, <n> frames, <bytes> bytes"` computed by summing written file sizes,
so 21-06's log is self-verifying. Flush progress every 25 written frames per camera.

Return 0 on success.

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| filesystem -> script | `--video-dir` / `--out-dir` are operator-supplied paths; the script writes recursively under `--out-dir` |
| video decoder -> script | `cv2.VideoCapture` output is untrusted in the sense that it silently returns `None` under the wrong interpreter |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-21-01-01 | Tampering | `--out-dir` path handling | mitigate | Camera id is derived from the AVI filename stem, then validated with `re.fullmatch(r"[A-Za-z0-9_-]+", cam)`; reject anything else so a crafted filename cannot produce a `../` path segment |
| T-21-01-02 | Denial of Service | silent zero-frame extraction | mitigate | Zero-frame and ragged-count guards return exit 1; a wrong-interpreter run cannot produce a quietly empty archive |
| T-21-01-03 | Information disclosure | none | accept | Script reads local research video and writes local PNG; no network, no credentials, no secrets |
| T-21-01-SC | Tampering | package installs | mitigate | This plan installs no packages; it imports only already-pinned `opencv-python`, `numpy`, `natsort` from the existing environment |
</threat_model>
