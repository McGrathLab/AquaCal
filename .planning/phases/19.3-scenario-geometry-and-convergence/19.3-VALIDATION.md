# Phase 19.3 — Validation Strategy

> Per-phase validation contract for feedback sampling during execution.

## Test Infrastructure

| Property | Value |
|----------|-------|
| **Framework** | pytest |
| **Config file** | `pyproject.toml` (project convention) |
| **Quick run command** | `~/anaconda3/envs/AquaCal/python.exe -m pytest tests/ -m "not slow" -q` |
| **Full suite command** | `~/anaconda3/envs/AquaCal/python.exe -m pytest tests/ -q` (**UNFILTERED**) |
| **Estimated runtime** | ~90 s quick; full suite substantially longer (slow-marked optimisation tests) |

**Baseline before this phase:** `1168 passed, 6 skipped, 42 deselected, 0 failed` on `-m "not slow"`.

> ⚠ **The full suite must be run UNFILTERED at every wave merge.** The bit-identity and
> frozen-anchor suites are marked `slow`, so `-m "not slow"` silently skips precisely the tests
> that constitute this phase's evidence. This is established project precedent: in Phase 19.2,
> plan 06's launch gate explicitly required an unfiltered run of the five bit-identity suites
> after `-m "not slow"` was found to deselect them. A green `-m "not slow"` run is **not**
> evidence of inertness. This rule is not weakened by any downstream bookkeeping in this document.

---

## Sampling Rate

- **After every task commit:** `pytest tests/ -m "not slow" -q`
- **After every plan wave:** full suite, **unfiltered**
- **Before phase verification:** full unfiltered suite green, PLUS the five experiments'
  production-scale acceptance gates (GEOM-05)
- **Max feedback latency:** ~90 s for the quick loop

## Wave 0 Requirements

**Wave 0 is satisfied by equivalence, not by a separate wave.** This phase has no standalone
Wave 0: every test below is embedded as a `tdd="true"` task inside the wave-1/2/3 plan that produces
the code it covers, with the `<behavior>` block written before the implementation. That satisfies
the Nyquist requirement — no task depends on a MISSING test — while keeping each test in the same
commit as the behaviour it constrains. Recorded here explicitly so the absence of a `wave: 0` plan
is not read as a gap.

- [x] Board-centre pose test (new — the re-centring of D-19.3-19 has no existing coverage)
      → plan 19.3-01, `tdd` task
- [x] Clearance-derivation tests: illegal raises, legal passes, and the floor moves when
      `BoardConfig` / `rotation_range_deg` change (the last one is what proves it is derived
      rather than hardcoded — without it the requirement is unfalsifiable)
      → plan 19.3-01, `tdd` task
- [x] `board`-required test on both generators → plan 19.3-01, `tdd` task
- [x] Guard-count recording test + the exact-equality inertness proof, following 19.2-27's
      pattern precisely (this one is load-bearing: without it E2 re-enters scope)
      → plan 19.3-02, `tdd` task; the inertness suite is `slow`-marked and only counts on an
      UNFILTERED run
- [x] E6 scale-axis legality test across all three `SCALE_AXIS_VALUES` → plan 19.3-06, `tdd` task
      (wave 3 — it depends on the corrected `SCALE_AXIS_VALUES` depth ranges that same plan resolves)
- [x] `DegenerateObservationWarning` text assertion — check first whether one already exists
      before creating it → plan 19.3-02, `tdd` task

*Anything above that already exists under another name is satisfied, not duplicated. This list
reflects what research could not find by grep, not certainty that nothing exists.*
