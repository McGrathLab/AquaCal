## 1. THE HEADLINE RESULT — the scenario-geometry defect is fixed, measured

After waves 1-2, **zero board corners sit at or above the water surface in any scenario.**
Measured directly against each scenario's own corner cloud (not inferred from warnings):

| scenario | corners above interface | shallowest corner clearance |
|---|---|---|
| `realistic` | **0** / 2 640 | +150.5 mm |
| `minimal` | **0** / 880 | +207.3 mm |
| grid 8×50 | **0** / 4 400 | +123.2 mm |
| grid 12×100 | **0** / 8 800 | +71.1 mm |
| grid 16×200 | **0** / 17 600 | +71.1 mm |

Pre-fix baseline on that same 12×100 cell: **61 of 8 800 corners above the surface, worst
protrusion 66.1 mm above.** It is now 71.1 mm below.

The realised clearance (71.1 mm on the grid family) exceeds the `k = 0.1` safety factor's
guaranteed minimum (~13 mm) because the worst-case tilt did not co-occur with the shallowest
sampled depth. The bound is conservative, as intended — this is not evidence that `k` could be
reduced, and `k` must not be tuned in either direction (19.2 anti-pattern #6).

## 2. ⚠ E3 IS A SIXTH AFFECTED EXPERIMENT — NEEDS A DECISION

**Status: OPEN. Not covered by any plan. Surfaced by plan 19.3-05.**

`19.3-SEED.md`'s blast-radius table lists five affected experiments (E1/E4/E5/E6/E7) and
excludes E2 as real data. **E3 is absent from that table but is affected**: it calls
`generate_real_rig_trajectory` (`experiments/e3_derived_quantities.py:331`), so the re-centred,
deeper geometry moves its sampled incidence angles. Plan 19.3-05 reports its
`newton_iterations.csv` baseline now mismatches by **134 cells**.

Plan 05 handed this to plan 19.3-10. **Plan 10 does not cover it** — `grep -i "e3\|newton"`
returns nothing in plans 08, 09 or 10. The handoff has no receiver.

Why it matters: `newton_iterations.csv` is the evidence behind **MF-01** (the supplement's
"two to four steps" Newton claim). If it is left stale, a committed artifact silently disagrees
with the shipped code — the exact defect class this phase exists to eliminate.

Scope assessment:
- **tier 1** (`code_constants.csv`) — declared constants vs source. Not geometry-dependent. Unaffected.
- **tier 2** (`newton_iterations.csv`) — **AFFECTED.**
- **tier 3** (`cpr_grouping.csv`) — P/group counts from camera and frame counts. Expected unaffected; confirm rather than assume.

E3's fast tiers are cheap (minutes, no production calibration), so regenerating is inexpensive.
The orchestrator deliberately did **not** add E3 to the production queue: that is a scope change
the plan-checker never reviewed, and GEOM-05 names five experiments. **Decide before MF-08 is
written**, or MF-08's provenance claim will be false.

## 3. Dropped inter-plan handoff — FIXED by the orchestrator

Plan 19.3-04 identified that `experiments/e1_refractive_comparison.py:478`'s
`smoke_depths = [0.30]` had to move once the preset standoff rose, and handed it to plan
19.3-05. The two plans ran in parallel, so 05 had already finished and never received it —
neither plan owned it at completion.

Left unfixed, E1 `--smoke` **exited 0 while silently producing nothing**: 0.30 m sits above the
new 1.031 m surface, so the reconstruction sweep emitted
`No valid 3D distance comparisons - returning NaN`. A green smoke test that validates nothing is
this phase's own defect class in miniature.

Fixed by the orchestrator: `smoke_depths = [1.30]`, drawn from `TEST_DEPTHS` so the smoke path
exercises a depth the real run also uses. Verified — the NaN warning is gone and the run still
exits 0.

**Lesson for future waves:** a handoff between two plans in the SAME wave has no receiver,
because both are already running. Cross-plan handoffs must go to a LATER wave.

## 4. `DegenerateObservationWarning` still fires on the `ideal` preset — benign, but know why

E1 `--smoke` emits the warning with 12 observations on `create_scenario("ideal")`, and this is
**not** a breached interface — that preset measures 0/1760 corners above the surface with
123.4 mm of clearance.

The cause is the warning's other documented condition: corners the refractive model cannot
project for reasons other than being above water. `ideal` is a 4-camera array at 0.1 m spacing
viewing a 0.6 × 0.42 m board at 1.15 m+, so its outermost corners sit at extreme obliquity.

Consequences:
- Harmless for published results — `ideal` and `minimal` are reachable only from `--smoke` paths.
- **Relevant to plan 19.3-07's harness gate**, which treats a non-zero guard count as
  `status != "ok"`. That is correct for production scenarios (all measured clean above), but a
  smoke run on `ideal` will legitimately trip it. The gate must not be applied to smoke paths,
  or it will report a false failure.
