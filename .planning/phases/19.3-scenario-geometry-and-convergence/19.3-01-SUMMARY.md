# Phase 19.3 Plan 01: Board Clearance Floor and Pose Re-centring Summary

**Derives the board clearance floor from the board's own corner cloud via a deterministic rotation sweep, re-centres board poses on the corner-cloud centroid, and makes `board` a required parameter on both trajectory generators so the clearance check can never be silently bypassed.**

## Performance

- **Duration:** ~85 min
- **Started:** 2026-08-01
- **Completed:** 2026-08-01
- **Tasks:** 3
- **Files modified:** 4

## Accomplishments

- Added `worst_upward_corner_excursion` and `board_clearance_floor` (new public exports of `aquacal.datasets`) that derive the minimum legal board-centre depth from `BoardGeometry(board).corner_positions` and the sampled rotation range -- never a restated constant.
- Re-centred `generate_board_trajectory` and `generate_real_rig_trajectory` so a pose's `tvec` genuinely places the board CENTRE (`tvec = sampled_xyz - R @ centroid_local`), matching the pre-existing (previously false) docstring claim. RNG call order/count is unchanged, so the sampled `(x, y, z, rx, ry, rz)` stream is bit-identical to pre-fix for a given seed -- only `tvec` moves.
- Made `board: BoardConfig` a required keyword-only parameter on both generators (bare `*`), deliberately breaking the codebase's usual "add optional kwarg with a safe default" pattern, because an optional path that could skip the clearance check is the exact defect shape this plan removes.
- `depth_range` now defaults to the derived `(floor, 2.0)` and raises `ValueError` naming both the derived floor and the supplied minimum when an explicit value violates it -- no clamping, no warn-and-continue.
- Updated every direct in-repo test caller (`tests/unit/test_datasets.py`, `tests/unit/test_synthetic_sweep_axes.py`) and `create_scenario`'s three branches to pass `board=` and to use legal `depth_range` values.
- Regenerated the `generate_real_rig_trajectory` / `create_scenario("realistic")` frozen anchor at the new legal derived depth range, following the established "anchors are regenerated deliberately and the regeneration is recorded" pattern.

## Computed Excursion and Floor Values (vs. phase reference figures)

The deterministic sweep (`rx, ry` each `linspace(-theta, theta, 41)`, `rz` `linspace(-pi, pi, 180, endpoint=False)`) computed:

| quantity | reference (CONTEXT.md) | computed | delta |
|---|---|---|---|
| excursion @ 15 deg | 131.3 mm | 132.01 mm | +0.71 mm |
| excursion @ 20 deg | 172.0 mm | 172.90 mm | +0.90 mm |
| floor @ 15 deg (`max(water_zs)=1.0367`) | 1.181 m | 1.1819 m | +0.9 mm |
| floor @ 20 deg (`max(water_zs)=1.0367`) | 1.226 m | 1.2269 m | +0.9 mm |

Both deltas are within the plan's 2 mm tolerance. Per the plan's instruction, the COMPUTED values are what the code and tests use -- `margin_factor` (`k = 0.1`) was never touched to reconcile the small delta, which is attributable to the reference figures having been computed via a 300k-draw Monte Carlo (per CONTEXT.md) versus this plan's deterministic 41×41×180 grid sweep -- a discretization difference, not a modeling error.

For the real-rig generator's own `water_zs` (all cameras exactly `WATER_Z = 1.031`, no interface tilt), the derived floor is **~1.2212 m** at 20 deg -- slightly below the phase's 1.226 m reference figure, because that reference is anchored at `max(water_zs) = 1.0367` (the tilt-varied grid family), while the real-rig array has no interface tilt at all. This is the per-scenario derivation working correctly, not a defect, and is documented in the generator's own docstring.

## Decisions Made

- **Task 1 and Task 2 landed in a single commit (`d156819`).** The plan's own Task 1 action (adding the two derivation functions immediately before `generate_board_trajectory`) and Task 2's rewrite of that same function were authored in one continuous file edit before the first commit checkpoint was reached, so they could not be cleanly split after the fact without an artificial `git add -p` reconstruction that risked introducing an inconsistent intermediate state (Task 1 alone, committed, would leave `generate_board_trajectory` still requiring the old signature while the new derivation functions sat unused). Both tasks' own acceptance criteria (verified via `-k` filtered pytest runs) pass under the combined commit. Documented here rather than silently deviating from the "one commit per task" expectation.
- **`create_scenario`'s three branches were updated in this plan, not deferred to 19.3-04**, even though `synthetic.py:754+` is nominally in plan 19.3-04's scope (D-19.3-09, preset heights/framing). This was necessary because Task 2's signature change (required `board=`) makes `create_scenario` uncallable via `TypeError` otherwise, and the shallow hardcoded `depth_range` literals for `ideal`/`minimal` (0.25-0.45, 0.25-0.40) and `realistic` (1.1-2.0) are now below their own derived floors, which would raise `ValueError`. The fix applied is minimal: `board=default_board` plus `depth_range=None` (derived) -- camera heights, `xy_extent`, `height_variation`, and all other preset framing parameters are untouched, preserving 19.3-04's full scope. This is a Rule-1/Rule-3 auto-fix (blocking issue directly caused by this plan's own signature change), not scope creep into preset design.

## Regenerated Frozen Anchor: Before/After

`generate_real_rig_trajectory(n_frames=100, depth_range=(1.1, 2.0), seed=42)` (pre-fix, corner-pivoted, now illegal since `depth_range[0]=1.1 < floor≈1.221`) vs. `generate_real_rig_trajectory(n_frames=100, board=<default 12x9 board>, depth_range=None, seed=42)` (post-fix, centre-pivoted, derived range):

- **rvec: bit-identical** across all 100 frames -- the RNG call order/count is unaffected by re-centring.
- **tvec: different**, e.g. frame 0: `(0.0435, 0.4644, 1.8727)` (pre-fix) -> `(0.3697, 0.6307, 1.8967)` (post-fix). The XY offset is `-(R @ centroid_local)`'s XY component; the Z offset reflects both the centroid subtraction and the wider derived depth range.
- **Extrinsics and water_zs: unchanged** (the real-rig array construction is untouched by this plan).

Reason: D-19.3-19's re-centring (tvec now places the board CENTRE, not a corner) plus D-19.3-01's derived floor (which makes the old `depth_range=(1.1, 2.0)` illegal for this generator, whose own floor is ~1.221 m). This is intended movement, following the established anchor-regeneration pattern (precedent: the `ideal` anchor regenerated under D-27, commit `4ed8259`).
