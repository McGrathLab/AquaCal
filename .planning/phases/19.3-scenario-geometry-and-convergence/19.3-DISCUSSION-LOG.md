## Depth clearance rule

### Q1 — How should the clearance margin above the derived minimum be set?

| Option | Description | Selected |
|--------|-------------|----------|
| Zero margin, strict bound | Exact worst-case bound with a strict inequality, no additive constant. Cleanest against anti-pattern #6; cost is that the worst-case corner lands asymptotically close to the interface where the Newton solve is near-grazing. | |
| Measured conditioning margin | Measure how close a corner can approach before the refractive Newton solve degrades, set the margin from that. Derived from physics; cost is that it is its own experiment inside the phase. | |
| Fractional margin (e.g. 10%) | `margin = k · clearance_term`, one dimensionless constant scaling with board size and tilt. Cost is that `k` is chosen by feel. | ✓ |
| You decide | — | |

**User's choice:** Fractional margin, k = 10%.
**Notes:** Claude flagged the anti-pattern-#6 tension and proposed the framing that resolves it: the *bound* is derived, `k` is a declared safety factor on a derived quantity, and it must never be adjusted in response to a failing run. That constraint was written into CONTEXT.md as part of the decision rather than left implicit.

Claude verified the derivation before asking. Two bound forms agree numerically for this board — `(half_x + half_y)·sin θ` = 147.5 mm and the exact `√(half_x² + half_y²)·sin(θ√2)` = 147.6 mm — but only by accident of the aspect ratio. Measurement nearly saturates the bound (146.5 mm observed corner reach vs 147.5 mm predicted), confirming it is correct and tight.

### Q1 — How should E6's scale axis be redefined so `half_scale` stays constructible?

Even moving the floor to 1.199 leaves it 84 mm short; clearing the bound would require a baseline floor of 1.367 m, abandoning the real-rig depth D-29 established.

| Drop `half_scale` | Report the axis as two points and state why. Honest, zero design work, but `half_scale` is currently the best-accuracy cell (0.4935 mm). | |
| You decide | — | |

**User's choice:** Anchor scaling at the floor.

**User's choice:** *(free text)* — "in the realistic rig, the board is sized such that it occupies a reasonable amount of the frame at 1-2m. **Notes:** The user rejected all three offered options and supplied a better principle. ## Convergence gate

### Q1 — Where should the strictness live when the guard fires at the converged solution?

| Option | Description | Selected |
|--------|-------------|----------|
| Library records, harness gates | Count on the final solution evaluation, record it, harnesses gate on it. Provably inert; E2 stays out of scope. | ✓ |
| Library raises at solve end | Universal protection, but not provably inert — E2 returns to scope, and a real user with a partly-emergent board gets a hard failure. | |
| Opt-in strict flag | Records by default, raises when set. Two code paths; the default-off path is what users get. | |
| You decide | — | |

**User's choice:** *(free text)* — "I could go either way, what do you think?" → then confirmed **library records, harness gates** after Claude's recommendation.

**Notes:** Claude recommended option 1 on four grounds, led by the physics: the guard firing means the *diagnostic* is invalid, not that the answer is wrong — above the surface pinhole is the physically correct model, and the accuracy evidence (high-optimality group 0.5938 mm vs healthy 0.5622 mm; `half_scale` best in the table at 0.4935 mm) directly contradicts treating it as a wrong answer. Then: inertness keeps E2's freshly re-verified §3 numbers closed, the construction-time `ValueError` already covers the case that matters, and the opt-in flag is option 1 with an untested second path.

Also settled: "at convergence" must mean the **final** residual evaluation. During iteration the guard legitimately fires — that is why `7e0cb90` added it.

## Scheduling correction (raised by the user)

**User's challenge:** *"you said 'three overnights' earlier, citing ~ten hours of runtime -- that feels like one overnight to me?"*

Correct on both counts, and Claude had over-counted twice:

1. The paired determinism sweep costs **+1.8 h, not +3.6** — the production E6 re-run *is* repeat 1 (same code, config and seed), so only one additional pass is needed. Sequence total ≈ **9 h**, not 10.6.
2. **~9 h is one overnight, not three.** The seed's "two overnights" for 7 h was already conservative and Claude compounded it. 19.2's own overnight queue completed waves 4 *and* 5 unattended, 12/12 stages.

What actually determines session count is gating, not compute — which became the next question.

### Follow-up — How should the ~9 h sequence be gated?

| Option | Description | Selected |
|--------|-------------|----------|

| Chained with a checkpoint | Fast three chained, human look before the ~7 h E4+E6 pair. Two sessions. | |

**User's choice:** Chained, automated gates.
