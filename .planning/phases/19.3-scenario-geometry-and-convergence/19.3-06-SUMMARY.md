# Phase 19.3 Plan 06: E6 Scale Axis Floor-Anchoring Summary

**Re-anchors `_scaled_depth_range` at the derived clearance floor instead of the water surface, so `half_scale`/`double_scale` can no longer violate the clearance requirement by construction, and corrects the axis's docstring to describe what it now measures (D-19.3-07).**

## Performance

- **Duration:** ~35 min
- **Completed:** 2026-08-02
- **Tasks:** 2
- **Files modified:** 2

## Accomplishments

- `_scaled_depth_range(factor)` now returns `(GRID_DEPTH_RANGE[0], GRID_DEPTH_RANGE[0] + factor * (GRID_DEPTH_RANGE[1] - GRID_DEPTH_RANGE[0]))` -- the floor is fixed at every factor, only the extent above it scales. Confirmed by direct evaluation:
  - `_scaled_depth_range(0.5) = (1.181852154281008, 1.590926077140504)`
  - `_scaled_depth_range(1.0) = (1.181852154281008, 2.0)` -- exactly `GRID_DEPTH_RANGE`
  - `_scaled_depth_range(2.0) = (1.181852154281008, 2.818147845718992)`
  - Resolved `SCALE_AXIS_VALUES`: `half_scale` depth_range `(1.181852154281008, 1.590926077140504)`, xy_extent `0.41860450308136926`, spacing `0.215`; `default` `(None, None, None)`; `double_scale` depth_range `(1.181852154281008, 2.818147845718992)`, xy_extent `1.674418012325477`, spacing `0.86`.
- Added `test_scale_axis_legal_at_production_frame_count`, which builds every `INDEX_AXIS_VALUES`/`LAYOUT_AXIS_VALUES`/`SCALE_AXIS_VALUES` configuration through `build_grid_scenario` at `BASELINE_N_FRAMES` (100, asserted rather than hardcoded) and confirms no board corner in any frame sits at or above `max(water_zs)` -- construction only, zero `calibrate_synthetic` calls. Satisfies GEOM-03's `pytest tests/unit/test_experiments_e6.py -k scale_axis_legal` selector.
- Rewrote the scale-axis comment block (previously lines ~108-128): removed the stale "does accuracy hold as the whole rig/tank scales up or down together" claim and replaced it with a description of what the axis now measures -- depth extent, `xy_extent`, and `spacing` all scale together above a FIXED board-to-surface standoff/clearance floor -- with the rationale (standoff set by tank/target, not rig size) and a citation of D-19.3-07.
- Updated `test_scale_axis_is_a_factor_of_two_ladder_about_the_new_baseline` (the direct behavior test for `_scaled_depth_range`), which asserted the OLD below-water-surface scaling relationship (`double_below[0] == 4 * half_below[0]`) and failed immediately once Task 1 landed -- confirming the change was real, not a no-op. Rewritten to assert the floor stays fixed across all three scale values and the extent above the floor scales by the expected factor.

## Decisions Made

- Reused `GRID_DEPTH_RANGE[0]` directly as the fixed floor rather than re-deriving it via a second `board_clearance_floor` call in `e6_generalization_sweep.py` -- this is the "import and derive, never restate" pattern the plan required, and it structurally avoids the interface-tilt anchor mismatch D-19.3-07 called out (anchoring on the nominal `GRID_HEIGHT_ABOVE_WATER` instead of `max(water_zs)` would leave `half_scale` ~3mm short even under a corrected definition).
- The legality test covers all three axes (not only `scale`), per the plan's explicit instruction that a legality regression on any axis should be caught by this test, not only the one that changed.
