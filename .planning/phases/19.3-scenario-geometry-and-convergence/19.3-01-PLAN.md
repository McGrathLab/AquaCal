<objective>
Make synthetic board trajectories physically valid: re-centre poses so `tvec` means the board
CENTRE, derive a clearance floor from the board's own corner cloud and the rotation range, and
raise `ValueError` at scenario construction when `depth_range` violates it.

Purpose: board corners protruding through the water surface put the residual on the
refractive/pinhole hinge, which is C0-but-not-C1 and destroys first-order optimality as a
convergence diagnostic. This plan removes the cause.

Output: `board_clearance_floor` (new public export), re-centred generators, a required
`BoardConfig` parameter on both, and the Wave-0 test set that makes the floor falsifiable.
</objective>

  <action>
    Add two module-level functions to `src/aquacal/datasets/synthetic.py`.

    `worst_upward_corner_excursion(board: BoardConfig, rotation_range_deg: float) -> float`
    computes, by deterministic evaluation (NOT a random sample and NOT the `sin(theta*sqrt(2))`
    closed form -- D-19.3-01 rejects both), the largest distance any board corner rises above the
    board-centre pose origin over the generators' rotation sampling box. Build the board-local
    corner cloud from `BoardGeometry(board).corner_positions`, subtract its centroid, then sweep
    `rvec = (rx, ry, rz)` over a fixed grid: `rx, ry` each `numpy.linspace(-theta, +theta, 41)`
    with `theta = deg2rad(rotation_range_deg)`, and `rz` `numpy.linspace(-pi, pi, 180,
    endpoint=False)`. Because a world corner's Z offset is `R[2, :] @ local`, only each rotation's
    third matrix row is needed; use `scipy.spatial.transform.Rotation.from_rotvec(rvecs).as_matrix()[:, 2, :]`
    to build them vectorised, and reduce with a loop over the 88 corners so peak memory stays flat.
    World +Z is DOWN (into water), so "upward" excursion is `max(-(R[2, :] @ local))`. Memoise on
    a hashable key built from the `BoardConfig` field values plus `rotation_range_deg` (module-level
    dict cache); the sweep must not be re-run per frame or per preset import.

    `board_clearance_floor(board: BoardConfig, water_zs: Mapping[str, float],
    rotation_range_deg: float, margin_factor: float = 0.1) -> float` returns
    `max(water_zs.values()) + (1.0 + margin_factor) * worst_upward_corner_excursion(...)`.

    Google-style docstrings with `NDArray` shapes. The `margin_factor` docstring must carry
    D-19.3-02's framing verbatim in substance: the *bound* is derived; `k = 0.1` is a declared
    safety factor on a derived quantity, and it is NEVER adjusted in response to a failing
    scenario -- if a scenario fails the check, the scenario moves.

    Export `board_clearance_floor` and `worst_upward_corner_excursion` from
    `src/aquacal/datasets/__init__.py` and add both to its `__all__` (project rule: every public
    name is exported).

    Add the tests named in `<behavior>` to `tests/unit/test_datasets.py`, with at least one test
