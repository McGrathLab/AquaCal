### `src/aquacal/core/refractive_geometry.py` (new public Newton diagnostic, D-19)

**Analog:** `_refractive_project_newton` in the same file (`refractive_geometry.py:325-419`)
— share the loop body rather than duplicate it (CONTEXT.md's explicit preference).

**Loop to share** (`refractive_geometry.py:384-411`):
```python
# Newton-Raphson iteration
for _ in range(max_iterations):
    d_air_sq = r_p * r_p + h_c * h_c
    d_air = np.sqrt(d_air_sq)
    r_q_minus_r_p = r_q - r_p
    d_water_sq = r_q_minus_r_p * r_q_minus_r_p + h_q * h_q
    d_water = np.sqrt(d_water_sq)
    sin_air = r_p / d_air
    sin_water = r_q_minus_r_p / d_water
    f = n_air * sin_air - n_water * sin_water
    f_prime = n_air * h_c * h_c / (d_air_sq * d_air) + n_water * h_q * h_q / (d_water_sq * d_water)
    delta = f / f_prime
    r_p = r_p - delta
    r_p = max(0.0, min(r_p, r_q))
    if abs(delta) < tolerance:
        break
```
Confirmed defaults: `max_iterations=10`, `tolerance=1e-9` (`refractive_geometry.py:329-330`).
The new public function should refactor this loop into a shared helper returning
`(r_p, n_iterations, final_residual)`, called by both `_refractive_project_newton` (which
discards the count) and the new public function (which returns it) — per CONTEXT.md,
"no bit-exactness risk to guard" since the projection result itself is unaffected either way.
