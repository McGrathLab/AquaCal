## `water_z_error_mm_mean` Origin

`compute_water_z_error_mm_mean(estimated_water_zs, true_water_zs)`: the mean, over cameras present in both dicts, of `abs(estimated_water_zs[cam] - true_water_zs[cam]) * 1000.0` — units millimetres. Called from `compute_configuration_metrics` with `estimated_water_zs = {cam: cal.water_z for cam, cal in result.cameras.items()}` and `true_water_zs = scenario.water_zs`. Unit-tested directly (`test_water_z_error_helper`) against a hand-built pair with a known 3 mm discrepancy on one camera and 0 on the rest, asserting the expected 1.0 mm mean (3 mm / 3 cameras).

## `e6_configs/` Path Shape and Skip Semantics

`{out_dir}/e6_configs/{config_key}.json`, one file per distinct scene (12 files for a complete full-sweep run, 4 for the smoke subset). Each file holds `{"status", "status_reason", "metrics", "seed", "n_frames"}`. When the file already exists and `force` is not set, `run_configuration` returns `status="skipped_existing"` without touching the file or recomputing, and the corresponding row's metric columns are nulled (mirroring E4's per-cell `status != "ok"` null convention) — a resumed run's completeness is judged by whether every configuration has a checkpoint file, not by trusting stale cached numbers into the final CSV.

## Smoke-Mode Configuration Subset and Measured Runtime

`build_smoke_configurations()`: the 3 baseline rows (1 shared scene) plus the first non-baseline value from each axis (`index=1.36`, `layout=ring`, `scale=half_scale`) — 6 rows, 4 distinct scenes, at `n_frames=8` and `refine_intrinsics=False`.

Measured wall-clock for `python -m experiments.e6_generalization_sweep --smoke`: **46.2s** (well under the 300s acceptance budget). One of the 4 scenes (`scale_half_scale`, the smallest working volume at only 8 frames) recorded `status="failed"` with `ConnectivityError: No frames with 2+ cameras detecting the board` — an expected, recorded outcome at this reduced smoke frame count, not a bug (the try/except in `run_configuration` catches it and the row records `status_reason`). The skip-if-exists probe against the already-checkpointed baseline configuration correctly returned `status="skipped_existing"`.

## Decisions Made
- Cached scene metrics keyed by `config_key` (not `(axis, axis_value)`), computed once via an in-memory dict during a single `run_sweep` call and separately checkpointed to `e6_configs/{config_key}.json` on disk, so the three baseline rows never re-run the same 12-camera calibration.
- Held-out reconstruction accuracy is scored using a second `build_grid_scenario` call (different seed) for its `board_poses` only, reusing the first scenario's camera geometry — this avoids a direct call to the underlying `generate_camera_array`/`generate_board_trajectory` generators, satisfying the acceptance gate that the scene is built only through the shared E4 builder.
- `--check` reconstitutes rows from existing `e6_configs/*.json` checkpoints and never re-runs a configuration (mirroring E4's `--check`, not E7's full-rerun `--check`), because a full E6 re-run at production scale would defeat the purpose of a fast comparison check.
