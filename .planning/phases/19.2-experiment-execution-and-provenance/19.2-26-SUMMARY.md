## What landed

An opt-in `discard_stats_out: dict[str, int] | None = None` out-parameter, defaulting to `None`,
threaded from `run_calibration_from_config` down to every non-hot-path site in the calibration path
that silently discards data. Follows plan 19.2-01's `memory_out` pattern: no module-level state, no
control-flow change, inert when omitted.

Counters reach `diagnostics.json` under a top-level `discard_stats` key, via
`save_diagnostic_report(discard_stats=...)` — the same route `frame_rejection` already uses.
**This is what makes plan 19.2-06's D-34 attribution gate runnable**: the degenerate-PnP guard was
previously silent (`return None` at `extrinsics.py:203`/`:214`, four bare `continue` consumers, zero
`logger.` calls in the module), so its rejection count could not be recovered from any artifact.

## Deviations from the plan, and why

1. **Function names.** The plan's `<interfaces>` said `estimate_board_pose_refractive`; the actual
   function is `refractive_solve_pnp`. Used the real names.
2. **More sites than the plan enumerated.** `estimate_board_pose` has *two* failure returns, not
   one: `len(corner_ids) < 4` (line 87) as well as `not success` (line 103). Both are counted.
3. **`refractive_solve_pnp` calls `estimate_board_pose` internally** (line 179). The out-parameter
   is deliberately NOT threaded into that inner call — doing so would count a refractive attempt in
   the non-refractive branch and break the denominator decomposition. That inner failure is counted
   as `pnp_initial_guess_failed` instead. Documented in both functions' docstrings.
4. **The producer/consumer invariant is WHOLE-RUN scoped.** The plan stated it unconditionally.
   Execution disproved that: it holds only when producers are reached *through* consumers, which is
   true of a pipeline run and false of a direct unit-test call. `check_discard_invariants` now
   documents the scope, and `check_denominator_only` exists for the unscoped subset. **The invariant
   caught this itself** — the first test run failed on exactly this case.
5. **`calibrate_from_detections` got its own out-parameter.** It is a public entry point that calls
   `optimize_interface`, so it needed one rather than a hardcoded `None`.
6. **Task 3 was removed before execution** (see the plan's own note). `discard_stats` only reaches
   `diagnostics.json` after Stage 3, so re-deriving the real-rig pair was an unmarked 48–87 min
   production run. That confirmation belongs to plan 19.2-06. **No real-rig pair is recorded here.**

### Root cause — BISECTED to `d5d9dde`, not `7e0cb90`

> ⚠ **An earlier revision of this summary attributed the failure to `7e0cb90` (the PnP guard) and
> raised the possibility that defect 1's inertness claim was incomplete. Both were WRONG.** The
> attribution rested on `git log ... -- src/aquacal/calibration/extrinsics.py`, which was scoped to
> one file and hid twelve other commits touching `src/`. Corrected below by bisection. Retained so
> the error is auditable.

Bisected in an isolated worktree with `PYTHONPATH` pinned to it (verified via `aquacal.__file__`):

| commit | | result |
|---|---|---|
| `7ae7ff6` | docs(19.2-17), the direct parent | **PASS** |
| `d5d9dde` | feat(19.2-18): D-27 centroid-default board trajectory | **FAIL** |
| `7e0cb90^` (`35d76a6`) | before the PnP-guard fix | **FAIL** — already broken |
| `7e0cb90` | the PnP-guard fix | FAIL (inherited) |

**`7e0cb90` is EXONERATED.** The test already failed at its parent. Neither the PnP guard nor the
NaN-clamp replacement moved this number, and **defect 1's inertness claim is not challenged by this
failure.**

**The cause is `d5d9dde` — plan 19.2-18's D-27 change to `src/aquacal/datasets/synthetic.py`**,
which made `generate_board_trajectory` centre its sampled volume on the camera centroid instead of
the origin. Its own commit message says so: *"This is deliberately non-inert for the grid family
(ideal/minimal presets, E4/E6)."* The failing test runs `_run_ideal_pipeline` — the **ideal**
preset, squarely in that family.

**Mechanism, confirmed by measurement.** The ideal preset's four camera centres are
(0,0), (0.1,0), (0,0.1), (0.1,0.1), so the centroid is **(0.05, 0.05)** — 7.07 cm from the origin.
D-27 therefore relocated the board volume by a real, macroscopic amount. `R` and `t` nonetheless
compare exactly equal because the ideal preset is noiseless (the run reports RMS 0.000 px) and
recovers ground-truth extrinsics regardless of where the board sits; only `water_z`, a fitted
parameter, reflects the different optimisation path — hence a 2-ULP difference rather than a
7 cm one. The small magnitude is a red herring: it is not evidence of a small change.

**What went wrong procedurally.** Plan 19.2-18 proved containment for the *realistic* path with
frozen-anchor tests, and explicitly accepted movement for the grid family — but it never updated
plan 19.2-14's `test_matches_pre_change_anchor`, which uses the ideal preset. A known, deliberate
non-inert change was not propagated to every anchor it invalidated.

**Why nobody noticed:** the test is `@pytest.mark.slow`, and the phase's gates have been running
`-m "not slow"`. It was among the 39 deselected in the run the handoff records as "0 failed".

**Why it matters now:** plan 19.2-06's D-26 launch gate requires those suites to pass **with no
marker filter** — precisely because the slow tests are the evidence. As things stand **plan 06 will
halt at Task 1 and never launch E2.**

### Verdict — RESOLVED, anchor regenerated 2026-07-31

The anchor was **legitimately stale**, invalidated by a deliberate, documented, reviewed change.
Regenerated with the cause recorded in `TestSolverConfigSeedIsInert`'s docstring — the class's
"never regenerate" rule is explicitly *superseded once, with cause*, not silently overwritten, and
restated for future mismatches ("the test was failing" is not a cause).

**Capture procedure — and the cross-check it buys.** Values were captured from a tree with
`git status --porcelain src/ tests/` **empty**, i.e. clean `e4bce72` WITHOUT this plan's counters,
via the test class's own `_run_ideal_pipeline`. The anchor therefore predates plan 19.2-26. It then
**passes with this plan's changes applied** — an independent proof of inertness on the full
`run_calibration_from_config` path, stronger than the synthetic-`minimal` evidence in
