### Adjudication: NOT plan 27's instrumentation

Plan 28 makes a moved metric column a hard stop, so this was escalated rather than absorbed, and the
cause was established by evidence rather than assumed:

1. **Iteration counts are identical.** `Function evaluations` across both sweeps:
   `32 4 60 4 73 4 27 4 29 4 19 4 26 4 20 4 20 5 24 6 32 12 29 4` — byte-identical. The solver takes
   the same path, the same number of steps. This rules out termination tie-breaking (`ftol` landing
   on N vs N+1 iterations), which was the first hypothesis and was wrong.
2. **Costs are identical; optimality is not.** Every `initial cost` and `final cost` matches to all
   printed digits, while first-order optimality differs — in one case 4.31e-03 → 2.30e-03, nearly 2×.
3. **That combination has one natural reading.** Near a minimum the cost surface is quadratic: a
   parameter perturbation δ moves cost by O(δ²) and the gradient by O(δ). A ~1e-6 difference in the
   final parameter vector is therefore invisible in cost at printed precision, plainly visible in
   optimality, and shows up in metrics at ~1e-6 — exactly the observed pattern.
4. **The baseline reproduces bit-exactly across three process launches on three days** (E4's grid
   2026-07-30, E6 wave 4 07-31, this run 08-01). So this is NOT blanket arithmetic non-determinism;
   if it were, the baseline would drift too.
5. **The smoke run reproduced bit-identically** against values measured before plan 27 existed.

6. **DECISIVE — the same configuration run twice on identical code gives different answers.** A
   direct probe (`scratchpad/determinism_probe.py`, temp dirs only, nothing in `experiments/results/`)
   ran `scale_half_scale` twice at seed 42 on this exact tree:

   | | reprojection_rms_px | focal_error_pct_mean |
   |---|---|---|
   | run 1 | `1.0071565426644968` | `0.0831694334341944` |
   | run 2 | `1.0071564703805398` | `0.08316997058208937` |
   | delta | −7.2e-8 (rel 7.2e-8) | +5.4e-7 (rel 6.5e-6) |

   No code change can explain a difference between two runs of the SAME code. This settles the
   adjudication on its own; lines 1–5 explain the mechanism.

   **Worth recording:** run 2 landed EXACTLY on the committed wave-4 values (both columns, to the last
   digit) while run 1 did not. The result is not drifting across a continuum — it lands on one of a
   small number of discrete outcomes. **A single "it reproduced!" observation on a marginal
   configuration therefore proves much less than it appears to**; wave 4 and this probe's run 2 would
   have looked like solid reproduction evidence had run 1 not existed.

**Conclusion:** the arithmetic is deterministic; what varies is the final *iterate* of
poorly-conditioned configurations, whose flat cost surface does not pin the parameter vector down.
The likely mechanism is reduction-order variation in the column-grouped finite-difference Jacobian.
Plan 27's sinks are exonerated — they were proven inert by unit test (Task 5), by the bit-identical
smoke run, and by the exact baseline reproduction here.

**Correlation supporting this:** `half_scale` has both the worst optimality in the table AND the
largest run-to-run movement; well-converged rows moved at 1e-9 or not at all.

> **Consequence for regression testing.** Bit-identity is a sound gate on cost, on small problems, and
> on well-conditioned configurations — and is NOT sound on the recovered parameters of marginal ones.
> A test asserting exact equality on `half_scale`'s outputs would be flaky by construction and would
> eventually be "fixed" by loosening it, which is this phase's recorded blocking anti-pattern. Choose
> the gate to match the conditioning of what is being asserted.

## ⚠ Caveat on citing the optimality column itself

**Optimality is the least reproducible number in this artifact.** Between two runs of identical code
it varied by up to ~2× (4.31e-03 → 2.30e-03) while cost stayed identical to all printed digits — it
is, by the mechanism described above, the *most* sensitive observable to a sub-1e-6 change in the
final iterate.

**Cite it as an order-of-magnitude convergence indicator, never as a precise value.** The distinction
it supports is 1e-3 healthy versus 1e1–1e9 broken — which is the distinction that caught MF-04 and
E4's four unconverged cells. It does not support "configuration A converged better than B" when both
sit in the same decade, and no digit beyond the first should be quoted in the manuscript or
supplement.
