### Known Open Defects (disclosed, judged here rather than re-discovered)

Four defects were found during wave 4-6 execution and deliberately left unfixed (no library code changed in those waves). Judgment on each, against the phase goal and EXP-07..11:

1. **E6's `--check` is permanently red** (24/24 NaN mismatches, all three `is_baseline` rows). **Root cause confirmed live**: `layout=grid`/`axis_value=grid` and `scale=default`/`axis_value=default` never match `baseline.json`'s `config_key='baseline'` under WR-03's identity guard. **Judgment: WARNING, not BLOCKER.** The underlying committed data is independently correct (the baseline row reproduces E4's 12x100 cell to the last digit, checked by a different mechanism — cross-experiment agreement, not self-`--check`). But this means E6 currently has **no working mechanical reproduction check at all** — a defect discovered after this fix would have no automated way to be caught for the three baseline configurations. This is exactly the class of gap the phase exists to eliminate (a check that reads as working but silently is not), so it should not be left open indefinitely, but it does not invalidate any number currently published.

2. **E5's attribution language names evidence E5 does not emit** (`discard_stats.pnp_guard_rejected`). **Judgment: WARNING.** The substitute evidence (magnitude comparison + exact source trace, per `.continue-here.md`) is weaker than what plan 23 promised but was not fabricated — it is a real, if less mechanical, form of attribution. Does not affect what is committed.

3. **E6's per-cell `git_sha` is inconsistent** (`baseline.json` = `3d5c3e6`, other eleven = `3d0aa3e`, due to a docs-only commit mid-sweep). **Judgment: INFO, not a gap.** Code was verified identical across both SHAs (per `.continue-here.md`); EXP-11 requires that a git SHA is recorded, which it is for every file — it does not require sweep-wide SHA uniformity, and the two SHAs differ by a documentation commit only.

4. **E6 records no solver diagnostics** (no `optimality` field in any `e6_configs/*.json`), so a diverged solve could in principle be published as `status="ok"`. **Judgment: WARNING, escalated to human_verification below.** This is the same failure class the project has already been burned by twice (E4's grid, MF-04's E2 §3 record) — RMS alone looked publishable on a solve that had not converged. The current E6 sweep was manually checked for exactly this during execution (`layout_line` FIXED, `double_scale` no longer diverges, per `.continue-here.md`), but that check is out-of-band, not mechanically enforced, and will not protect any future re-run of this sweep.

None of the four defects reverses either of the two truths that failed in the prior verification round, and none blocks EXP-07..11 as literally worded. Two (#1 and #4) are flagged for an explicit human decision because they represent unmechanized reproducibility/convergence risk of the same kind this phase was created to close.
