**Status vocabulary and exit-code mapping:**
- `status` ∈ `{"ok", "failed", "skipped_existing"}` — the complete D-04 vocabulary.
- Child exit code `0` → `"ok"`.
- Child exit code `SKIPPED_EXIT_CODE = 3` → `"skipped_existing"` (returned by the `--cell` branch when `write_direct_call_benchmark` skipped an existing file with `force=False`).
- Any other exit code (including a negative signal code or an OS OOM-kill code) → `"failed"`, with `status_reason` carrying `f"child exit_code={code}: {stderr[-400:]}"` and `exit_code` recorded on the row.

## Decisions Made

- **`peak_bytes_baseline` sourcing:** `assemble_benchmark_record` discards the `"_baseline"` memory reading after using it to compute the first real stage's delta — it is never written to its own JSON block. Since `problem_shape` is a free-form passthrough dict, `run_grid_cell` stashes `memory["_baseline"]["peak_bytes"]` there as `problem_shape["peak_bytes_baseline"]`, and `_extract_assembled_row` reads it back via `"problem_shape.peak_bytes_baseline"`. Documented inline at both the write and read sites. E2's row has no equivalent value (E2's `memory` block never had a baseline breakdown either) and is correctly `None`.
- **`--cell`'s allowed-value set:** validated against `DECLARED_CELLS ∪ SMOKE_CELLS` (`_ALLOWED_CELL_VALUES`), not `DECLARED_CELLS` alone. This lets `--smoke` reach the real child-process hop via `run_cell_subprocess` (as the plan requires — "the smoke path must reach the child via the same `run_cell_subprocess` helper ... rather than by loosening the `--cell` validation") while an arbitrary undeclared, non-smoke pair (e.g. `7x13`) is still rejected. Both sets are fixed, enumerated, literal values — never an open-ended range.
- **Two row-extraction functions, not one:** `_extract_assembled_row` reads from an `aggregate()`-produced pandas row (dotted column names, e.g. `"solver_config.normal_fixed"`); `_extract_pipeline_row` reads from E2's raw JSON dict directly (e.g. `record["solver_config"]["interface_normal_fixed"]`). Forcing one shared column-mapping across both would have required either renaming E2's already-committed `benchmark.json` keys (out of scope — `src/` and committed artifacts are frozen per D-26) or silently mismapping `normal_fixed`/`shared_interface` for one of the two row types.
- **Task 1 and Task 2 committed together:** both live in the same file with no natural split point (the scene builder/per-cell runner and the row-assembly/aggregation code are read and reviewed as one coherent module); splitting the commit would have meant an intermediate commit with an incomplete, non-importable module.
