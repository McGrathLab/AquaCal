<objective>
Re-run E2 against the local release frameset with `internals.benchmark_memory: true` so the
committed real-rig record carries stage-attributed peak memory (D-07), and verify that every
section-3 number reproduces exactly (D-08).

Purpose: E4's tenth grid point reuses E2's `benchmark.json` (sequencing constraint 9, EXP-04
precedes EXP-08). Without the memory block, the real row would carry no memory while the nine
synthetic rows do, reintroducing in a second column the comparability problem `record_source` and
`timing_scope` exist to fix.
Output: a refreshed set of committed E2 artifacts whose numbers are provably unchanged, plus a
memory block attributing peak growth to a stage.

**This is a production run, not a test step.** ~50 minutes. Launch with `python -u` in the
background per `CLAUDE.md`; without `-u` the log stays empty for the entire run and a real stall is
indistinguishable from normal progress.

**Why this plan is in wave 1 despite being the phase's longest-running work.** It has no
prerequisites (`depends_on: []`), so wave 1 is where the plan set's own convention puts it. Two
reasons make that placement deliberate rather than incidental:

1. **D-08's determinism argument requires an unmodified `src/`.** Task 2 rests on
   `git diff f193d60..HEAD -- src/` being empty — identical source plus identical frameset plus a
   seeded split must reproduce. Plans 19.2-01, 19.2-02 and 19.2-03 all modify `src/`
   (`datasets/pipelines.py`, `calibration/_observability.py`, `calibration/interface_estimation.py`,
   `calibration/refinement.py`, `core/refractive_geometry.py` — the last of which touches the
   refractive projection path the real rig actually runs). Forking this plan from a base that
   already contains those edits would falsify its own stated premise, and a moved number could no
   longer be cleanly attributed to nondeterminism. Wave 1 keeps the base at `5762d6d`, where the
   premise holds.
2. Starting a ~50-minute run at the earliest possible point gets it off the critical path sooner;
   plan 19.2-07 (E4) blocks on its output, and the phase carries a 2026-08-21 manuscript deadline.

Its `files_modified` are all under `experiments/results/` and collide with no other wave-1 plan
(19.2-01 through 19.2-04 touch only `src/`, `experiments/_io.py`, and `tests/unit/`), so wave-1
parallelism is safe.
</objective>
