this plan set placed it in wave 1 on the argument that D-08's determinism premise required an
unmodified `src/`. **That placement was withdrawn by the user's ordering principle D-26:** *all `src`
changes land, and are proven inert, before any experiment that yields a publishable result.* Three
things forced it:

   `src/`, alongside this plan, whose own acceptance criterion requires `git status --porcelain src/
   experiments/` to be empty at both launch and completion. `files_modified` disjointness held — which
   is why the wave model could not see the conflict — because this plan's constraint is **temporal**
   (`src/` frozen for the duration of the run), not file-based.

   19.2-02's addition to `SolverDiagnostics`, which IS captured on the pipeline path — and plan
   19.2-09 reuses this record as the grid's tenth row, where D-15's element count is
   `n_residuals × n_params`. `solver_config["seed"]` comes from plan **19.2-14**; without it this
   fresh record would fail plan 19.2-12's own `test_every_benchmark_record_carries_a_seed`.
   Running first and carving the two fields out as null-with-reason was offered to the user and
   **rejected**: it would publish a §3 record less complete than the nine synthetic cells beside it.
3. **The determinism argument survives in a stronger form.** See the gate below.

**D-08's hard stop is NOT weakened — only its justification changes.** The premise is no longer
"source is bit-identical to `f193d60`". It is now: **source changed, and every change is covered by a
