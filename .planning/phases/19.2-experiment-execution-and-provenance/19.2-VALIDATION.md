# Phase 19.2 — Validation Strategy

> Per-phase validation contract for feedback sampling during execution.

---

## Test Infrastructure

| Property | Value |
|----------|-------|
| **Framework** | pytest (existing — `tests/unit/` one file per source module, `tests/synthetic/` integration) |
| **Config file** | `pyproject.toml` (pytest config; `slow` marker already registered) |
| **Quick run command** | `python -m pytest tests/unit/test_experiments_*.py tests/unit/test_optim_common.py -x` |
| **Full suite command** | `python -m pytest tests/ -m "not slow"` |
| **Estimated runtime** | ~60 s quick · ~5 min full (874 tests green on `main` as of Phase 19.1) |

**Standing hazard — see `[[worktree-editable-install-resolves-to-main]]`.** The editable install
resolves to the main checkout, so any executor working in a git worktree MUST
`export PYTHONPATH="$(pwd)/src"` or its passing tests are meaningless. This bit during both
Phase 18 and Phase 19.

---

## Sampling Rate

- **After every task commit:** the specific new unit-test file for that script.
- **After every plan wave:** `python -m pytest tests/unit/test_experiments_*.py tests/unit/test_optim_common.py -x`
- **Before `/gsd:verify-work`:** `python -m pytest tests/ -m "not slow"` green, **plus** all four
  new `--smoke` invocations exit 0.
- **Max feedback latency:** ~60 s.

**Long-run carve-out.** E2's re-run (~50 min), E4's grid, E5's band, and E6's sweep are NOT part
of any sampling loop. They are one-shot production runs launched with `python -u` in the
background per `CLAUDE.md`. Their correctness is sampled by the schema/CLI unit tests plus
`--smoke`; their *results* are reviewed as artifacts, not as test outcomes.
