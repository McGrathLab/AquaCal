# Phase 19.2: Code Review Report

**Reviewed:** 2026-07-29
**Depth:** standard
**Files Reviewed:** 26
**Status:** issues_found

## Summary

Reviewed the E3–E6 experiment scripts, the shared `experiments/_io.py` layer, the
library changes they required (`datasets/pipelines.py`, `_observability.py`,
`refractive_geometry.py`, the two Stage-3 sites, `pipeline.py`'s `solver_config`
seed), the CI smoke additions, and the accompanying unit/provenance tests. Two
findings were reproduced by execution against the AquaCal env; the rest are
traced through the code paths and cross-checked against the committed artifacts
under `experiments/results/`.

The seed threading itself is sound: `config.seed` now reaches the pipeline record
(`benchmark_grid.csv`'s `real_rig_13cam_200fr` row carries `seed=42`), the
direct-call path stamps `solver_config["seed"]` without mutating the caller's
dict, and `test_experiments_provenance.py` gates it with an exactly-verified
carve-out. `e3 --check` and `e6 --check` both reproduce their committed baselines
here.

The serious defects cluster in three places:

1. **Resumability is silently lossy in both grid runners.** E4 and E6 both write
   per-cell/per-configuration records to disk specifically so an interrupted run
   can resume, and then both discard those records' metrics on the resume path,
   publishing an all-null CSV. Each module's own `--check` path proves the
   reconstitution is trivial and already implemented three lines away.
2. **`compare_experiment_csv` still has an uncaught crash class** — the third
   instance of the CSV dtype round-trip family this phase has already fixed twice.
   Reproduced live.
3. **A published number's stated provenance is wrong.**
   `refractive_project_newton_diagnostic`'s docstring claims it measures the path
   "used inside every residual evaluation"; the optimizer's residual evaluation
   actually runs a *third, duplicated* Newton loop
   (`_refractive_project_newton_batch`) that the shared-helper refactor did not
   unify and whose termination rule differs.

## Critical Issues

### CR-01: E4 resume path publishes an all-null benchmark grid despite valid per-cell records

**File:** `experiments/e4_benchmark_grid.py:605-608, 836-840`
**Issue:** `run_cell_subprocess` maps a skipped (already-present) cell to
`status="skipped_existing"` (via `SKIPPED_EXIT_CODE`), and `build_grid_dataframe`
then does:

```python
metrics = metrics_by_cell.get((n_cameras, n_frames))
row.update(metrics if metrics is not None else _NULL_METRICS)
if row["status"] != "ok":
    row.update(_NULL_METRICS)
```

`"skipped_existing" != "ok"`, so every cell whose `benchmark.json` already exists
has its metrics nulled — even though `aggregate()` just read them successfully
into `metrics_by_cell`. Resuming an interrupted nine-cell grid without `--force`
(the documented D-24 resumability path, and the only reason the skip exists) is
therefore guaranteed to produce a CSV in which every previously-completed cell is
blank. `_run_check` at line 986-996 already uses the correct rule ("cell file
exists → ok"), which is the proof this nulling is unintended rather than a policy.
Every E4 test uses `status="ok"` fixtures (`full_grid_dir`, line 184-193), so no
test covers this path.
**Fix:** Null metrics only for `failed`, and let `skipped_existing` keep the
on-disk record's metrics:

```python
metrics = metrics_by_cell.get((n_cameras, n_frames))
row.update(metrics if metrics is not None else _NULL_METRICS)
if row["status"] == "failed" or metrics is None:
    row.update(_NULL_METRICS)
```

Add a test that builds the frame with `status="skipped_existing"` and asserts the
metric columns are populated from the cell record.

### CR-02: E6 resume path discards the checkpoint it just wrote for resumability

**File:** `experiments/e6_generalization_sweep.py:463-469, 574-582`
**Issue:** `run_configuration` returns `{"status": "skipped_existing", ...,
"metrics": None}` when `out_dir/e6_configs/{config_key}.json` exists and `force`
is False — it never opens the file. `build_row` then nulls every `_METRIC_COLUMNS`
entry (line 405). The docstring concedes this ("a genuinely resumed CSV still
requires re-running with `force=True`"), which means the checkpoint mechanism
introduced "so an interrupted sweep resumes per configuration instead of
restarting the longest sweep in the phase from zero" (module docstring, line 36-38)
does not actually let the sweep resume — it only lets it skip work and lose the
answer. `_run_check` (lines 634-646) already reads `cached.get("metrics")` and
rebuilds a fully populated row from exactly this file, so the reconstitution
exists and is unused on the write path. Because `write_experiment_csv` skips an
existing CSV, the all-null frame is written precisely in the scenario resumption
targets (crash after the configs completed, before the CSV was written).
**Fix:** On the skip path, load and return the cached outcome instead of nulling:

```python
if config_path.exists() and not force:
    cached = json.loads(config_path.read_text())
    return {
        "status": cached.get("status", "failed"),
        "status_reason": cached.get("status_reason", ""),
        "metrics": cached.get("metrics"),
    }
```

(This also fixes WR-08 below.) Add a test that writes a checkpoint, re-runs with
`force=False`, and asserts the metrics survive.

### CR-03: E4's aggregation aborts (losing the whole run's output) if E2's record is missing or any cell's schema drifts

**File:** `experiments/e4_benchmark_grid.py:162, 843-844, 803`
**Issue:** `build_grid_dataframe` ends with an unguarded
`with open(Path(e2_benchmark_path)) as f: json.load(f)`. `E2_BENCHMARK_PATH` is
the **cwd-relative** `Path("experiments/results/benchmark.json")`, so running the
grid from any other working directory — or before E2's record is present — raises
`FileNotFoundError` *after* all nine cells have been solved, so neither
`benchmark_grid.csv` nor `benchmark_grid.tex` is written and the run's aggregation
is lost. The same applies to `aggregate(cells_dir)` (line 803), which
`_render.aggregate` documents as refusing loudly on an unrecognized
`schema_version`. E3's equivalent copy-source read (`_build_copied_cpr_row`,
lines 425-443) handles the missing file by emitting nulls with
`record_source="missing_e2_benchmark"` and a WARNING — E4 should not be the one
module that dies.
**Fix:** Anchor the path to `__file__` as E3 does
(`Path(__file__).resolve().parents[1] / "experiments" / "results" / "benchmark.json"`),
and degrade rather than raise:

```python
e2_path = Path(e2_benchmark_path)
if not e2_path.exists():
    logger.warning("E2 record not found at %s; emitting a null real-rig row.", e2_path)
    e2_row.update(_NULL_METRICS)
    e2_row["record_source"] = "missing_e2_benchmark"
else:
    e2_row.update(_extract_pipeline_row(json.loads(e2_path.read_text())))
```

### CR-04: `compare_experiment_csv` raises instead of returning a report on two reachable inputs

**File:** `experiments/_io.py:312-323, 354-371`
**Issue:** Both reproduced live against this working tree:

1. **Differing row count / row set.** `fresh_sorted[col] != committed_sorted[col]`
   (line 321) on frames of different length raises
   `ValueError: Can only compare identically-labeled Series objects`. Reachable
   whenever a band or config list is edited (`CPR_CONFIGS`, `N_ASSUMED_BAND`,
   `DECLARED_CELLS`, `*_AXIS_VALUES`) — exactly the change `_find_cpr_row`'s own
   docstring anticipates.
2. **Float-in-fresh vs strings-in-committed.** If a column is float dtype in
   `fresh` (e.g. an all-NaN status column) while the committed baseline carries a
   real string, the column lands in `float_columns` (line 286-291, which ORs the
   two dtypes), `assert_frame_equal` fails as intended, and then the worst-cell
   loop's `committed_sorted[col].to_numpy(dtype=float)` (line 356) raises
   `ValueError: could not convert string to float: "KeyError: 'cam11'"`.

Both cases turn the phase's reproducibility gate into an obscure traceback with no
`ComparisonReport`, no worst-cell identification, and no `exit_code_for` mapping.
This is the same defect family as the two already fixed in `ee8af31` and `ac75e35`
— fixed by analogy each time rather than by making the function total.
**Fix:** Make the comparator total rather than patching dtype cases one at a time:

```python
if len(fresh_sorted) != len(committed_sorted):
    return ComparisonReport(passed=False, worst_cell=..., worst_rtol=float("inf"),
                            n_mismatched_cells=abs(len(fresh_sorted) - len(committed_sorted)),
                            message=f"Row-count mismatch: fresh {len(fresh_sorted)} vs committed {len(committed_sorted)} ({committed_path})")
```

and in the worst-cell loop use
`pd.to_numeric(series, errors="coerce").to_numpy(dtype=float)` on both sides, so a
non-numeric cell inside a "float" column becomes NaN in the report rather than an
exception. Add tests for both inputs (a length mismatch, and a float/NaN fresh
column against a string committed column).

### CR-05: `refractive_project_newton_diagnostic` does not measure the loop the optimizer actually runs

**File:** `src/aquacal/core/refractive_geometry.py:477-481, 546-658`; consumed by
`experiments/e3_derived_quantities.py:257-313` → `newton_iterations.csv`
**Issue:** The diagnostic's docstring states it "performs the identical root-find
as `_refractive_project_newton` — **the shipped projection path used inside every
residual evaluation** — via the shared `_solve_newton_r_p` helper, so the counts
and residual returned here describe production behavior rather than a
re-implementation." The bundle-adjustment residual evaluation does **not** call
`_refractive_project_newton`: `_optim_common.py:635` calls
`refractive_project_batch` → `_refractive_project_newton_batch`, which is a
**third, hand-inlined copy** of the Newton loop (lines 624-645) that
`_solve_newton_r_p` was introduced to prevent ("so a change to the convergence
logic cannot drift between two copies", line 338-340). The batch copy also has a
different termination rule — `np.all(np.abs(delta) < tolerance)`, i.e. no per-point
break and no per-point convergence flag — so `newton_iterations.csv`'s
`n_not_converged=0` column is a property of the scalar path only and is not
measured for the loop that dominates production runtime. A manuscript citing this
table as "production Newton behavior" would be citing the wrong loop, and any
future change to the batch copy will silently desynchronize from the published
table.
**Fix:** Refactor `_refractive_project_newton_batch` to call a vectorized form of
the shared helper (or have `_solve_newton_r_p` accept array inputs), so the
diagnostic and the production batch path share one implementation; until then,
correct the docstring to state explicitly that it measures the scalar
`_refractive_project_newton` path and that `_optim_common`'s residual evaluation
uses the batch variant, and add a test asserting the two loops agree in iteration
count on a shared fixture.

## Warnings

### WR-01: E4 writes the LaTeX fragment unconditionally while the CSV honors `--force`

**File:** `experiments/e4_benchmark_grid.py:1052-1058`
**Issue:** `write_experiment_csv(..., force=args.force)` skips the CSV when it
already exists, but the next line calls `write_grid_latex(df, out_dir /
"benchmark_grid.tex")` with no `force` guard and no `warn_if_overwriting`. A
re-run without `--force` therefore leaves a stale CSV beside a freshly regenerated
`.tex` derived from a different frame — two committed artifacts that silently
disagree. E3's `write_cpr_latex`/`write_derived_values_latex` get this right.
**Fix:** Gate `write_grid_latex` with the same `path.exists() and not force`
check E3 uses, and call `warn_if_overwriting` before writing.

### WR-02: E6 records no solver diagnostics, so a diverged solve is indistinguishable from a converged one

**File:** `experiments/e6_generalization_sweep.py:482-488`; artifact
`experiments/results/generalization_sweep.csv` (`scale_double_scale` row)
**Issue:** `calibrate_synthetic` is called without `diagnostics_out`/`timings_out`,
unlike E4 (`e4_benchmark_grid.py:436-442`). The committed
`scale_double_scale` row is recorded as `status="ok"` with
`reprojection_rms_px=1536.4`, `reconstruction_rmse_mm=1330089` (1.33 km) and
`xy_position_error_mm_mean=476528` (476 m) on a rig whose camera spacing is 0.2 m
— an unmistakably diverged solve published under the same status label as the
converged rows, with nothing in any committed record (no `nfev`, `status`,
`optimality`, no per-config solver block) to distinguish them. Reporting "as
measured" without a verdict column is the stated design; recording no evidence of
convergence at all is not the same thing, and this row directly contradicts the
module's stated finding that accuracy "holds across the sweep".
**Fix:** Pass `diagnostics_out={...}` per configuration and persist
`nfev`/`status`/`optimality`/`cost` into the checkpoint JSON and as columns on the
CSV, so a reader can see the solver's own termination state without a verdict
column being introduced.

### WR-03: E6 checkpoints carry no configuration identity; `--check` re-pairs them at aggregation time

**File:** `experiments/e6_generalization_sweep.py:526-531, 630-646`
**Issue:** The per-configuration JSON stores only `status`, `status_reason`,
`metrics`, `seed`, `n_frames`. `_run_check` re-derives every identity and scene
column (`layout`, `n_water`, `depth_range`, `xy_extent`, `spacing`,
`normal_fixed`, `n_cameras`) from `build_axis_configurations()` **at aggregation
time**. Editing `SCALE_AXIS_VALUES` or `INDEX_AXIS_VALUES` — or changing
`GRID_NORMAL_FIXED` — silently re-labels cached metrics with a configuration that
did not produce them, and `--check` will report a pass. That is the precise
failure mode this phase exists to prevent.
**Fix:** Write the full `config` dict (plus `normal_fixed` and the resolved
`GRID_*` constants) into the checkpoint, and have `_run_check` assert the cached
config matches the recomputed one before reusing its metrics.

### WR-04: E5's committed band records neither `refine_intrinsics` nor `normal_fixed`

**File:** `experiments/e5_index_sensitivity.py:117-135, 356-362, 476-491`
**Issue:** `run_index_point`'s `refine_intrinsics` defaults to `False` and
`_run_full` never overrides it, so the entire production band ran with intrinsics
pinned at ground truth — which `calibrate_synthetic`'s own docstring calls "a
best-case bound, not a realistic scenario". Neither that flag nor
`E5_NORMAL_FIXED` nor the hardcoded `n_frames=30` appears in `E5_COLUMNS`, and E5
writes no JSON sidecar (`CSV_TO_RECORD` records it as "self (own seed column)").
A reader of `index_sensitivity.csv` cannot reconstruct the configuration that
produced it, which is what EXP-11 requires of every published value.
**Fix:** Add `refine_intrinsics`, `normal_fixed`, and `n_frames_calibration`
columns to `E5_COLUMNS` (populated in `build_row`), or emit an E3-style
`e5_provenance.json` sidecar carrying the run configuration, and register it in
`CSV_TO_RECORD`.

### WR-05: E3 `--check` ignores `--seed`

**File:** `experiments/e3_derived_quantities.py:657-700` (line 681), `713`
**Issue:** `_run_check(out_dir)` takes no seed and hardcodes
`build_newton_iterations_df(n_frames=100, seed=42)`. `--check --seed 7` silently
verifies a seed-42 recomputation and reports a pass, so the flag is inert exactly
where reproducibility is being asserted. Relatedly, the sidecar publishes
`args.seed` while `_build_computed_cpr_row` hardcodes `_make_detections(...,
seed=0)`, so the published seed does not describe how `cpr_grouping.csv` was
produced (benign today because `visibility=1.0` makes the pattern
RNG-independent, but the record still misstates its own origin).
**Fix:** Thread `args.seed` (and the tier-2 frame count) into `_run_check`; either
pass the run seed into `_make_detections` or note in the sidecar that tier 3 is
seed-independent by construction.

### WR-06: cwd-relative artifact paths silently change behavior when the cwd differs

**File:** `experiments/e4_benchmark_grid.py:162`,
`experiments/e5_index_sensitivity.py:472-473`,
`tests/unit/test_experiments_provenance.py:27`
**Issue:** Three committed-artifact locations are resolved relative to the process
working directory rather than to `__file__` (E3's `_E2_BENCHMARK_JSON_PATH`, line
153-155, shows the correct pattern and states the rationale). Consequences differ
in severity: E4 crashes (CR-03); E5's `load_holdout_floor_pct` logs a WARNING and
publishes **null** `holdout_floor_pct`/`scale_bias_over_floor` columns — the two
yardstick columns the experiment's whole argument rests on; and the provenance
test module's `pytestmark` skips the *entire* EXP-11 gate when
`experiments/results` is not resolvable, so the mechanical provenance check can
vanish from a run without failing it.
**Fix:** Anchor all three to `Path(__file__).resolve().parents[N]`. For the test
module, keep the fresh-clone skip but base it on the resolved repo-root path.

### WR-07: `compute_per_camera_errors(gauge_correct_z=True)` assumes a reference camera the solver may not have chosen

**File:** `src/aquacal/datasets/pipelines.py:360-369`
**Issue:** The gauge correction takes `camera_names[0]` — the lowest-numbered
`camNN` — as the reference camera, but `calibrate_synthetic` selects the
reference by `min(||C||)` (line 111-114) and `run_calibration_from_config` selects
it by its own rule. When those disagree, the correction subtracts a mean that
includes the pinned reference camera's structurally-zero error and excludes one
genuinely free camera, producing a wrong published `z_position_error_mm` with no
symptom. They happen to agree (`cam0`) for `realistic`, all `generate_camera_array`
layouts, and `generate_real_rig_array`, so this is latent — but
`compute_per_camera_errors` is now a shipped public export (D-06.3). The same
lines also do `int(s.replace("cam", ""))`, which raises `ValueError` for any
camera not named `camNN` (i.e. every real-rig calibration).
**Fix:** Accept the reference camera as an explicit argument (defaulting to
`min(ground_truth.extrinsics, key=lambda c: np.linalg.norm(...C))`, matching the
solver), and sort by name rather than by a parsed integer suffix.

### WR-08: A failed E6 configuration is checkpointed, then silently skipped forever with its reason erased

**File:** `experiments/e6_generalization_sweep.py:516-531, 463-469`
**Issue:** `run_configuration` writes the checkpoint on the failure path too. On
any subsequent non-`--force` run, that configuration is reported as
`skipped_existing` with `status_reason=""`, so the recorded failure reason
(`"KeyError: 'cam11'"` for `layout_line` in the committed artifact) disappears
from the CSV, the configuration is never retried, and a reader sees a blank row
with no explanation. `_run_check` preserves the reason; `_run_full` does not.
**Fix:** Covered by CR-02's fix (returning the cached status *and* reason). Also
consider not treating a `failed` checkpoint as a skip candidate at all.

### WR-09: `run_cell_subprocess` lets a timeout escape, contradicting its documented never-raises contract

**File:** `experiments/e4_benchmark_grid.py:602`
**Issue:** `subprocess.run(..., timeout=timeout)` raises
`subprocess.TimeoutExpired`, which is not caught. The docstring promises "Never
raises on a non-zero child exit -- that is data (D-04), not an exception", and
D-04 requires a failed cell to be a recorded row. A timed-out cell instead
propagates out of `_run_full` and aborts the whole grid before any CSV is written.
Latent today only because the grid path passes `timeout=None`.
**Fix:**

```python
try:
    proc = subprocess.run(cmd, capture_output=True, text=True, timeout=timeout)
except subprocess.TimeoutExpired as exc:
    return {..., "status": "failed",
            "status_reason": f"timeout after {timeout}s", "exit_code": None}
```

### WR-10: `compare_experiment_csv` aligns rows by sorted position, not by key join

**File:** `experiments/_io.py:265-270`
**Issue:** The docstring says the frames are realigned on `key_columns` "not row
index", but the implementation sorts both frames and then compares positionally.
If the two frames' key *sets* differ while their lengths match, rows are compared
against the wrong counterpart; the mismatch is caught only because the key columns
themselves are compared, and the worst-cell report prints `key=` from `fresh` only,
so the message names a row that may not be the committed row being compared
against.
**Fix:** Merge on `key_columns` with `indicator=True`, report `left_only`/
`right_only` keys explicitly as a distinct failure mode, and compare only the
matched rows.

### WR-11: Two provenance tests skip the remaining files when the first is absent

**File:** `tests/unit/test_experiments_provenance.py:306-320, 322-331`
**Issue:** `test_new_phase_csvs_carry_a_seed_column` and
`test_e1_and_e7_records_already_comply_on_environment` call `pytest.skip()` from
inside their `for` loops. A single missing file skips the whole test, so the
remaining two/five files are never checked, and the result is reported as a skip
rather than as partial coverage. This is the "silently weakened gate" pattern the
module docstring says it exists to prevent.
**Fix:** Parametrize over the file list (so a missing file skips only its own
case), or collect the missing names and assert on the ones that are present.

### WR-12: E5 `--check` crashes instead of reporting a missing baseline

**File:** `experiments/e5_index_sensitivity.py:496-522`
**Issue:** `_run_check` re-runs the full band (~11 real calibrations) and then
calls `compare_experiment_csv(df, out_dir / "index_sensitivity.csv", ...)` with no
existence check. If the baseline is absent, `pd.read_csv` raises
`FileNotFoundError` after all that work, instead of the "No committed baseline at
… to check against" message + exit 1 that E3, E4, and E6 all print. Check the
baseline *before* running the band.
**Fix:** Add the existence check at the top of `_run_check`, mirroring
`e4._run_check` lines 975-978.

### WR-13: `newton_iterations.csv`'s `converged`/`residual_max_m` describe the pre-clamp Newton step, not the Snell residual

**File:** `src/aquacal/core/refractive_geometry.py:382-392, 537-543`
**Issue:** `_solve_newton_r_p` computes `delta = f / f_prime`, applies
`r_p = max(0.0, min(r_p, r_q))`, and then records `final_abs_delta = abs(delta)` —
the step *before* clamping. When the clamp is active, the reported step overstates
the actual movement, and `converged = final_abs_delta < tolerance` can report a
clamped-but-stationary point as unconverged (or, symmetrically, mask a clamp).
The published column is also named `residual_max_m` while holding a step size, not
`|f(r_p)|`. The committed table shows `n_not_converged=0` everywhere so no row is
currently affected, but the definition is what a manuscript reader will quote.
**Fix:** Record the post-clamp movement (`abs(r_p_new - r_p_old)`) and/or the
actual Snell residual `abs(f)` at the returned `r_p`, and rename the column to
match whichever is published.
