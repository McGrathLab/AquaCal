<objective>
Make `compare_experiment_csv` total: every reachable input produces a `ComparisonReport`, never a
traceback.

Purpose: closes review finding **CR-04**. This function is the reproducibility gate for every
experiment in the suite — E1, E3, E4, E5 and E6 all route `--check` through it, and waves 3–5 of
this phase depend on it to tell a determinism defect from an expected regeneration. A gate that
raises instead of reporting produces no `ComparisonReport`, no worst-cell identification, and no
`exit_code_for` mapping — the failure looks like a broken script rather than a moved number.

This is a **precondition for wave 3** (D-30). The E4 grid re-run in wave 3 will change row values
and E6's re-run in wave 4 will change row values and may change the *set* of successful rows —
exactly the inputs that crash today.

Output: `experiments/_io.py` with a documented totality contract, plus tests over both live-reproduced
crash inputs.

**Do not "fix" this by adding a third dtype special case.** Two prior commits (`ee8af31`,
`ac75e35`) each patched one dtype round-trip case by analogy to the previous one, and each left the
function partial. The acceptance criteria below require a stated contract and a test that exercises
the general shape, not just the two known inputs.
</objective>

  <behavior>
    - Row-count mismatch (fresh 14 rows, committed 13 rows, same header): returns
      `passed=False` with a message naming both counts and the committed path. No exception.
    - Key-set mismatch at equal length (fresh has key `A`, committed has key `B`): returns
      `passed=False` naming the fresh-only and committed-only keys as a distinct failure mode.
      No exception, and no positional comparison of `A` against `B`.
    - Matching key sets: behaviour is unchanged from today — the same `passed`, the same
      `worst_cell` string, the same `n_mismatched_cells` on every input that works today.
  </behavior>
  <action>
Establish and document a totality contract for `compare_experiment_csv`: **it returns a
`ComparisonReport` for every `(fresh, committed_path, key_columns, rtol)` whose committed file is
readable as a CSV. The only exceptions it may propagate are I/O errors reading `committed_path`.**
State that contract in the docstring in those terms, so the next person extending this function
knows they are extending a total function rather than adding a case.

Restructure the alignment step. Instead of sorting both frames and comparing positionally, align on
`key_columns` explicitly and classify the outcome before any cell-level comparison:

  - If the two key sets are unequal, return a report naming the `left_only` and `right_only` key
    tuples (truncate a long list, but state the full counts). This subsumes the row-count case and
    also closes WR-10's silent mis-pairing.
  - If the key sets are equal but the row counts differ (duplicate keys), return a report saying so.
  - Otherwise, compare only the matched rows, aligned by key, so a worst-cell message always names
    the same row on both sides.

`n_mismatched_cells` for these structural failures should be a defensible count (e.g. the number of
unmatched keys), and `worst_rtol` should be `float("inf")` — matching how the existing header-mismatch
branch already reports a structural failure. Do not change `exit_code_for`.

Preserve every existing behaviour on inputs that already work. The header-mismatch early return
stays first and unchanged. The two prior dtype reconciliations (lines 279–284 and 294–316) stay —
they are correct; they are just not sufficient. Their explanatory comments are the record of why
each exists and must not be deleted or compressed.

Write the tests first: a length mismatch, a key-set mismatch at equal length, and a duplicate-key
case. Assert on `report.passed`, on the substrings the message must contain, and on
`exit_code_for(report)`.
