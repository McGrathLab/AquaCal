<objective>
Make `calibrate_synthetic` able to (a) report per-stage peak memory through a new optional
`memory_out` out-parameter (D-06), (b) honor `scenario.n_air` / `scenario.n_water` when generating
its detections (D-23), and (c) accept a `normal_fixed` passthrough so callers can run tilt-enabled
(review H1) — all three as zero-numerical-change edits guarded by exact-equality tests.

Purpose: E4's nine synthetic grid cells cannot record stage-attributed memory without (a); E6's
refractive-index axis measures nothing without (b) — every scenario in the sweep would be silently
generated at 1.333 and produce a null result that looks like data; and without (c) E4's grid runs
tilt-FIXED while `schema.py`'s `interface_normal_fixed=False` pipeline default, E2's real-rig
point, and every `tab:cpr` row are tilt-ENABLED, so the published grid would describe a solver
configuration two tilt DOF smaller than the one the paper documents — invisibly, because
`solver_config` carries no `normal_fixed` key today.
Output: three new behaviors on one shipped public function, plus six new tests proving none of them
changes an existing caller's numbers.

**Why a passthrough and not a changed default.** `optimize_interface` and `joint_refinement` both
default `normal_fixed=True`. Keeping `calibrate_synthetic`'s new parameter at `True` means E1's and
E7's already-committed Phase-19.1 records stay bit-identical and are never re-run; only the new
experiments opt into `False`. Flipping the library default was considered and rejected on exactly
that ground.
</objective>
