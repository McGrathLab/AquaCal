## What was fixed (commit `7e0cb90`)

**Defect 1 — flat NaN clamp.** `compute_residuals` replaced a failed refractive
projection with the constant 100.0 px. Zero derivative ⇒ exactly-zero Jacobian
rows; a fully-invalid frame opened an exact 6-dim null space (measured rank
339/345, sv_min 2.1e-12, cond 4.1e16); and the invalid region was **absorbing**,
so a lifted board could never come back. Replaced by the pinhole continuous
extension. **Inert** — instrumented branch-hit count of 0 on every converging
configuration. Cannot move committed results.

**Defect 2 — unvalidated `cv2.solvePnP`.** Returns `success=True` on
near-minimal oblique views with `|t|` up to 3.09e12 m; `_refine_poses_multi_frame`
folds that into a weighted mean, poisoning whole cameras to ~1e10 m. Now
self-checked threshold-free: a pose that cannot project a single corner it was
fitted to is rejected. **NOT inert.**

Also `a17331e`: the D-33 pre-flight memory guard is **removed**. It assumed 100%
board visibility, over-projected residuals ~3.76x, and wrongly refused the whole
`n_frames=200` column. A cell too large is now measured, not predicted — OOM
kills only that cell's child, recorded as `status=failed` with its exit code.

And `c511429`: the **20-minute per-cell timeout is also removed** (`CELL_TIMEOUT_
SECONDS = None`). Its derivation assumed ~3 min/cell from the old geometry;
measured cells run 3.4-70 min, so it would have killed healthy cells. **There is
now NO bound on a cell that pages indefinitely without dying** — accepted
deliberately by the user for an attended run. If a future run must be bounded,
derive the value from measured per-cell times, not from the superseded figure.

## RESOLVED — the deltas are seed noise, not an accuracy change

**Read the conclusion at the end of this section before quoting the first
table.** The single-seed comparison below looked like a regression and is
retained only to show how it was disproved.

**Question:** are the deltas the fix correcting previously-wrong numbers, or the
fix introducing error?

**Method:** re-ran E1 to a scratch directory (no committed artifact touched) and
compared `exp1_parameter_errors.csv`, whose columns are referenced to GROUND

### ...BUT THE SEED CHECK OVERTURNS THAT. The deltas are NOISE.

Re-ran E1 at seeds 43 and 44 on the fixed code to measure the noise floor. Seed
variation dwarfs the fix's effect on every metric:

| metric (refractive) | fix delta (s42) | seed range (s42/43/44) | ratio |
|---|---|---|---|
| focal_length_error_pct | +0.00855 | 0.09912 | 11.6x larger |
| z_position_error_mm | +0.00369 | 0.38963 | 105x larger |
| xy_position_error_mm | +0.01421 | 0.26155 | 18.4x larger |

`z_position_error_mm` alone ranges 0.197-0.586 mm across three seeds against a
fix delta of 0.004 mm.

**CONCLUSION: there is no measurable accuracy regression.** The single-seed
comparison above read noise as signal. A one-seed A/B cannot resolve an effect
this small in this experiment. This does NOT prove the fix is exactly neutral —
it removes the evidence that it is harmful, which is a weaker and more honest
claim.

The project already has this lesson recorded from Phase 19.1: *a plausible delta
with a plausible mechanism is not evidence anything changed.* It recurred here
and was caught only by measuring the noise floor. **Any future old-vs-new
comparison on these experiments must establish seed variation before calling a
delta real.**

The earlier assumption ("removing poisoned 1e12 m poses can only help") is still
unproven as stated — it is simply not contradicted.

**Net position for the manuscript:** on configurations that already converged,
the fix has no accuracy effect resolvable above seed noise. On configurations
that were broken it is decisive — optimality 1.6e10 to 1.6e-3, and E4's grid from
2 converged cells to 9. Regenerated numbers WILL differ from published ones
(E1/E5/E7 all moved), but the movement is within the range these experiments
already show across seeds, so it should be described as re-measurement, not as a
change in accuracy.
