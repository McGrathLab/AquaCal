> ## ⚠ AMENDED 2026-08-01 — the bit-identity gate's premise was disproved by plan 28
>
> This plan was written asserting that exact reproduction is the expectation and anything else is a
> defect. **Plan 28 measured otherwise.** Running the SAME configuration TWICE on IDENTICAL code
> produced different answers (`scale_half_scale`: rms rel 7.2e-8, focal rel 6.5e-6). The cause is a
> C0-but-not-C1 kink where board corners cross the water surface and the refractive projection is
> continued with a pinhole extension: the minimum is not uniquely pinned, so the final iterate of a
> marginally-conditioned configuration lands on one of several nearby points.
>
> **The gate is therefore ATTRIBUTION, not equality** — the same correction D-35 applied to plans 22,
> 23 and 24. Ask "is this movement consistent with the measured mechanism?" rather than "is it zero?"
> A gate that still catches unexplained movement is the goal; a gate widened until it passes is the
> failure mode this phase has already hit.
>
> **Concretely:** movement at or below ~1e-5 relative on a column whose configuration emitted
> `DegenerateObservationWarning` is attributable and accepted. Movement larger than that, or on a
> configuration with NO degenerate observations, is unexplained and still halts.
>
> **Also capture, for the follow-on phase:** record each index point's degenerate-observation count
> and optimality from the run log. E5 runs on real-rig geometry whose trajectory generator carries
> the same `depth_range=(1.1, 2.0)` default implicated in E6, so this run is free evidence about how
> far the scenario defect reaches beyond the grid family.

**Reproduction is still the expectation** — same seed, same code path — and a bit-identical result
remains the best outcome. What changed is what a non-identical result means.
</objective>
