<objective>
Re-run E6's three-axis generalization sweep on the redesigned geometry and re-anchor its baseline to
E4's new 12×100 cell.

Purpose: EXP-10 and EXP-11. The committed layout rows are **not trustworthy as a layout comparison**:
under the old geometry each layout got a different board-to-array alignment (a 0.18 m offset for
`grid`, 0.19 m for `ring`, 0.55 m for `line`) and a different fraction of its own footprint covered
(from ±0.75× down to ±0.14×). A `ring` row reading slightly worse than `grid` may have been measuring
a centroid offset rather than anything about ring geometry. D-27 and D-28 removed both confounds; this
plan re-measures on the corrected scenes. The same run supplies the four-field provenance that plan
19.2-16 taught E6 to emit.

**`layout_line` is the headline check.** Its committed row is a failure — `KeyError: 'cam11'` — and
the containment audit attributes it directly to the board never leaving the first ~14% of a `line`
rig because the volume was pinned to cam0, an end camera. If it now succeeds, D-27 did the thing it
was adopted to do. If it still fails, that is a finding to report, not a row to accept quietly.

**This plan runs ALONE on the machine**, in its own wave, after E4's grid (review H4). The
`depends_on` edges to plans 19.2-16, 19.2-18 and 19.2-21 encode a **temporal** constraint — the tree
must be frozen and E4's new 12×100 cell must already exist to anchor against — which
`files_modified` disjointness cannot express.

Output: a re-measured `generalization_sweep.csv`, twelve self-describing checkpoints, and
`e6_provenance.json`.

**Do not change any code in this wave.** If the sweep reveals a code defect, record it and report;
fixing it here would mean half the sweep ran on different code from the other half.
</objective>
