# Phase 19.2 Plan 19: E5 Provenance Sidecar + cwd-Anchoring Summary

E5 now emits an E3-shaped `e5_provenance.json` sidecar carrying its environment, seed,
and full run configuration, and two cwd-dependent behaviours (`_default_metrics_path`,
`_run_check`'s missing-baseline path) were fixed so a re-run from a different working
directory cannot silently degrade the two yardstick columns E5's argument depends on.

## What Was Built

### Task 1 — `build_provenance_sidecar` (experiments/e5_index_sensitivity.py)

Added `build_provenance_sidecar(seed: int) -> dict`, matching
`e3_derived_quantities.build_provenance_sidecar`'s exact shape:

- `experiment: "e5"`
- `schema_version: 1`
- `seed: <seed>`
- `solver_config: {"seed": <seed>}` (duplicated per E3's documented convention — the
  generic schema_version-keyed provenance check reads `solver_config["seed"]`)
- `environment: capture_environment()` — carries all five `REQUIRED_ENVIRONMENT_KEYS`
  (`aquacal_version`, `git_sha`, `python_version`, `numpy_version`, `scipy_version`)

Plus the configuration WR-04 says the CSV alone cannot reconstruct:

- `refine_intrinsics: E5_REFINE_INTRINSICS` (== `False` — **the entire production band
  ran with intrinsics pinned at ground truth**, a best-case bound `calibrate_synthetic`'s
  own docstring names explicitly; the CSV alone never revealed this)
- `normal_fixed: E5_NORMAL_FIXED` (== `False`, i.e. tilt-enabled, matching E2)
- `n_frames: E5_N_FRAMES` (== `30`, newly lifted from a literal in `_run_full`)
- `n_assumed_band: N_ASSUMED_BAND` (the 11-point swept list)
- `n_true: N_TRUE` (== `1.333`)
- `holdout_seed_offset: HOLDOUT_SEED_OFFSET` (== `100_000`)

Two new module constants (`E5_N_FRAMES = 30`, `E5_REFINE_INTRINSICS = False`) were added
so both `_run_full`/`_run_check` and the sidecar builder read the same values — the
record cannot drift from the run.

`_run_full` writes `e5_provenance.json` beside `index_sensitivity.csv`, honoring the same
`--force` discipline the CSV write already uses (skip-with-log if present and not
forced). `E5_COLUMNS` is unchanged; `--smoke` writes into a temp directory as before and
never touches `experiments/results/`.

**`CSV_TO_RECORD` narration change required for plan 19.2-24** (in
`tests/unit/test_experiments_provenance.py`, not touched here per the plan's
instruction): the `index_sensitivity.csv` entry currently reads *"self (own seed
column); no benchmark.json backs it (E5 has no per-row JSON sidecar)"*. It should become
something like: *"self (own seed column) plus experiments/results/e5_provenance.json
(environment/version/git-SHA and run configuration, added 19.2-19)"*.

### Task 2 — Anchored path + guarded `--check` (WR-06, WR-12)

`_default_metrics_path()` previously did
`Path("experiments/results/real_rig_metrics.json").resolve()` — resolved against the
**process working directory**. Now anchored to `Path(__file__).resolve().parents[1] /
"experiments" / "results" / "real_rig_metrics.json"`, matching
`e3_derived_quantities.py`'s `_E2_BENCHMARK_JSON_PATH` pattern exactly.

**Verified from a directory entirely outside the repository** (`/tmp`, not just a
different directory inside it): with only `PYTHONPATH` pointing at `src/` and the repo
root, `import experiments.e5_index_sensitivity as m; m._default_metrics_path()`
returned the correct absolute path and `.exists()` was `True`. This is the two columns
(`holdout_floor_pct`, `scale_bias_over_floor`) that E5's whole argument rests on —
before this fix a foreign cwd degraded both to null with only a WARNING, indistinguishable
at a glance from a determinism defect in wave 5's re-run.

`_run_check` now checks `baseline_path.exists()` **before** calling `run_band` (which
would otherwise re-run all eleven real calibrations, ~22 min) and prints "No committed
baseline at {path} to check against." + returns exit code 1, mirroring
`e4_benchmark_grid._run_check`'s existing-baseline-check pattern.

**Neither change alters any published value when run from the repository root** — this
is how the committed `index_sensitivity.csv` was produced, and it is what makes wave 5's
byte-comparison meaningful. Confirmed by: `--smoke` exiting 0 with
`git status --porcelain experiments/results/` empty afterward, and the full fast suite
passing at 1080/6/39 (up from the 1073/6/39 baseline — 7 new tests, 0 regressions).
