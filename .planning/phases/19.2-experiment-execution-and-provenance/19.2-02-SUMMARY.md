# Phase 19.2 Plan 02: Instrumentation Gap Closure (n_residuals, memory_readings, seed) Summary

One additive diagnostics field (`n_residuals`) wired at three solver call sites, plus two additive
keyword parameters (`memory_readings`, `seed`) on `write_direct_call_benchmark`, closing the two
instrumentation gaps E4's synthetic grid collides with, without touching `io/benchmark.py` or
bumping `schema_version`.

## What Was Built

### Task 1: `SolverDiagnostics.n_residuals`

`src/aquacal/calibration/_observability.py`:
- Added `n_residuals: int | None = None` and `n_residuals_reason: str | None = None` as the last
  two fields of `SolverDiagnostics` (declaration order preserved for every prior field).
- `capture_solver_diagnostics` gained matching keyword-only parameters, assigned onto
  `diagnostics_out` alongside the existing fields. Nothing reads `result.jac` — the value is
  supplied by the caller (`grep -c "result.jac"` unchanged at 6).

Final field list (`dataclasses.fields(SolverDiagnostics)`, in order):
```
nfev, njev, cost, optimality, status, message, ftol, xtol, gtol,
max_nfev_effective, max_nfev_source, n_params, n_params_reason,
n_groups, n_groups_reason, n_residuals, n_residuals_reason
```

Call-site population, verbatim `n_residuals_reason` strings:

- `interface_estimation.py` (Stage-3 first pass, line ~373):
  `n_residuals=jac_sparsity.shape[0] if use_sparse_jacobian else None`, reason:
  `"use_sparse_jacobian=False; no column-grouping structure was built"`
- `refinement.py` (Stage-3 intrinsic pass, line ~280): identical pattern and reason string.
- `interface_estimation.py` (auxiliary registration, line ~725): `n_residuals=None`, reason:
  `"register_auxiliary_camera uses dense 2-point FD; no column-grouping structure exists at this site"`
  (matches the voice of the existing `n_params_reason`/`n_groups_reason` at that site verbatim).

`dataclasses.asdict` flows the field into every `benchmark.json` stage block automatically — no
edit to `src/aquacal/io/benchmark.py` (`grep -c "n_residuals"` there is 0).

### Task 2: `write_direct_call_benchmark(memory_readings=..., seed=...)`

`experiments/_io.py` final signature:
```python
def write_direct_call_benchmark(
    path: Path,
    *,
    problem_shape: dict,
    timings: dict,
    diagnostics: dict[str, "SolverDiagnostics"],
    solver_config: dict,
    accuracy: dict,
    memory_readings: dict | None = None,
    seed: int | None = None,
    force: bool = False,
) -> bool:
```

- `memory_readings` (default `None`) is forwarded to `assemble_benchmark_record(..., memory_readings=memory_readings)`
  in place of the old hardcoded `None`. Omitted, the record shape is byte-identical to E1's/E7's
  committed records (no `memory` key). Supplied, the `_baseline` key survives untouched — it is
  NOT run through the `_SETTLED_STAGE_KEYS` allowlist (that loop still guards only `timings` and
  `diagnostics`).
- `seed` (default `None`) stamps `solver_config["seed"]` into a **shallow copy** of the caller's
  `solver_config` (`solver_config = {**solver_config, "seed": seed}`) — the caller's dict is never
  mutated in place, since E4 reuses one config dict across cells. If the caller's `solver_config`
  already carries a `"seed"` key and `seed` is also given, `ValueError` is raised naming both
  values.
- Docstring verbatim sentence declaring `solver_config["seed"]` a deliberate additive extension,
  not schema drift:

  > `solver_config["seed"]` is a deliberate additive extension of the constraint-10 settled
  > schema, not schema drift: it adds a key INSIDE the pass-through `solver_config` dict, which
  > `assemble_benchmark_record` forwards unmodified and whose key set nothing validates, so it
  > changes no top-level key, no stage block, and requires no schema version bump --
  > `_render.aggregate` continues to flatten it without edit. It is required because EXP-11 and
  > ROADMAP SC5 demand a seed on every committed result and, verified against
  > `e1_benchmark_refractive.json`, no benchmark record carries one today.

- The superseded "Always passes `memory_readings=None` (D-11)" docstring sentence was removed and
  replaced with a paragraph stating the historical behavior is preserved by default and that
  19.1's D-11 deferral is superseded by 19.2's D-24.
- `schema_version` reference count in `experiments/_io.py` is unchanged (0 before, 0 after) — no
  version bump.
