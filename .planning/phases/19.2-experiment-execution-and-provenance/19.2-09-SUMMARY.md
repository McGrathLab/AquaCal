## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 1 - Bug] Fixed a crash in `experiments/_io.py`'s `compare_experiment_csv`**
- **Found during:** Task 3, first invocation of `python -m experiments.e4_benchmark_grid --check` against the real ten-row committed CSV.
- **Issue:** `compare_experiment_csv` crashed with `ValueError: could not convert string to float: ''` instead of returning a `ComparisonReport`. Root cause: the freshly-built comparison frame's `status_reason` column is all empty strings (every declared cell is `status=ok`); that same column, read back from the committed CSV via `pandas.read_csv`, becomes an all-NaN `float64` column (pandas infers float dtype for an all-empty/all-missing text column). The function's float/non-float classifier (`is_float_dtype(fresh) or is_float_dtype(committed)`) then misclassified `status_reason` as a float column and crashed calling `.to_numpy(dtype=float)` on the empty-string side. A secondary discovery: the freshly-built frame's string columns use pandas 3.0's new default `"str"` dtype, which `is_object_dtype` does not recognize -- an `is_object_dtype`-only check would have silently missed this case even after a naive fix.
- **Fix:** Before classifying float vs. non-float columns, any column that is object/string-dtype on the fresh side and float-dtype on the committed side (the empty-string-round-trips-to-NaN signature) is normalized back to object dtype with `""` in place of `NaN` on the committed side, so the exact non-float comparison path handles it correctly.
- **Files modified:** `experiments/_io.py`
- **Verification:** `pytest tests/unit/test_experiments_io.py tests/unit/test_experiments_e4.py -q` -- 35 passed. Full fast suite: `pytest tests/ -m "not slow" -q` -- 967 passed, 39 deselected, no failures. `python -m experiments.e4_benchmark_grid --check` now returns a real `ComparisonReport` instead of crashing.
- **Committed in:** `ee8af31` (fix, Task 3)
- **Scope note:** `experiments/_io.py` is not in this plan's declared `files_modified`, but it is shared infrastructure used by every experiment module (`e1`..`e7`), and the crash directly blocked this plan's own acceptance criterion (`--check`'s exit code and worst-offending-cell must be recorded, which is impossible from an unhandled traceback). No unit test previously exercised a committed CSV with a fully-empty-string column against a same-shape fresh frame, because no prior plan had run `--check` against genuine all-`ok` production data with this column shape.
