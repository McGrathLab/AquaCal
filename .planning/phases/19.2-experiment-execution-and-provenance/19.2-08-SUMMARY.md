# Phase 19.2 Plan 08: E5 Index-Sensitivity Sweep Machinery Summary

**Built `experiments/e5_index_sensitivity.py`: a real-rig-geometry sweep of the assumed refractive index (`n_water`) that scores held-out reprojection RMSE and depth/scale bias against both an internal Δn=0 control and E2's live-read noise floor, using the shipped `calibrate_synthetic` path with no new library parameter.**

## Performance

- **Duration:** ~35 min (dominated by a ~20-25 min `python -m experiments.e1_refractive_comparison --check` run proving the formula extraction is pure)
- **Tasks:** 2
- **Files modified:** 3 (1 modified, 2 created)

## Accomplishments

- Extracted the inline scale-bias expression in `e1_refractive_comparison.py` into a single shared `compute_scale_bias()` function, proved to be a pure extraction by `--check` exiting 0 against all three committed CSVs.
- Built `experiments/e5_index_sensitivity.py`: a real-rig-geometry scenario builder (`build_real_rig_scenario`), a per-point sweep runner (`run_index_point`), and band-level post-processing (`add_control_columns`, `add_holdout_floor_columns`) that never hardcodes E2's noise floor.
- Wrote 9 fast, hand-built-fixture unit tests covering the row schema, the E1-formula cross-check, the live noise-floor read, delta_n arithmetic, control-column derivation, seed population, and the no-verdict-column guard.
- Verified `--smoke` (2 band points, 4 frames, `refine_intrinsics=False`) runs clean into a throwaway temp directory and leaves `experiments/results/` untouched.

## Decisions Made

- `compute_scale_bias` lives in E1 (not a new shared module) and E5 imports it — matches the plan's explicit instruction and keeps the formula's one origin co-located with its first/primary user.
- The band-level columns (`scale_bias_pct_control`, `bias_over_control`, `holdout_floor_pct`, `scale_bias_over_floor`) are always present in `build_row`'s output (as `None`) so the row-builder's schema test can assert exact column identity independent of the post-processing step that fills them in — this was necessary to satisfy `test_e5_row_schema`'s "returns exactly `E5_COLUMNS`, in order" requirement while still keeping `add_control_columns`/`add_holdout_floor_columns` as clean, band-scoped, single-responsibility functions.
- `--check` is explicitly unimplemented for E5, erroring via `parser.error()` — there is no committed `index_sensitivity.csv` yet (that lands in plan 19.2-13), so a real `--check` comparator would have nothing to compare against.
