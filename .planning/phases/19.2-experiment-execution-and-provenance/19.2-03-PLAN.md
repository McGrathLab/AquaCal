returns the iteration count and final residual for a single point's refractive projection, by
extracting the existing Newton loop into a shared private helper that both
`_refractive_project_newton` and the new public function call.

this, not the experiment script.
Output: one new public name exported from `aquacal.core`, one extracted shared helper, and a
bit-exactness guard proving the projection path's numbers did not move.

**Step 1 — extract the loop.** Create a module-private helper
`_solve_newton_r_p(r_p, r_q, h_c, h_q, n_air, n_water, max_iterations, tolerance)` returning
`tuple[float, int, float]` = `(r_p, n_iterations, final_abs_delta)`. Move the loop body from
`_refractive_project_newton` into it **verbatim** — same operation order, same expressions, same
clamp, same `abs(delta) < tolerance` break condition. Count iterations as the number of Newton
steps actually taken (i.e. increment once per loop body execution, so a break on the first step
reports 1). `final_abs_delta` is `abs(delta)` from the last executed step.

Do NOT move the early-return guards (`h_c <= 0`, `h_q <= 0`, `r_q < 1e-10`) or the initial-guess
computation into the helper — the helper takes the initial `r_p` as an argument. Keeping the
guards where they are means the projector's control flow is untouched.

Rewrite `_refractive_project_newton`'s loop as a single call to `_solve_newton_r_p`, discarding
the count and residual. Its signature, its guards, its return type, and every number it produces
stay exactly as they are. This is the "share the loop body rather than duplicate it" requirement of
D-19 — do NOT copy-paste the loop into the new public function.

**Step 2 — add the public diagnostic.** Define
`refractive_project_newton_diagnostic(camera, interface, point_3d, max_iterations=10,
tolerance=1e-9) -> dict | None` immediately after `_refractive_project_newton`. It repeats the
same setup and the same three early-return guards, calls `_solve_newton_r_p`, and returns a dict
with exactly these keys:
  - `n_iterations: int` — Newton steps taken
  - `converged: bool` — `final_abs_delta < tolerance`
  - `final_residual: float` — the `final_abs_delta` returned by the helper, in metres
  - `r_p: float` — the converged interface-crossing radius, in metres
  - `incidence_angle_deg: float` — `degrees(arctan2(r_p, h_c))`, the air-side incidence angle at
    the interface, so a consumer can report iteration count against obliquity without recomputing
    geometry
Return `None` for exactly the same three degenerate cases the projector returns `None`/short-circuits
for, so a caller can distinguish "no Newton solve happened" from "converged in 0 steps". For the
`r_q < 1e-10` straight-down case, return `None` — there is no root-find to report.

Write a Google-style docstring stating: units are metres; the defaults (`max_iterations=10`,
`tolerance=1e-9`) are the same literals the shipped projector uses and are E3 tier 1's declared
constants; this function performs the identical root-find as the shipped projection path via a
shared helper, so its counts describe production behavior rather than a re-implementation; and
it is a diagnostic, not a projector — it returns no pixel.

Type-hint with `NDArray` where arrays appear, per `.claude/rules/code-style.md`.

**Step 3 — export it.** Add `refractive_project_newton_diagnostic` to the
`from aquacal.core.refractive_geometry import (...)` block and to `__all__` in
`src/aquacal/core/__init__.py`, in the same commit as the definition, per
`.claude/rules/source-code.md`. Keep the existing alphabetical ordering of that import block.

Do NOT touch `_refractive_project_newton_batch`, `refractive_project`, `refractive_project_batch`,
or any other function in the file.
