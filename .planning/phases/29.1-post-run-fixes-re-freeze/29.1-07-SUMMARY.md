## The two smoke runs

The first pass reported **72 PASS / 17 N/A / 2 FAIL**. Both FAILs were `gate_e2_band`, and the
cause is exact: `check_rerun_gates.py:2262` resolves E2's band directory as
`out_dir.parent / "results_e2_band"`, a literal with no smoke form, so under `--smoke` the
roll-up judges the **production** tree while the stage correctly writes to
`experiments/results_smoke_e2_band`. That path then meets a three-state gate — **absent** → one
`N/A`; **present but empty** → two `FAIL`s; populated → the full battery. Plan 29.1-06's
`git mv` removed the tracked files but left the empty directory on disk, putting this working
copy in the middle state; attempt 1's box was in the first.

90 → 91 results, 72 PASS unchanged, one `N/A` becoming two `FAIL`s. The arithmetic identifies
the cause instead of proposing it.

`experiments/results_e2_band` holds **zero tracked files at HEAD**, and git does not track empty
directories, so a fresh clone of `rerun-freeze-02` will not contain it. The empty directory is a
property of this checkout, not of the tag. `rmdir` (which refuses a non-empty directory, and is
therefore its own safety check) restored the clone state, and the re-run gave **72 PASS / 18 N/A
/ 0 FAIL** with `gate_e2_band` back to its single `N/A`. One variable, one result, totals back to
attempt 1's exactly.

Both runs are reported in the bar. Run A is what this working copy produced; run B is what the
tag produces. Both logs preserved at `/home/tlancaster/AquaCal_smoke_aside/2026-08-24-a833a15/`.
