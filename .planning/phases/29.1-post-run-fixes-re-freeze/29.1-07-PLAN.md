## Hard constraints (all plans)

1. **`src/` must not be modified.** This plan modifies no code at all.
2. **The driver exits non-zero on a healthy run.** Acceptance is the end-of-run completeness
   roll-up, never `$?`. This is the single most misread fact in the whole freeze procedure:
   roughly 17-19 per-stage `GATE FAIL` findings survive a passing run because gates 1-4 judge
   the whole tree while it is still filling and are applied to auxiliary trees they do not own.
3. **Three signals stay hard and are NOT relaxed by that ruling:** a `STAGE FAILED` line in the
   sticky failures file (a stage that ran and failed, distinct from a `GATE FAIL` line); any
   stage carrying a non-zero exit in the state TSV; and `gate3_run_manifest_clean_tree`.
4. **Do not add pre-flight override flags.** If the rehearsal output tree is non-empty,
   archive it outside the repository — never `--allow-nonempty-out`, which poisons exactly the
   before/after comparison this task needs. Never `--skip-e2`, which silently declares a
   synthetic-only run.
5. **Do not commit anything while a run is in flight.** A per-stage `git rev-parse` would
   otherwise split one run's artifacts across two shas.
