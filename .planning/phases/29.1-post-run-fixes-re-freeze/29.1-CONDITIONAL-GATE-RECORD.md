# 29.1 Conditional-Artifact Gate: Mechanism Record

**Plan:** 29.1-09 (criterion 7 / SC-7)
**Decisions:** D-16 (fold it in), D-17 (measured scope), D-18 (the requirement and the two
ruled-out resolutions), D-19 (the large-file interaction)
**Date:** 2026-08-24

---

## 1. Why this record exists

A gate reporting a false PASS is the same class of defect as the two FAILs this phase exists to
fix, and is arguably worse: a FAIL announces itself, a false PASS does not (D-16). The mechanism
by which the false PASS was removed was the planner's choice under D-18, so the choice, the
alternatives, and the limitations that survive belong on the record rather than in a commit
message the next reader will not find.

## 2. Measured scope

Counted from `experiments/suite_expectations.json`, not assumed (D-17):

| Fact | Value |
|---|---|
| `conditional: true` entries in the manifest | **exactly 2** |
| Their stage | both `e2_production` |
| Their declared `dir` before this plan | both `experiments/results` |
| Mis-scored in the 2026-08-20 roll-up | **both** |

So the conditional mechanism was wrong **everywhere it was used**, not in one instance. There was
no correct case to preserve and no partial fix to consider.

Both artifacts were in fact written, into the E2 invocation tree:

- `degenerate_observations.csv` — written into all three `results_e2_invocations/` trees;
  the classification copy carries the flagged rows MF-24 cites.
- `all_observation_depths.csv` — written into `results_e2_invocations/e2_classification/` only,
  at ~10.9 MB.

The condition **held** for both on the 2026-08-20 run. Evaluated by the new predicate code
against the committed tree:

    degenerate_observations.csv: held=True  value=198
    all_observation_depths.csv: held=True  value=True

The gate read "the condition did not hold" from an absence that meant "written somewhere else".

**On the 198.** The count is a property of that run, not an invariant: 29.1-05 measured it at
198/210/183 for seeds 42/43/44 and 194 under OpenCV 4.14, and recorded that as MF-24. Nothing in
this plan re-asserts it. The manifest pins **no row count** for either artifact (`"rows": {}`),
and the predicate asks only whether the flagged count is **non-zero** — never whether it equals
198. The one place the number appears is a dated statement about what the 2026-08-20 roll-up
mis-scored, in the entry's `rows_rationale`.

## 3. The diagnosis, which is also the fix

`src/aquacal/validation/diagnostics.py:1031,1038` writes both files into the **pipeline's**
`output_dir`. E2's generated invocation configs set that per variant — for the classification
variant, `results_e2_invocations/e2_classification` — and never to the experiment's `--out`.

**The manifest named a directory the writer has never used.** This is criterion 2's defect one
directory deeper: a document claiming something the design never did.

The `dir` could not simply be corrected, for a one-line reason: `_expectations._resolve_dir` took
only the **last path component** of a non-primary `dir`, so a nested invocation-tree path could
not be written down in the manifest at all.

## 4. The three mechanisms D-18 offered, and why this one

D-18 left the mechanism open and named three candidates. Four properties decide between them:
keep `src/` untouched (hard constraint 1), move no published artifact, create no second copy of a
measurement, and avoid the 10.9 MB hazard (D-19).

| Mechanism | `src/` untouched | Moves no published artifact | No second copy | Avoids the 10.9 MB hazard | Verdict |
|---|---|---|---|---|---|
| **A. Correct the manifest `dir` and evaluate the predicate** (chosen) | yes | yes | yes | yes | **chosen** |
| B. Emit the files into `--out` as well | **no** — the writer is in `src/` | yes | **no** — two copies of one measurement | **no** — lands 10.9 MB under `experiments/results` | rejected |
| C. Resolve conditional artifacts across the invocation trees | yes | yes | yes | yes | rejected — see below |

**Why B fails.** It requires changing where `diagnostics.py` writes, which hard constraint 1
forbids outright. It would also duplicate `all_observation_depths.csv` into
`experiments/results`, which has no ignore rule for that filename, tripping
`check-added-large-files --maxkb=1000` for the next person to clone (D-19) — and it would create a
second copy of the same measurement, which is the two-sources-of-truth problem this milestone
exists to end.

**Why C fails, despite scoring the same on all four properties.** C searches the invocation trees
for the artifact rather than declaring where it lives. That makes the gate green whenever a copy
is found *anywhere*, which is a weaker statement than the one the gate is supposed to make: it
cannot distinguish the classification copy of record from the timing and memory byproducts, and it
would have gone green on the 2026-08-20 tree for exactly the wrong reason. A search is also not a
document — the manifest would still not say where the artifact is produced, so the next reader
learns nothing. A weakened form of C survives inside A, deliberately and with a different job: the
misplacement search in §7, which produces a **FAIL** rather than a PASS.

**What A actually does.** (i) `_resolve_dir` is widened to resolve a non-primary `dir` by its path
relative to the manifest's own `experiments/` root, so a nested path is expressible; (ii) both
`dir` values are corrected to the classification invocation; (iii) a `condition` object is added
beside `conditional: true`, declaring the predicate in the manifest rather than inferring it in
code; (iv) `_check_artifact`'s conditional branch evaluates it.

## 5. The two resolutions D-18 ruled out — considered, and declined

Named here so a later reader can see they were on the table:

1. **Removing the conditional mechanism.** Declined. It still exists: an artifact whose condition
   demonstrably did not arise is still PASS on absence. Removing it would have converted a real
   property of these two artifacts — they are written only when something is flagged, or only when
   a logging switch is on — into a permanent FAIL, which is a different false verdict, not a fix.
2. **Treating absence as unconditionally acceptable.** Declined. That is precisely the pre-existing
   behaviour and precisely the defect. Absence is now acceptable **only** on a machine-evaluated
   predicate, and never when the artifact is found elsewhere.

Both are pinned by tests rather than by this paragraph:
`TestConditionalArtifacts::test_absent_but_condition_held_fails` and
`::test_misplaced_artifact_fails_naming_both_paths` in `tests/unit/test_expectations.py` both fail
against any implementation that took either resolution.

"legitimately absent" wording any more**; that sentence no longer exists in the codebase.

The three verdicts an absence can now produce, all of which name the predicate's source, its
pointer and the value read:

| Situation | Verdict |
|---|---|
| Predicate evaluates, condition did not hold | PASS |
| Predicate evaluates, condition **held** | FAIL |
| Predicate cannot be evaluated (source missing/unparseable, pointer unresolved, wrong type) | **N/A**, never PASS |
| Absent here but present in another **declared** directory | FAIL, naming both paths, predicate not consulted |

## 7. Stated limitations

Two, both named in the code's own docstrings so they are discoverable from the implementation and
not only from here.

**7.1 The misplacement search set is bounded to directories the manifest declares.**
`_misplacement_search_dirs` searches the primary out directory plus every directory any artifact
entry names, resolved the same way. A copy landing somewhere entirely undeclared is **still
invisible** to it. This is deliberate: an honest limitation stated is worth more than a filesystem
walk, which would make the gate's cost and its verdicts depend on whatever else happens to be on
disk. The production manifest depends on the bound — E2's timing and memory invocations write
byproduct copies of `degenerate_observations.csv` into their own undeclared trees, and those are
properties of two runs whose purpose is timing and memory rather than measurements anyone cites.
They are deliberately not separately gated, and must not be reported as misplacements of the
classification copy.

**7.2 The `--out` resolution gap, which predates this plan.** `_resolve_dir` anchors every
non-primary directory at `out_dir.parent`, so it tracks a relocated `--out` only for directories
that move with it. A run that repoints the invocation tree independently
(`SUITE_E2_INVOCATION_DIR`, `run_experiment_suite.sh:405`) is not tracked, and the gate would look
under `<out_dir>/../results_e2_invocations/...` for files written elsewhere. **This is the
pre-existing behaviour of all three sibling entries** (`results_e2_band`, `results_e2_timing`,
`results_e2_memory`) and is not introduced here. It cannot bite the two entries corrected today:
both are `full`-only, and the production invocation directory is the default one. The next person
to add a nested entry needs to know.

**Not a limitation, but worth stating:** the `_resolve_dir` change is a **widening, not a
re-pointing**. `TestResolveDirIsAWidening` re-implements the pre-29.1-09 rule verbatim and asserts
that every single-component declared directory resolves identically under both rules — asserted by
construction, not assumed.

## 8. The D-19 constraint, checked rather than asserted

The chosen mechanism leaves `all_observation_depths.csv` where it is, so no file moved into
`experiments/results` and no new ignore rule is needed. A constraint checked and found already
satisfied is worth writing down, because the next person will ask.

| Check | Result |
|---|---|
| `.gitignore` modified by this plan | no — `git diff --quiet -- .gitignore` exits 0, and `git diff results/rerun-freeze-01..HEAD -- .gitignore` is empty for the whole branch |
| Files newly **tracked** by this phase under `experiments/` | **none** — every added path on this branch is a `.planning/` markdown file |
| `all_observation_depths.csv` tracked anywhere in the repository | no — `git ls-files \| grep all_observation_depths` returns nothing; it stays covered by the DATA-01b rule `experiments/results_e2_invocations/*/all_observation_depths.csv` committed in `672be71` |

| `pre-commit run check-added-large-files` over the staged change | **Passed** |
