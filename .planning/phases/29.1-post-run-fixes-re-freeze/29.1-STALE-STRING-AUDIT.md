# 29.1 Stale-string audit — the bounded sweep D-09 authorises

**Run:** 2026-08-24, phase 29.1 plan 03.
**Bound:** static strings in the 2026-08-20 production run's **writer modules** that annotate a
value **that run recomputed** (D-09).
**Rule applied (D-09, from `2026-08-17-audit-static-strings-that-annotate-recomputed-values.md`):**
classification is **attribution**, not pattern matching.

- **`legitimate`** — the string names a specific historical run, release, probe or archived record,
  so the number is a **citation** and is *supposed* to be frozen.
- **`defective`** — the string annotates a field the code **recomputes**, with no attribution, so
  the number silently becomes a claim about the current run that nobody re-derives.

> **This document necessarily contains the stale sentences it corrects.** Every claim quoted below
> is quoted *because* it is the thing being retired. Any grep-based gate for this defect class must
> therefore stay **scoped by filename** and must never scan `.planning/`, or it matches this file
> after a perfect fix. `tests/unit/test_stale_provenance_strings.py` says the same thing about
> itself; both files are named in that module's docstring.

grep -nH -E "(#|\"|')" \

**high-precision decimal** (three or more fractional digits — the shape of a measured value rather
than a design round number) or an **integer immediately followed by a quantity word the suite
measures** (second `grep`).

## Verdict

The pass found **9 defective rows, across 8 comment blocks in 4 of the 11 boundary files**, and **19 legitimate citations**
that must stay frozen. Two more files (`e5_index_sensitivity.py`, `e3_derived_quantities.py`) and
the three zero-candidate modules are clean.

The defective category has one shape and three causes, and all three are D-10's pattern — a claim
outliving the conditions that produced it:

1. **Ruling A1 resized E1's seed axis** and five sites still describe the ten-seed grid
   (`e1:51`, `e1:213`, `e1:339`, `e1:359`, `run_experiment_suite.sh:1471`). Plan 29.1-02 closed the
   two most visible ones in the same file; these are the ones that survived because they are
   arithmetic and cross-references rather than provenance prose.
2. **Phase 28 ran**, and two E6 docstrings still quote the pre-run values of the field one of them
   computes (`e6:625`, `e6:675`).
3. **MF-24 (plan 29.1-05) measured the seed sensitivity of the 198**, retiring a same-day claim in
   this phase's own plan 29.1-01 output (`e4:1555`, `e4:1560`). This is the sharpest instance in
   the table: the stale string was **fourteen commits old**, which is the argument for the sweep
   existing at all.

Every correction is prose. **No measured value, no gate id, no PASS/FAIL verdict and no published
artifact moves as a result of this pass** — the constraint the whole phase is written under.

The gate that holds this state is `tests/unit/test_stale_provenance_strings.py`
(`TestBoundedStaleStringSweep`), filename-scoped, asserting on whole claim sentences.
