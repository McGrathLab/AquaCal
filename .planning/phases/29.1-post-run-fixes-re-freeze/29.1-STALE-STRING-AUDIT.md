# 29.1 Stale-string audit — the bounded sweep D-09 authorises

**Run:** 2026-08-24, phase 29.1 plan 03.
**Bound:** static strings in the 2026-08-20 production run's **writer modules** that annotate a
value **that run recomputed** (D-09).
**Rule applied (D-09, from `2026-08-17-audit-static-strings-that-annotate-recomputed-values.md`):**
classification is **attribution**, not pattern matching.

- **`legitimate`** — the string names a specific historical run, release, probe or archived record,
  so the number is a **citation** and is *supposed* to be frozen.
- **`defective`** — the string annotates a field the code **recomputes**, with no attribution, so
  the number silently becomes a claim about the current run that nobody re-derives.

> **This document necessarily contains the stale sentences it corrects.** Every claim quoted below
> is quoted *because* it is the thing being retired. Any grep-based gate for this defect class must
> therefore stay **scoped by filename** and must never scan `.planning/`, or it matches this file
> after a perfect fix. `tests/unit/test_stale_provenance_strings.py` says the same thing about
> itself; both files are named in that module's docstring.

## Enumeration command

Run from the repository root. Pasted verbatim; re-running it reproduces the candidate set exactly.

```bash
grep -nH -E "[0-9]\.[0-9]{3,}|[0-9]+[ _-]?(rows?|seeds?|frames?|observations?|corners?|cells?|cameras?|hours?|minutes?|px|mm|m)\b" \
    experiments/e1_refractive_comparison.py \
    experiments/e2_real_rig.py \
    experiments/e3_derived_quantities.py \
    experiments/e4_benchmark_grid.py \
    experiments/e5_index_sensitivity.py \
    experiments/e6_generalization_sweep.py \
    experiments/e7_interface_ablation.py \
    experiments/e7_focal_standoff_analysis.py \
    experiments/fd_jacobian_accuracy.py \
    experiments/reconstruction_bootstrap.py \
    experiments/run_experiment_suite.sh
```

**What it selects.** Every line of the eleven boundary files carrying either a **high-precision
decimal** (three or more fractional digits — the shape of a measured value rather than a design
round number) or an **integer immediately followed by a quantity word the suite measures**
(`rows`, `seeds`, `frames`, `observations`, `corners`, `cells`, `cameras`, `hours`, `minutes`,
`px`, `mm`, `m`).

> **A narrower first attempt was rejected during this pass, and the rejection is the point.** The
> command originally pre-filtered to comment-and-string-literal lines with
> `grep -nH -E "(#|\"|')"` before the numeric filter, on the reasoning that only prose can carry a
> stale claim. It yielded 118 lines and **it has a blind spot**: a wrapped docstring line with no
> quote character and no `#` — for example `e1_refractive_comparison.py:44`, `x 2 models = 160 rows
> at production scale)` — is silently dropped. That line is one of the defects in the Pass B table
> below; it was found by hand while verifying a neighbouring row, not by the command. The
> filter was therefore removed. The wider command costs 78 extra candidates, all of which fall out
> in Pass A as code constants, and it has no known false negative. **A boundary with a blind spot
> is not a boundary**, and a sweep whose command misses a defect the author then finds by eye has
> not established anything.

**Yield: 196 candidate lines** at the **pre-correction** tree — commit `f983d21`, which is this
audit's own commit and carries the eleven boundary files exactly as the 2026-08-20 run left
them. Re-run it against the corrected tree and it yields **188**, because the corrections
