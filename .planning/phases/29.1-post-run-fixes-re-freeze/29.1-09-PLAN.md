<objective>
Stop the completeness gate reporting a PASS it cannot justify: point `e2_production`'s two
conditional artifacts at the directory their writer actually writes to, and make the
conditional verdict depend on a machine-evaluated predicate rather than on absence alone.

Purpose (D-16): a gate reporting a false PASS is the same class of defect as the two FAILs
this phase exists to fix, and is arguably worse — a FAIL announces itself, a false PASS does
not. Measured scope (D-17): `suite_expectations.json` has exactly two `conditional: true`
entries, both `e2_production`'s, both declared at `experiments/results`, and **both are
mis-scored** in the 2026-08-20 roll-up. The condition held — 198 observations were flagged —
and both files were written, into `results_e2_invocations/`. The gate read "no flagged rows"
from an absence that meant "written somewhere else".

Output: a manifest that describes where the artifacts are produced, a gate that evaluates the
condition it claims to be reasoning about, and a record of the mechanism chosen.

The phase's tracer is `29.1-01` task 1. This plan expands the same manifest-versus-reality
concern that `29.1-02` opened, one directory deeper.
</objective>

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| run output → gate verdict | The completeness gate is what licenses a run as complete; a verdict it cannot justify is worse than a missing check, because it is trusted. |
| manifest declaration → what is actually written | The manifest is the machine-readable claim about where each artifact lives; the library decides where it really lands. |
| large artifact → repository | A 10.9 MB file entering a tracked path trips the repo-wide large-file guard for everyone who clones. |
