## 1. RULING — D4, the three exact-equality anchor failures

### The measurement, stated without softening

The full test suite at this sha, run on this machine with the interpreter that produced the
accepted 2026-08-20 production run:

    2407 passed, 26 skipped, 3 FAILED        (0:27:47)

    FAILED tests/unit/test_discard_accounting.py::test_matches_frozen_anchor
    FAILED tests/unit/test_optim_common.py::TestPerObservationDetailSinks::test_detail_sink_recomputed_geometry_matches_projector
    FAILED tests/unit/test_pipeline.py::TestSolverConfigSeedIsInert::test_matches_pre_change_anchor

**This document does not claim the suite is clean, and no artifact of this phase may.**
D-14 asked for attempt 1's full bar, and attempt 1's row reads *0 failed*. This run reads
*3 failed*. Seven of the bar's eight elements clear; this one does not. Full diagnosis in
`29.1-VERIFICATION-BAR.md`; the defect entry is D4 in `deferred-items.md`.

### What is established about the three

| Test | Actual | Expected | Disagreement |
|---|---|---|---|
| `test_matches_frozen_anchor` | `0.794471850364211` | `0.7944718492870945` | rel. 1.4e-9 in reprojection RMS |
| `test_detail_sink_recomputed_geometry_matches_projector` | `0.10681280743540097` | `0.10681280743540099` | **1 ULP** on a `sqrt(dx²+dy²)` |
| `test_matches_pre_change_anchor` | `1.179461e-16`, `2.493056e-16` | `1.626336e-16`, `4.927961e-16` | 2.4e-16 absolute, on the off-diagonal *zeros* of an identity rotation |

1. **Deterministic, not flaky.** Re-run in isolation they reproduce bit-for-bit.
2. **Not a threading artifact.** Unchanged under
   `OPENBLAS_NUM_THREADS=1 OMP_NUM_THREADS=1 MKL_NUM_THREADS=1`.
3. **Not caused by this phase and not caused by this branch.** The three test modules,
   `tests/fixtures/`, `tests/synthetic/conftest.py`, `pyproject.toml`, `src/` and
   `experiments/_degeneracy.py` are all byte-identical to `rerun-freeze-01`. Running these
   tests at this sha *is* running them at the predecessor tag. **They fail at
   `rerun-freeze-01` too** — the predecessor's `0 failed` is a Windows measurement.
4. **This is the first pytest evaluation of these anchors on Linux, ever.**
   `27-ONTARGET-VERIFICATION.md` verified the predecessor on this same box with a dry run,
   `fd_jacobian` at full scale and an on-target `--smoke` pass — **never with `pytest`**.
   The failure is not new; the *measurement* is new.
5. **The anchors record no platform.** `tests/fixtures/discard_anchor.json`'s `provenance`
   carries a sha, a scenario and kwargs, and no platform, no numpy version, no BLAS. There
   is nothing in the fixture that says which machine it is exact against.
6. **CI would not have caught two of them.** Two are `@pytest.mark.slow`, which
   `test.yml`'s `pytest tests/ -m "not slow"` deselects. The third would run on
   `ubuntu-latest` — a different box from this one.

### The ruling

**Cut the tag, with this exception recorded — the same shape as attempt 1's `GATE FAIL`
ruling, and for the same reason.** Attempt 1 met 17 structurally-red per-stage gate findings
and declined to edit the gate script inside the freeze window to turn a number green, ruling
instead that acceptance is read where the evidence actually is. This is that trade again:

- The failures are **a real finding about cross-platform exactness**, not a defect in the
  code being frozen. Nothing this tag ships behaves differently because of them.
- **Making them pass would require destroying the only property they exist to hold.** Two of
  the three forbid it in their own docstrings — *"A mismatch here is a finding to report, not
  a tolerance to loosen"*, and *"compared with `==`, never `pytest.approx` — a tolerance
  would pass on a sink that had drifted to a different (but nearby) formula."* Regenerating
  the anchors on Linux would silently re-baseline them against an unaudited tree.
- **The alternative — blocking the freeze — buys nothing.** The failures are equally present
  at the predecessor tag, so refusing to cut `rerun-freeze-02` would not avoid them; it would
  only leave the re-run blocked behind a condition no reachable sha satisfies.

### What was deliberately NOT done

**Nothing was deselected, marked `xfail`, skipped, loosened to a tolerance, or regenerated.**
The three tests remain exactly as `rerun-freeze-01` shipped them, and they fail exactly as
measured. Anyone who runs `pytest tests/` at `rerun-freeze-02` on a Linux box should expect
to see **3 failed**, and should read this section rather than treat it as a regression.

### What this ruling does NOT relax

- The `--smoke` acceptance roll-up still had to reach **0 FAIL** — it did (§4).
- All 20 stages still had to exit 0 — they did.
- There still had to be **no `STAGE FAILED` line** — there was none.
- `gate3_run_manifest_clean_tree` still had to PASS — it did.
- The lint gates still had to pass — they did.

### Carried forward past the tag

The re-run's verifier must expect these three, and must **not** treat them as caused by the
re-run. They are also the strongest available argument for the post-submission work of giving
`tests/fixtures/discard_anchor.json` a platform field, so a future reader can tell which
machine an anchor is exact against.

## 3. RULING — D3, the formatting hooks were not run tree-wide, deliberately

`end-of-file-fixer` and `trailing-whitespace` would rewrite **148 of the 227 committed
artifacts** under `experiments/freeze01_run_output/`. A whitespace-only rewrite does not
change a measurement, but it does change bytes the gate reads, and it would destroy the
byte-for-byte-what-the-run-produced claim `29.1-GATE-BEFORE-AFTER.md` asserts.

**`pre-commit run --all-files` was therefore never executed in this phase, and must not be.**
The hooks that matter for exposure and size were run explicitly instead, scoped to the 304
files the phase changed:

    xargs -a <changed files> pre-commit run check-added-large-files --files   ->  Passed
    xargs -a <changed files> pre-commit run check-yaml             --files   ->  Passed
    xargs -a <changed files> pre-commit run detect-secrets         --files   ->  Passed

The working tree was fingerprinted before and after each invocation and was **unchanged** —
so no file was rewritten by the audit itself.
