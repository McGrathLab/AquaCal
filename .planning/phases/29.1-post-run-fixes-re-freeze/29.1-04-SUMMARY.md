## Accomplishments

- **Corrected the defect that made the frozen package unbuildable from its own instructions.** §1.2 said `python -m pip install -e .`, which resolves runtime dependencies only. It now says `python -m pip install -e ".[dev,bench]"`, with a paragraph per extra naming exactly what breaks without it: `dev` because `e3_derived_quantities.py` imports `DECLARED_CONSTANTS` from a test module that imports `pytest` — a §3-facing artifact generator depending on a test runner — so e3 exits 1 on both `--check` and `--force` and takes five artifacts with it; `bench` because `capture_environment()` fills `cpu_count_logical` and `ram_total_bytes` from `psutil` inside a `try/except` and leaves both `None` otherwise, failing `gate3_run_manifest_fields` for a reason with nothing to do with the run. The dependency table gained a `Source` column and both extras so the table and the command agree, and the section now records that this was found on the Linux run machine on 2026-08-19 and was invisible on Windows because both packages are permanently present there — the Linux-only failure class the on-target verification venue exists to catch.
- **Ruled on every other install site in the shipped tree, which was the half of D-11 that is easy to skip.** 26 sites across 17 files in `29.1-INSTALL-SITES.md`, each with a `file:line`, the command, the audience, a ruling from a fixed four-category vocabulary, and its reason. One `corrected`. Five `correct as-is — not a first install` — the `--no-deps` metadata-refresh commands in `experiments/README.md` and `prelaunch_gate.sh`, and the prose references in `_run_manifest.py`, `benchmark.py` and `test_benchmark.py` — where adding extras would change what the command does. The rest are CI, contributor and PyPI end-user installs whose extra sets are correct for their audience.
- **Proved it by execution from a clean environment.** Built `aquacal-freeze02-cleanenv` (conda, Python 3.11.15) and installed with the command *read out of the corrected file by `awk`*, not retyped from the plan. `pytest` 9.1.1 and `psutil` 7.2.2 both arrived; `capture_environment()` returned `cpu_count_logical=32` and `ram_total_bytes=33351241728`; e3 exited **0** on `--check` against `experiments/results` (all three baselines matched) and **0** on `--force` into a scratch directory outside `experiments/`, producing all five artifacts plus the LaTeX fragments. `aquacal.__file__` resolved under this clone (T-29.1-13), and the OpenCV hard pin held at 4.13.0.92.
- **Closed the deferral from 2026-08-19.** The todo moved to `.planning/todos/done/` with a `## Resolved` block naming D-11, the corrected command and the execution record — and stating explicitly that options 2 and 3 remain open by decision, so a future reader can tell a deliberate scope boundary from an oversight.

## Decisions Made

- **Took todo option 1 in full and left options 2 and 3 open, on the record.** Option 2 (move `DECLARED_CONSTANTS` out of the test module) and option 3 (promote `psutil` to a runtime dependency, or add an `os.cpu_count()` / `/proc/meminfo` fallback) are both correct long-term and both touch `src/` or `pyproject.toml`, which this phase forbids and which would require the suite re-run behind them. Recorded in both the todo's `## Resolved` block and `29.1-INSTALL-SITES.md` so the boundary is legible.
- **`--no-deps` sites must not gain extras.** This is the distinction that would most easily have been got wrong by a mechanical find-and-replace: `pip install -e . --no-deps` exists to re-stamp installed distribution metadata after a version bump *without* touching the resolved environment. Adding extras would make it resolve and install, defeating its purpose. Five sites ruled this way.
- **`.github/workflows/test.yml:73` (the `experiments-smoke` job) ruled correct as-is, with the counter-argument recorded.** It runs `e3_derived_quantities --smoke` — the stage that dies without `pytest` — but `dev` already supplies it, and the job never builds a `run_manifest.json` or runs Gate 3, so `bench` is unasserted there. Adding `bench` would be a defensible hardening (CI's environment would then match the run environment); it is out of scope because D-11 authorises a documentation fix and `.github/` is not part of the operator instruction set. Written down rather than silently dropped.
- **Cited the negative half instead of rebuilding it.** Whether a runtime-only environment fails was measured on the run machine itself on 2026-08-19 (`27-ONTARGET-VERIFICATION.md` §6). Re-creating a deliberately broken environment on this box would be a weaker measurement in a weaker venue.
- **Read the command under test out of the file.** The install was extracted with `awk` from §1.2's fenced block rather than retyped, so a drift between what the plan says and what the shipped file says cannot pass this verification.
