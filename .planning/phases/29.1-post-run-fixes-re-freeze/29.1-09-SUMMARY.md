# Phase 29.1 Plan 09: Conditional-Artifact Mis-scoring Summary

**The completeness gate no longer reports a PASS it cannot justify: `e2_production`'s two conditional artifacts are declared at the directory their writer actually writes to, and an absence is now scored by a machine-evaluated predicate — PASS only when the condition demonstrably did not hold, FAIL when it held, N/A when the gate could not tell, and FAIL naming both paths when the artifact turns up somewhere else.**

## Accomplishments

- **SC-7 satisfied.** The defect was not one bad entry: `suite_expectations.json` has **exactly two** `conditional: true` entries, both `e2_production`'s, and **both were mis-scored** in the 2026-08-20 roll-up. The mechanism was wrong everywhere it was used, so there was no correct case to preserve.
- **The diagnosis is the fix.** `aquacal.validation.diagnostics` writes both files into the **pipeline's** `output_dir`, which E2's generated invocation configs set per variant — never to `--out`. The manifest had always named a directory the writer never uses. The gate read "no flagged rows" from an absence that meant "written somewhere else".
- **`_resolve_dir` widened so the correct directory is expressible at all.** It kept only the last path component of a non-primary `dir`, which is the one-line reason the `dir` could not simply be corrected. It now resolves a non-primary directory by its path relative to the manifest's own `experiments/` root. **This is a widening, not a re-pointing** — and that claim is a test, not a docstring assertion: `TestResolveDirIsAWidening` re-implements the pre-change rule verbatim and asserts the two agree for every declared directory the old rule could express.
- **The predicate is declared in the manifest, not inferred in code.** Each conditional entry now carries a `condition` object: a human `description`, a `source` in the same vocabulary as `dir`, a `pointer` into it, and a `holds_when` drawn from a **closed** two-member vocabulary (`nonzero_number`, `boolean_true`) that `_validate_manifest` rejects anything outside of. Both sources are artifacts the run itself produces, so the predicate is a statement about *this* run.
- **Three verdicts where there was one.** An absent conditional artifact is PASS only when the predicate evaluates and the condition did not hold; **FAIL** when it held; **N/A** when the predicate cannot be evaluated. Every message names the source, the pointer and the value read, so a reader can audit the verdict from the gate's own output.
- **A misplaced artifact is never silently green**, and this outranks the predicate: absent where expected but present in any directory the manifest declares is a FAIL naming both paths.
- **Both ruled-out resolutions declined, and testably so.** The conditional mechanism still exists, and absence is still not unconditionally acceptable — `test_absent_but_condition_held_fails` and `test_misplaced_artifact_fails_naming_both_paths` both fail against any implementation that took either.
- **The roll-up is unmoved at `TOTAL: 176 PASS, 7 N/A, 0 FAIL`**, with no gate weakened and no committed artifact regenerated. What changed is what the PASS *means*: both artifacts are now **found and checked** instead of excused. The string `legitimately absent` no longer occurs anywhere in the codebase.
- **34 new tests**, 17 of them confirmed failing against the pre-change branch — including both false-PASS classes.

## Decisions Made

- **Mechanism A of D-18's three, on four properties.** Keep `src/` untouched, move no published artifact, create no second copy of a measurement, avoid the 10.9 MB hazard. **B** (emit into `--out` as well) fails three of the four: it needs a `src/` change hard constraint 1 forbids, it lands a 10.9 MB file where no ignore rule covers it, and it duplicates a measurement.
- **C was rejected despite scoring identically to A.** Resolving conditional artifacts by searching the invocation trees makes the gate green whenever a copy is found *anywhere*. That is a weaker statement than the one the gate is supposed to make — it cannot distinguish the classification copy of record from the timing and memory byproducts, and it would have gone green on the 2026-08-20 tree for exactly the wrong reason. A search is also not a document: the manifest would still not say where the artifact is produced. A weakened form of C survives inside A with the opposite job — the misplacement search produces a **FAIL**, never a PASS.
- **The predicate asks "non-zero", never "198".** 29.1-05 measured the count at 198/210/183 for seeds 42/43/44 and 194 under OpenCV 4.14 and recorded it as MF-24. Pinning 198 would re-assert as invariant exactly what that plan measured to be variable. Neither entry pins a row count (`"rows": {}`); the only place the number appears is a dated statement about what the 2026-08-20 roll-up mis-scored.
- **The `holds_when` vocabulary is closed and the validator enforces it.** An unrecognised member would otherwise become a silent N/A, which is how a gate quietly stops gating. Two members suffice today and adding a third is a deliberate act.
- **The misplacement search set is bounded, and the bound is stated rather than closed.** A filesystem walk would make the gate's cost and its verdicts depend on whatever else happens to be on disk, and would report the timing and memory byproduct copies as misplacements. `test_a_copy_in_an_undeclared_directory_is_not_searched` pins the bound as intended behaviour so nobody later "fixes" it into a walk by accident.
- **`_validate_manifest` also rejects a non-conditional entry carrying a `condition`** (Rule 2, beyond what the plan asked). A predicate nothing would ever evaluate is a dead key that reads to the next person as a live guarantee — the same shape as the defect this plan removes.
