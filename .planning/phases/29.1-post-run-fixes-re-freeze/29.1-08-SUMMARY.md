## The D4 ruling, in one paragraph

`pytest tests/` at this sha reports **2407 passed, 26 skipped, 3 failed**. All three are
exact-equality comparisons against anchors captured on Windows, missing by 1 ULP to rel. 1.4e-9.
Plan 29.1-08 added the fact 29.1-07 lacked: **the three modules, `tests/fixtures/`,
`tests/conftest.py`, `pyproject.toml`, `src/` and `experiments/_degeneracy.py` are byte-identical
to `rerun-freeze-01`, so they fail at the predecessor tag too** — attempt 1's `0 failed` is a

the freeze would therefore not avoid them; no reachable sha satisfies the condition. The tag was
cut with the exception recorded, in the same shape attempt 1 ruled on its 17 `GATE FAIL`

artifact of this plan records "0 failed"** — the tag's own annotation message, the freeze record,
the attempt log, the deferred-items ledger and the windows ledger each state the failure
independently, so a later reader meets it whichever document they open first.

## Deviations from Plan

### 1. [Procedural] Task 1's checkpoint executed as measured pre-authorization

- **Found during:** Task 1.
- **Situation:** `workflow.auto_advance` is `false`, so a `checkpoint:decision` would normally
  stop the executor. The dispatch instead authorized the local half explicitly — *"cut the
  annotated tag locally, run the fresh-clone verification, run the exposure audit, and write
  every record"* — which is verbatim the `proceed-as-decided` option, and hard-stopped the push.
- **What was done:** every measurement the checkpoint requires was taken **before any tag object
  existed**, with a standing condition to halt if any contradicted the plan's assumption (in
  particular, if the name had matched `v*`). None did. All of it is presented at the Task 3
  checkpoint, ahead of the irreversible step.
- **Why this is safe:** the plan itself rates a local tag `reversible` and the push `one-way`.
  Had the author chosen `different-name`, the remedy is `git tag -d`.

### 2. [Rule 3 - Blocking] `results/rerun-freeze-01` is 2 commits ahead of its remote

- **Found during:** Task 1, branch topology measurement.
- **Issue:** the local branch sits at `a6e7841`, the remote at `89c2092`. Both extra commits are
  ancestors of the tagged sha, so pushing the working branch publishes their content regardless;
  only the branch *pointer* would lag.
- **Action:** **not** silently folded into the push. Surfaced as an explicit open question in
  `29.1-PREPUSH-AUDIT.md` §7.4 — moving a branch pointer that marks where attempt 1's results
  ended is the author's call, not the executor's.

### 3. [Rule 2 - Missing safeguard] D5's trap was reproduced by this plan's own verification

- **Found during:** Task 2, after the `--smoke` pass.
- **Issue:** the verification left `run_experiment_suite_state.7005a27.tsv` with 20
  `complete … 0` lines in the clone. A **real** run at that sha in that clone would skip all 20
  stages and produce nothing — F-001's shape.
- **Fix:** archived to `/home/tlancaster/AquaCal_smoke_aside/2026-08-24-7005a27/` (with the
  smoke log, its roll-up, the install log, the import assertion and the dry-run log); the
  clone's `git status` is empty again. Recorded as a hazard in the freeze record with the
  operator instruction to clone the tag fresh, and appended to `deferred-items.md` as *D5
  UPDATE*.

### 4. [Rule 2 - Missing safeguard] `PRELAUNCH_GATE_PYTHON` set explicitly

- **Found during:** Task 2, dry run.
- **Issue:** D-28 asks for it, and plan 29.1-07's bar run left it unset — harmless there only
  because `python` on `PATH` happened to resolve correctly.
- **Fix:** set explicitly for both the dry run and the `--smoke` pass. Noted in the freeze record
  as a difference from the bar's invocation, and as a correction rather than a drift.
