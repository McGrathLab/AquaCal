## Why this bar was run at all (D-15)

Nothing else runs the test suite on this branch.

- `.github/workflows/test.yml` triggers only on `push: branches: [main]` and
  `pull_request: branches: [main]`. This branch is neither, so CI has never seen it.
- The `pytest tests/ -m "not slow"` pre-push hook was removed on 2026-08-20 (`cc56eea`),
  on the reasoning that it duplicated that workflow. That reasoning holds for `main` and
  not for the experiments line. `.pre-commit-config.yaml` says so itself, in the comment
  that replaced the hook: *"pushes to a long-lived branch like experiments/* now have no
  automated test gate."*
- This clone has **no git hooks installed at all** — `.git/hooks` holds only samples and
  `core.hooksPath` is unset. Every gate recorded here was invoked explicitly.

Between the branch-scoped CI and the removed hook, **this run is the only test gate that
exists before the tag is cut.** That is why the bar is the *full* attempt-1 bar and not a
reduced one, and it is why the three failures below are handed forward rather than waved
past. The reasoning is recorded here, at the point in the phase where the gate is actually
scheduled, so it travels with the evidence.

### What was deliberately NOT done

Nothing was deselected, marked `xfail`, skipped, or loosened to a tolerance. Two of the
three tests forbid it in their own docstrings — *"A mismatch here is a finding to report,
not a tolerance to loosen"*, and *"compared with `==`, never `pytest.approx` — a tolerance
would pass on a sink that had drifted to a different (but nearby) formula."* Loosening them
inside the freeze window would convert a real platform finding into a green number and
destroy the only property those tests exist to hold.

**This is handed to plan 29.1-08 as a blocking decision**, in the same shape D1 hands it the
provenance dormancy: either resolve them, or record an explicit ruling for them the way

### The two smoke runs — 72/17/2, then 72/18/0

The first `--smoke` pass on this box reported **72 PASS / 17 N/A / 2 FAIL**. Both FAILs were
`gate_e2_band`:

    [FAIL] E2  gate_e2_band:record_count  found 0 per-seed metric record(s) under
                                          .../experiments/results_e2_band, expected exactly 3
    [FAIL] E2  gate_e2_band:scope         e2_band_scope.json missing or unreadable under
                                          .../experiments/results_e2_band

**Cause, identified result by result.** `check_rerun_gates.py:2262` resolves E2's band
directory as `out_dir.parent / "results_e2_band"` — a literal that does not honour `--smoke`.
Under `--smoke`, `out_dir` is `experiments/results_smoke`, so the end-of-run roll-up reads the
**production** `experiments/results_e2_band` while the stage itself correctly wrote to
`experiments/results_smoke_e2_band`. (This is the same class of defect the driver already
documents for `e7_focal_standoff`, which reads a hardcoded `experiments/results/…` path.)

That path then meets a three-state gate at `check_rerun_gates.py:1666`:

| State of `experiments/results_e2_band` | Results emitted |
|---|---|
| **absent** | 1 × `N/A` — *"not present (its stage has not run yet)"* |
| **present but empty** | 2 × `FAIL` — `record_count`, `scope` |
| populated | the full battery |

On this box the directory was **present and empty** — the physical residue of plan 29.1-06's
`git mv`, which removes tracked files but leaves the now-empty directory on disk. On attempt
1's box it was absent, so the gate returned its single `N/A`.

**The arithmetic closes exactly, which is what identifies the cause rather than merely
proposing it:** attempt 1's 72 / 18 / 0 = 90 results; run A's 72 / 17 / 2 = 91. The 72
PASSes are identical, one `N/A` became two `FAIL`s, and nothing else moved.

**`experiments/results_e2_band` holds zero tracked files at HEAD** (`git ls-tree -r HEAD` is
empty for it, as it is for every sibling output tree). Git does not track empty directories,
so **a fresh clone of `rerun-freeze-02` will not contain that directory at all** — it will be
in the *absent* state, not the *present-and-empty* state. The empty directory is a property
of this working copy, not of the tag.

So the working copy was returned to the state the tag actually ships — `rmdir
experiments/results_e2_band`, which refuses to act on a non-empty directory and is therefore
its own safety check — and the pass was re-run. **Run B: 72 PASS / 18 N/A / 0 FAIL**, with

    [N/A ] E2  gate_e2_band  .../experiments/results_e2_band not present (its stage has not run yet)

as the single restored result. One variable changed, one result changed, and the totals
returned to attempt 1's exactly.

Both runs are reported because both are true: **run A is what this working copy produced, run
B is what the tag produces.** The row in the bar above is run B, because the bar is a
statement about the tag. Nothing in the gate, the manifest or the expectations was edited to
reach either number. Both logs are preserved at
`/home/tlancaster/AquaCal_smoke_aside/2026-08-24-a833a15/{runA,runB}/`.

## Findings this bar produced, handed to plan 29.1-08

1. **BLOCKING — the three exact-equality anchor failures.** Above, and D4 in
   `deferred-items.md`. 29.1-08 must resolve them or rule on them explicitly. It cannot
   record "full test suite: 0 failed".
2. **A `--smoke` rehearsal and a real run at the same sha share one state file.**
   `STATE_FILE` is derived from `RUN_EXPERIMENT_SUITE_DRY_RUN` and the short sha only
   (`run_experiment_suite.sh:288-292`); `--smoke` does not enter it. A completed rehearsal
   therefore leaves `run_experiment_suite_state.<sha>.tsv` with 20 `complete … 0` lines, and
   a *real* run at that same sha would skip all 20 stages and produce nothing. The dry-run
   path has an explicit `.dryrun.tsv` separation for exactly this failure mode; `--smoke`
   has none. Both rehearsal state files were archived out of the tree here so the hazard
   cannot reach the tag. Logged as D5.
3. **The real state artifacts are not gitignored, so a rehearsal dirties `git status`.**
   `run_experiment_suite_state.<sha>.{tsv,failures.txt,stagelogs/}` are trackable by design
   (a production run's are citable artifacts; only the `.dryrun.*` forms are ignored). They
   do not affect `git describe --dirty` or `gate3_run_manifest_clean_tree`, which ignore
   untracked files — but they do make `git status --porcelain` non-empty. Archived aside
   here. Logged as D5.
4. **`check_e2_band`'s sibling-directory resolution does not honour `--smoke`.** Detail
   above. Not fixed: it is a change to the script that judges every artifact, inside the
   freeze window, and attempt 1 declined exactly that trade. Logged as D6.
5. **`PRELAUNCH_GATE_PYTHON` should be set explicitly for the production run** (D-28). It
   was harmless here only because `python` on `PATH` happened to be the right interpreter.
