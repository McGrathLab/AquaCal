## Why this tag name

`rerun-freeze-02` deliberately **does not match `v*`**. `.github/workflows/publish.yml` triggers
on `push: tags: ['v*']` and publishes to PyPI — a release published that way can be yanked but
never un-published, and it is this phase's only one-way door. All five workflow files were read
and matched before any tag object existed:

| Workflow | Trigger | Fires? |
|---|---|---|
| `publish.yml` | `push: tags: ['v*']` | **no** |
| `release.yml` | `push: branches: [main]` | no |
| `test.yml` | `push`/`pull_request` on `main` | no |
| `docs.yml` | `pull_request: branches: [main]` | no |
| `slow-tests.yml` | `workflow_dispatch` | no |

The match was confirmed with git's own ref-glob engine rather than by eye:
`git for-each-ref 'refs/tags/v*'` returns 20 refs, and `rerun-freeze-02` is not among them.

`git describe` is restricted to `--match 'v[0-9]*'` wherever it anchors a version, so this
non-version tag cannot silently replace the semantic-version anchor. There is exactly one such
call site in the code — `experiments/_run_manifest.py:170`, using `_VERSION_TAG_GLOB = "v[0-9]*"`
— and it was verified **by execution**: the fresh clone's run manifest records
`git_describe: v2.0.1-346-g7005a27`. The unrestricted `git describe --tags` now answers
`rerun-freeze-02`, which is precisely why the restriction exists.

Confirmed after tagging: `rerun-freeze-01` still resolves to tag object `b31c8020…` and commit
`3ab9c137…`, and the `v*` tag count is unchanged at 20.

## Tags are never moved

If verification finds a defect, the finding sends the freeze **back**: fix it on the branch,
commit, cut `rerun-freeze-03` at the new sha, and re-verify against that. Abandoned tags stay as
the audit trail — a force-moved tag destroys the record of the failed attempt, which is precisely
the provenance fracture this milestone exists to stop repeating. **A second tag is a normal
outcome, not a failure signal**, and this record is the proof of that: attempt 1 closed
successfully and attempt 2 exists anyway, because the run it licensed surfaced defects worth
fixing before the next one.

Do **not** patch a running clone in place and continue. A stage that ran at a different commit
than the rest makes the whole run unreportable.

## The one thing most likely to be misread

**The driver exits NON-ZERO on a healthy run.** This one exited **1**, and that is expected.
Acceptance is read at the **end-of-run completeness roll-up**, never at `$?` — author's ruling,
2026-08-19, unchanged and restated here so the next operator cannot misread it. 17 per-stage
`GATE FAIL` findings survive a passing run because gates 1-4 judge the whole tree while it is
still filling, and are applied to the auxiliary `e2_band` / `e2_timing` / `e2_memory` /
`e4_repeat` trees they do not own. Any finding is sticky and any finding forces a non-zero exit;
that is D-01 working as designed. See `experiments/HANDOFF.md` §2.8 and `27-PREPUSH-AUDIT.md`.

Three signals stay hard and were all checked above: a `STAGE FAILED` line, any stage carrying a
non-zero exit in the state TSV, and `gate3_run_manifest_clean_tree`.

## Hazards the next operator must know about

1. **D5 — a `--smoke` rehearsal and a real run at the same sha share one state file.**
   `STATE_FILE` is derived from `RUN_EXPERIMENT_SUITE_DRY_RUN` and the short sha only
   (`run_experiment_suite.sh:288-292`); `--smoke` does not enter it. A completed rehearsal
   leaves `run_experiment_suite_state.<sha>.tsv` with 20 `complete … 0` lines, and a **real** run
   at that sha would **skip all 20 stages** and produce nothing — F-001's shape.
   **This verification produced exactly such a file**, at `7005a27`, in
   `aquacal-frozen-rerun-freeze-02`. It has been archived out of the clone to
   `/home/tlancaster/AquaCal_smoke_aside/2026-08-24-7005a27/`, and the clone's `git status` is
   empty again. **Do not reuse this verification clone for the production run — clone the tag
   fresh.**
2. **D1 — the 8 `test_experiments_provenance.py` failures are dormant, not fixed.** They return
   the moment the re-run repopulates `experiments/results/`. Expect them.
3. **D6 — `check_e2_band` resolves E2's band dir with a literal that does not honour `--smoke`**
   (`check_rerun_gates.py:2262`). Any operator who rehearses with `--smoke` in a working copy
   holding an **empty** `experiments/results_e2_band/` will see two roll-up FAILs that say
   nothing about the run. A fresh clone of this tag has no such directory, so it lands in the
   `N/A` state — which is why this run read 0 FAIL.
4. **D3 — never run `pre-commit run --all-files` on this tree.** `end-of-file-fixer` and
   `trailing-whitespace` would rewrite **148 of the 227 committed artifacts** under
   `experiments/freeze01_run_output/`, destroying the byte-for-byte claim
   `29.1-GATE-BEFORE-AFTER.md` asserts. Scope any hook invocation to changed files.
5. **D-28 — set `PRELAUNCH_GATE_PYTHON` explicitly** for the production run.
6. **A fresh clone's `--smoke` pass downloads 4.35 GB** (Zenodo record 21889922). Pinned and
   safe — it fetches one specific record, not "latest" — but it ambushes a metered or air-gapped
   machine. This verification took it cold, which re-proved the pinned record still resolves.
   The **production** run does not do this: `reconstruction_bootstrap` `depends_on: [e2_production]`,
   whose output lands in `experiments/results/`, so the local tier hits.
