# 29.1-INSTALL-SITES — every install instruction in the shipped tree, ruled on

**Plan 29.1-04, task 1. Decision D-11.** SC-5.

D-11 asks for two things: correct `experiments/HANDOFF.md` §1.2 to
`python -m pip install -e ".[dev,bench]"`, and **check every other place the install command
appears rather than only that section**. This file is the second half. It enumerates every
install invocation in the tracked tree outside `.planning/` and rules on each one, so that a
later reader does not have to re-open a question that has already been settled.

## Method

```bash
git grep -n -E 'pip install' -- ':!.planning'
```

run at `phase/29.1-post-run-fixes`, plus a sweep for conda/`environment.yml`/`setup.py`/`tox.ini`
style install specifications (there are none in this repository; `docs/Makefile` is a Sphinx
driver and installs nothing). Seventeen files carry the string. Every hit is ruled below,
including the ones that are prose about installs rather than instructions to run one — because
"this line is descriptive, not an instruction" is itself a ruling worth recording once.

## Ruling categories

| Category | Meaning |
|---|---|
| `corrected` | The site tells a **suite operator** how to build a run environment and omitted the required extras. Changed by this plan. |
| `correct as-is — different audience` | A contributor, CI, or end-user install whose extra set is right for what that audience does. |
| `correct as-is — not a first install` | A `--no-deps` metadata-refresh command, or prose describing when editable-install metadata refreshes. These **must not gain extras**: adding them would change what the command does. |
| `handed to plan 29.1-06` | A site in a file another plan owns this wave. |

## What was deliberately **not** done

The todo behind this work offers three fixes. D-11 authorises only the first, and the other two
are recorded here so the choice is legible rather than forgotten:

- **Not taken (todo option 2):** moving `DECLARED_CONSTANTS` out of
  `tests/unit/test_experiments_e3_constants.py` into a non-test module, inverting the dependency
  so a §3-facing generator no longer needs a test runner. Correct long-term; touches the source
  of §3-facing constants and requires the suite re-run behind it. Out of this phase's scope
  (hard constraint 1).
- **Not taken (todo option 3):** promoting `psutil` from the `bench` extra into runtime
  dependencies, or giving `capture_environment()` a non-psutil fallback
  (`os.cpu_count()`, `/proc/meminfo`) so two `REQUIRED_MANIFEST_FIELDS` can never be null on
  Linux. Also correct long-term; also touches `src/` and `pyproject.toml`. Out of scope.
- **Not taken, and never to be taken:** weakening `gate3_run_manifest_fields` to tolerate the
  nulls. The gate was right — that is the whole reason the defect was visible at all.

Both open options stay in the todo's own body, which moves to `.planning/todos/done/` with a
`## Resolved` block naming them explicitly.

# -> python -m pip install -e ".[dev,bench]"

and run with `python` resolved to the new environment's interpreter by absolute path (there is
