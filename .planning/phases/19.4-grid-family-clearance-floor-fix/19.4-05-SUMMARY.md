# Phase 19.4 Plan 05: Shared Seed-Band Mechanism + E7 --seeds Summary

**Added `parse_seed_list`/`run_seed_band` to `experiments/_io.py` and wired a `--seeds` flag into E7, so MF-05's per-arm seed bands become a committed, regenerable `interface_ablation_band.csv` instead of a planning-document table.**

## Performance

- **Duration:** ~50 min of edits/commits; verification (foreground, synchronous) added ~35 min: full unit suite (`tests/ -m "not slow"`) took 26m42s, and `python -u -m experiments.e7_interface_ablation --check` took ~6 min at production ("realistic", 12-camera) scale.
- **Tasks:** 2/2 completed
- **Files modified:** 2 source files, 2 new test files

## Accomplishments
- `experiments/_io.py` gained `parse_seed_list` (comma-separated seed parsing, rejecting empty/non-integer/duplicate tokens by name) and `run_seed_band` (runs a caller-supplied per-seed closure and concatenates the results with a `seed` column, fail-fast on any exception) -- the shared mechanism D-19.4-14 asks E4/E6 to reuse later as configuration, not new code.
- `experiments/e7_interface_ablation.py` gained a script-local `--seeds` flag (mutually exclusive with `--check`), emitting `interface_ablation_band.csv` at `len(seeds) * n_cameras * len(ARMS)` rows, and additively stamping `solver_config["seeds"]` into each `e7_benchmark_<arm>.json`.
- Verified, not assumed: the single-seed production path (`--seed 42` default, `--check`) is byte-identical after this change -- `python -u -m experiments.e7_interface_ablation --check` printed "Fresh output matches committed baseline within tolerance." and exited 0.
- The shared five-flag CLI contract (`--seed`, `--out`, `--force`, `--smoke`, `--check`) is unchanged -- asserted directly in both new test files.

## Decisions Made
- A `--seeds` run never writes `interface_ablation.csv` (only ever produced by a plain `--seed` run) -- keeps the E7-inertness gate's comparison target untouched by any band run.
- Force is implied for the band CSV write only; per-arm benchmark JSON writes during a band run still honor `--force`/resumability normally.
- The per-arm benchmark payload written during a band run reflects the LAST seed in the resolved list (diagnostics/timings/accuracy cannot represent N independent solves in one record); the `seeds` list itself records which N were actually run, so a reader is never left assuming the payload reflects only the last one.
- `run_seed_band` intentionally has no exception handling, matching D-19.4-11's fail-fast posture — a failing seed must propagate, not produce a silently partial band.
