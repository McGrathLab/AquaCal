### `src/aquacal/datasets/synthetic.py` — `generate_camera_array` fix (model, transform)

**Analog 1 (the defect site itself):** `generate_camera_array`, `src/aquacal/datasets/synthetic.py:166-262`

**Current (defective) per-camera loop** (lines 234-262):
```python
for i, pos in enumerate(positions):
    cam_name = f"cam{i}"
    intrinsics[cam_name] = generate_camera_intrinsics(
        image_size=image_size, fov_horizontal_deg=fov_deg,
    )
    # Extrinsics: cameras look straight down
    if i == 0:
        roll = 0.0
    else:
        roll = rng.uniform(-0.1, 0.1)  # radians

    R = _rotation_z(roll)
    t = -R @ pos                       # pos[2] is always 0.0 today

    extrinsics[cam_name] = CameraExtrinsics(R=R, t=t)

    # Interface distance with small variation  <-- THE DEFECT
    if i == 0:
        dist = height_above_water
    else:
        dist = height_above_water + rng.normal(0, height_variation)
    distances[cam_name] = dist
```

**Analog 2 (the target shape — `generate_real_rig_array`, already correct):**
`src/aquacal/datasets/synthetic.py:265-350` — every camera gets the frozen module-level
`WATER_Z` (line 348: `water_zs[cam_name] = WATER_Z`); no per-camera jitter of the surface at all.
The module-level constant it uses (lines 154-163):
```python
# D-19.3-09: this constant is also generate_camera_array's default
# height_above_water below, and both the "ideal" and "minimal"
# create_scenario presets' standoff -- it is no longer specific to the
# real-rig array.
WATER_Z: float = 1.031
```

**Analog 3 (the no-op-preserving branch — `"ideal"` preset, `create_scenario`, :1040-1051):**
```python
if name == "ideal":
    intrinsics, extrinsics, distances = generate_camera_array(
        n_cameras=4, layout="grid", spacing=0.1,
        height_variation=0.0,
        seed=seed,
    )
```
`height_variation=0.0` makes `rng.normal(0, 0.0) == 0.0` always — this is the existing proof that
setting the variation to zero is a true no-op today, and is the reference case the post-fix
`h_c = water_z - C_z` identity must reduce to for `i==0` and for `"ideal"`.

**RNG-ordering constraint (from the docstring at :189, "Std dev of per-camera height variation"
plus RESEARCH's own pitfall):** `roll = rng.uniform(...)` (line 248) is drawn BEFORE the
interface-distance block (line 255) in today's code. The fix must preserve `roll` then `delta`
per iteration — only WHAT the drawn value is applied to changes (camera Z vs. distance dict), not
the number or order of `rng` calls. `t = -R @ pos` (line 251) must be recomputed AFTER `pos[2]` is
set to `-delta`, so the loop's internal statement order changes even though the RNG call order
must not.

### Bit-inertness proofs for E1/E3/E5/E7 (test, exact-equality proof)

**Analog (the house form, exact-equality only):** `tests/synthetic/test_guard_inertness.py:144-220`

```python
def _assert_bit_identical(result_none, result_populated):
    """Assert every returned calibration value is bit-identical between two runs.

    Exact equality only -- `==` / `np.testing.assert_array_equal`. Never a
    fuzzy/tolerance-based comparison...
    """
    ext_a, dist_a, poses_a, rms_a = result_none
    ext_b, dist_b, poses_b, rms_b = result_populated
    assert rms_a == rms_b
    assert sorted(ext_a) == sorted(ext_b)
    for cam in ext_a:
        np.testing.assert_array_equal(ext_a[cam].R, ext_b[cam].R)
        np.testing.assert_array_equal(ext_a[cam].t, ext_b[cam].t)
        assert dist_a[cam] == dist_b[cam]
```

2. **E1**: `create_scenario("realistic", seed=42)` before/after, assert `scenario.water_zs` dict

### `experiments/e4_benchmark_grid.py` and `experiments/e6_generalization_sweep.py` — fail-fast wiring (controller, batch)

**E4's existing record-and-continue sink** (`run_grid_cell`, :890-898):
```python
except Exception as exc:
    logger.warning("Cell %s failed: %s: %s", cell_key, type(exc).__name__, exc)
    return {
        "cell_key": cell_key, "n_cameras": n_cameras, "n_frames": n_frames,
        "status": "failed",
        "status_reason": f"{type(exc).__name__}: {exc}",
    }
```
This runs INSIDE the per-cell CHILD subprocess (spawned by `run_cell_subprocess`, :953). Fail-fast
for E4 is a two-layer change: (1) gate this `except Exception` behind `--no-fail-fast` in the
child so an uncaught exception genuinely exits non-zero instead of being swallowed into a
`status="failed"` dict the child itself still exits 0 on; (2) the outer `_run_full` cell loop
(:1531-1559, `for n_cameras, n_frames in DECLARED_CELLS: ... run_cell_subprocess(...)`) must stop
iterating on the first non-`"ok"`/non-`"skipped_existing"` status returned by
`_invoke_subprocess_with_status_mapping` (:901-950), which ALREADY distinguishes `"ok"` /
`"skipped_existing"` / `"failed"` cleanly — the stop condition can key directly off that existing
vocabulary.

**E6's existing record-and-continue sink** (`run_configuration`, :841-850):
```python
except Exception as exc:
    logger.warning(
        "Configuration %s failed: %s: %s", config_key, type(exc).__name__, exc
    )
    outcome = {
        "status": "failed",
        "status_reason": f"{type(exc).__name__}: {exc}",
        "metrics": None,
        "degenerate_observations_at_solution": None,
    }
```
This runs IN-PROCESS (no subprocess hop, unlike E4) inside `run_sweep`'s config loop
(:913-936, `for config in configs: ... cache[config_key] = run_configuration(...)`). Fail-fast for
E6 is a single-layer change: gate the `except Exception` behind `--no-fail-fast`, or check
`outcome["status"] == "failed"` immediately after each `run_configuration` call inside the loop and
`sys.exit(1)`/raise (with the D-19.4-11 message: configuration key, exception, and — for a
clearance rejection — both supplied minimum and derived floor).

**Opt-out precedent to preserve (D-19.4-11):** 19.2-21 pre-authorised E4's 16×200 cell to fail as
a recorded row — `--no-fail-fast` must remain expressible on both scripts so that pre-authorised
failure mode does not regress into an unattended-run abort.

**Confirmed no analogous sink in E1/E5 (per RESEARCH.md grep):** neither file loops over
independent configurations the way E4/E6 do; an uncaught exception there already propagates
unhandled, which is arguably fail-fast by omission already. No fail-fast wiring task should target
E1/E5/E7.

```bash
    return $?
  fi
  python -u -m experiments.e4_benchmark_grid --force --out "${OUT_DIR}"
}
```
Always `python -u`; always `--force`; always the shared `${OUT_DIR}`.

**Gate-check invocation after every stage** (:118-127, :270-274) — call

automatic abort-on-gate-FAIL into the script; that would silently exceed 19.3's own precedent.
