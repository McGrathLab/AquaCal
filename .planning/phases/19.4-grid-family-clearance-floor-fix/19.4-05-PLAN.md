<objective>
Make a failing long run stop and say why, in seconds, instead of completing and exiting 0.

Purpose: D-19.4-06 is a direct user decision and it describes a defect in the harness, not a
preference. `run_configuration` wraps both scenario builds in one `try` with a blanket
`except Exception`, records the failure as a `status="failed"` row, and continues. At seeds 47 and
50 all twelve configurations ran, all twelve failed for the same reason, and the process **exited
0** — 74 and 84 minutes each. The information needed to stop was available in the first second.

After this phase's fix a clearance failure should be impossible by construction, so a failure
post-fix means something OTHER than the diagnosed defect is wrong — which is precisely when
continuing is least useful and stopping is most.

Output: `--no-fail-fast` on E4 and E6, fail-fast as the default on both run paths, an abort
message carrying the number needed to start the reassessment, and tests for all of it.
</objective>
