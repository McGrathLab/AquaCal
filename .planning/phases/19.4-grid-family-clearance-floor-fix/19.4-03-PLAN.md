fix that only touches the default path.

**A measured correction to D-19.4-03, which the executor must implement as stated below.**
D-19.4-03 says "record the RESOLVED ABSOLUTE range in the checkpoint payload, so every committed
identity still matches byte-for-byte." Ten of the twelve committed checkpoints record `null`, so
recording a resolved tuple *everywhere* would mismatch ten of them and reintroduce exactly the
migration the decision exists to avoid. The decision's stated GOAL — no key-set change, no
exemption code path, committed identities match because the value genuinely did not move — is
achieved by recording the resolved absolute tuple **where the configuration declares a non-default
extent factor**, and `None` where it declares the default. At seed 42 that is byte-identical to all
twelve. The "what range was actually used" information D-19.4-04 wants lands in the CSV columns,
which is where a human reads it. Implement this form; do not widen `_SCENARIO_IDENTITY_KEYS`.

**Anti-pattern 3 is blocking.** If the committed-checkpoint test fails, the fix moves — never the
comparison, never the key set, never the committed artifacts.

**Anti-pattern 7 is blocking, and it is the anti-pattern that produced this phase.** The frozen
constant exists because someone derived it once, at one seed, and generalised. Do not replace it
with a second constant derived once at one seed.
