## The two unpredicted FAILs — `gate4_band`, diagnosed

`exp1_band.csv` and `interface_ablation_band.csv` each hold 10 seeds, but no
sidecar records `solver_config['seeds']`, so the band cannot be checked against
what was requested.

**Cause.** E1 and E7 each run single-seed **with** `--force`, then the band
**without** it (`rerun_19_4.sh:298` vs `305`, `322` vs `330`). The band writer
does set `solver_config["seeds"]` (`e1_refractive_comparison.py:774`,
`e7_interface_ablation.py:698`) but passes `force=force`, and `_io.py:711` skips
when the path exists and force is false. The single-seed run created the files
first. The run logged exactly 6 skips, matching exactly the 6 affected sidecars.

**Adding `--force` to the band is the WRONG fix** — the band writes from
`last_results`, so forcing it would overwrite the seed-42 production record with
seed 51's values. The skip is what protects the production record.

Recording-only: both band CSVs carry all 10 seeds, and the requested list is in
`rerun_19_4.log`. Tracked in
`.planning/todos/pending/2026-08-05-band-sidecar-competes-with-production-benchmark-record.md`.
