# Plan 19.4-08 Summary — the risk-first production queue

## What was built

`experiments/rerun_19_4.sh` — an eight-stage, resumable, risk-first queue, plus
gate-script and prelaunch-gate updates for this phase's artifacts.

**Stage order (D-19.4-16), encoded verbatim from plan 03's approved verdict:**

```
STAGES=(e6_repeat1 e4 e6_repeat2 e6_seed43 e7 e1 e5 e3)
```

Cumulative completion targets: e6_repeat1 ~100 min, **e4 ~232 min**,
e6_repeat2 ~328, e6_seed43 ~428, e7+band ~484, e1+band ~547, e5 then e3 ~569
(9 h 30). Both high-risk stages finish inside 4 h instead of 6, at the same
total wall clock. 19.3's cheapest-first order did not start e4 until 230 min in.

The four-point abort protocol is written into the script header as numbered
comment lines so it is not decided mid-run, along with the detached-launch
invocation and the prohibition on `run_in_background` (which the harness kills
at 35-50 min; this project has lost three sweeps to it).

## Defects found and fixed while writing it

**1. A dry run would have deleted 14 tracked artifacts.** Adapted from 19.3,
`run_stage_e6_repeat1` performed `rm -rf ${OUT_DIR}/e6_configs` and `rm -f
generalization_sweep.csv e6_provenance.json` *before* the dry-run branch.
`git ls-files` confirms all three are tracked (plus 12 checkpoint JSONs). Any
exercise of the queue's control flow would have destroyed committed results.
All three cleanup blocks (repeat1, repeat2, seed43) are now inside their
dry-run guards, and dry run 1 verified `experiments/results/` is untouched.

**2. The gate invocation needed a pinned interpreter, and the reason is the
opposite of what it first looked like.** The plan permitted a bare `python`
call *if* `check_rerun_gates.py` was verified stdlib-only. It is not — it
imports pandas. Git Bash's `python` on this box is Anaconda base, where that
import fails. `run_gate_check` now uses the same pinned interpreter and
`PRELAUNCH_GATE_PYTHON` override as `prelaunch_gate.sh`, with a bare-`python`
fallback so a missing env degrades the gate to a logged finding rather than
taking down a production stage.

**3. A comment tripped a literal acceptance grep.** The criterion
`grep -v '^#' … | grep -c 'grep -P'` returned 1 for an *indented* comment
explaining why the Perl-regex grep mode is avoided — `grep -v '^#'` only strips
comments at column 0. The comment was reworded rather than the check weakened;
there is no actual usage. Same class as the inertness-gate false positive
earlier in this phase.

## e6_seed43 needs its own output directory, and that is not tidiness

E6's `_SCENARIO_IDENTITY_KEYS` omits `seed`, and `seed` is not in its `config`
at all, so a seed-43 run into the shared `${OUT_DIR}` would compare identical to
the seed-42 run already there and **silently resume it**, producing a seed-42
result labelled seed 43. That latent defect is a Deferred Idea (it needs its own
migration decision, since committed checkpoints carry no `config["seed"]`) and
is explicitly NOT fixed here. The separate directory is the documented
workaround, named as such in the script.

## Gate-script changes

`check_band_csv` added for D-19.4-14's two band artifacts. It checks the
property that makes a band trustworthy — that the CSV carries the N *distinct*
seeds its provenance sidecar claims — rather than merely that a file appeared:

- N/A when the band CSV is absent (its stage has not run yet)
- FAIL on a missing `seed` column, on a distinct-seed count disagreeing with
  `solver_config["seeds"]`, or on a band with no sidecar to verify against
- PASS only when the counts match

`_check_git_sha_consistency` is **unchanged** — it already implements
D-19.4-16's requirement that every `git_sha` across the run be identical, with
FAIL (not warn) on mismatch. The E2 `real_rig` widening remains a Deferred Idea
and was not done.

`prelaunch_gate.sh`: repointed at `19.4-01-SUMMARY.md`, archive pattern moved to
`e[0-9]+-2026-08-04-pre-interface-fix`, and 19.3's unconditional E3 archive
check **removed** rather than repointed — E3 is inert this phase and has no
archive; proving that is plan 10's byte-comparison. The expected set now parses
to exactly `{e4, e6}`. TREE_CLEAN, SUITE_GREEN, HEAD_RECORDED and
WORKTREES_CLEAN are unchanged.

## Deviations from plan

**Executed by the orchestrator, not a plan executor.** Five of six executors in
this phase stalled on long-running commands, and this plan sits on the critical
path to an overnight launch the user asked for before going to bed. Writing it
directly removed the stall risk entirely. Every acceptance criterion in the plan
was still checked as written.

**The state file `experiments/rerun_19_4_state.tsv` is listed in the plan's
`files_modified` but is deliberately NOT committed.** It is generated run state;
the dry runs created and then removed it so the production queue begins from a
genuinely clean slate.
