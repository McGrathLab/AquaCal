  <how-to-verify>
    ⚠ **This is the ORCHESTRATOR's run, never an executor's.** Per `CLAUDE.md`, an executor that
    backgrounds a long run and returns "waiting for the notification" has stalled permanently and
    will not come back — it has cost this project hours across phases 19.2–19.4. Launch detached and
    poll.

    1. Launch the smoke pass with a DISTINCT out dir, unbuffered and detached:

       `SUITE_SMOKE_OUT=experiments/results_smoke nohup bash experiments/run_experiment_suite.sh --smoke --out experiments/results_smoke > experiments/run_experiment_suite_smoke.log 2>&1 & disown`

       The distinct out dir is mandatory, not tidiness: every experiment's `--smoke` path tests
       `args.out == parser.get_default("out")`, and the parser default is `Path("experiments/results")`
       (`experiments/_io.py:64`), so passing the default is indistinguishable from passing nothing and
       E3/E4/E5/E6/E7 would all silently take the temp-dir branch. E1 and E2 write to a
       `TemporaryDirectory` unconditionally and are expected to produce nothing here — that is why
       the manifest marks their artifacts `profiles: ["full"]`.

    2. Poll the process listing and the log; do not assume a quiet transcript means a dead run.

    3. When it exits, record in the SUMMARY:
       - the driver's final exit code, and whether any stage set the sticky flag;
       - the full state-file contents (one `start` and one `complete` line per stage, with the ISO
         stamps);
       - every `GATE VERDICT` block's TOTAL line, and every FAIL verbatim;
       - the emitted `run_manifest.json` in full, confirming every required field is non-null, that
         `opencv_build` carries the `.90` suffix, and that `git_describe` is the long form;
       - the completeness gate's `smoke`-profile roll-up, and confirmation that no E1 or E2 artifact
         was expected;
       - whether E2 printed the visible `SKIPPED` line (dataset absent) or ran;
       - the wall clock of the whole pass.

    4. Judge the pass. It is GREEN when: pre-flight completed and emitted the manifest; every stage
       ran or was legitimately skipped; the `smoke`-profile completeness roll-up produced no
       unexplained FAIL; and the final exit code is consistent with the verdicts (0 if nothing
       failed, non-zero if anything did — an exit 0 alongside a FAIL is itself the defect this phase
       exists to kill).

    5. Do NOT commit `experiments/results_smoke/`. It is acceptance evidence, not an artifact; add an
       ignore rule if `git status` shows it. Do NOT run any Linux-side check — that is Phase 27 /
       RUN-01 (D-35).

    6. If a stage fails for a real reason, the fix belongs in whichever plan owns that file, as a gap
       closure — not here.
  </how-to-verify>
