Add the two user-facing behaviors that make the ablation usable: (1) per-camera seed resolution with
the CONTEXT-locked None/partial/unknown/auxiliary rules (IFACE-04), applied only on the per-camera
path; and (2) the per-camera water_z spread report — always written in per-camera mode as
`internals/interface_spread.json` (meters + stats) plus a console summary line in mm. Shared mode is

reads, so it must be trivially visible (console, mm) and trivially machine-read (JSON, meters), with
no gating flag between the user and it; and the seed rules must distinguish a mistake (unknown camera
name = warn) from valid intent (auxiliary-camera key = silently ignore).
Output: two small pure helpers + their wiring into the per-camera branch + tests.
</objective>
