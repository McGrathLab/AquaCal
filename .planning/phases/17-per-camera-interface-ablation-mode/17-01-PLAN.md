Thread a `shared_interface: bool = True` flag through the four packing/structure functions in
`_optim_common.py` (`pack_params`, `unpack_params`, `build_jacobian_sparsity`, `build_bounds`)
and the grouping function `build_structural_column_groups`, plus `build_parameter_labels` in
`_observability.py`. When `shared_interface=False`, the single global `water_z` parameter becomes
N per-camera `water_z` parameters (one per camera in `camera_order`, including the reference
camera), packed contiguously in the slot the single `water_z` currently occupies.

pipeline dependency) and independently testable. The default `shared_interface=True` path MUST
stay bit-for-bit identical to current behavior (IFACE-05 depends on this).

per-camera water_z spread; the forward model is already per-camera, so this is purely an optimizer
parameterization change.
Output: shared_interface-aware `_optim_common.py` + `build_parameter_labels`, with tests covering
per-camera packing, per-camera sparsity, and the all-mode-combination grouping validity assertion.
</objective>

<grouping_correctness>
Per-camera water_z grouping (IFACE-03 correctness argument): camera i's water_z column is nonzero
only in camera i's residual rows. Two DIFFERENT cameras' water_z columns therefore never share a
residual row, exactly like like-indexed extrinsic columns of different cameras. So all N
per-camera water_z columns collapse into a SINGLE group slot (reuse the current water_z slot,
raw id 6). The theoretical group-count lower bound is UNCHANGED: 13 (17 with refine_intrinsics).
A per-camera water_z column DOES conflict with that camera's extrinsic columns (both touch that
camera's rows), so it cannot merge into the extrinsic slots — it keeps its own slot.
</grouping_correctness>
