## Divergences

**1. [mechanism: solver-path floating-point noise] All three files' mismatched cells are
last-significant-digit differences from the nonlinear least-squares solver's exact
convergence trajectory.**

- **Observed magnitude:** worst relative differences are `5.3e-4` (exp1), `2.6e-6` (exp2),
  `5.1e-6` (exp3) -- all at or a few significant digits below the value's own precision
  (e.g. exp1's worst cell is `-0.00155702` vs `-0.00155619`, a committed value already at
  the 0.0016% scale, where a ~9e-7 absolute difference in a near-zero quantity produces a
  visually large relative difference despite being a last-digit effect).
- **Why this happens:** `calibrate_synthetic` calls `scipy.optimize.least_squares` twice
  per model (Stage 3, Stage 3's second pass). The 2026-02-24 committed run predates the
  intervening v1.7/v1.8 changes (in-air intrinsics seeding, outlier rejection -- both
  confirmed inapplicable to E1 by D-19's own mitigating-fact analysis, since
  `calibrate_synthetic` bypasses the pipeline and this is a fully synthetic scenario) and
  was produced in a different BLAS/SciPy environment. `least_squares`'s exact iteration
  count and terminal point are sensitive to floating-point summation order, which BLAS
  implementations are not required to preserve across environments -- so a bit-identical
  reproduction across a five-month, two-minor-version gap was never the bar (D-22
  explicitly softens `--check` to numeric tolerance for exactly this reason).
- **Not a porting bug:** confirmed via both of RESEARCH's diagnostic checks (see
  `## Diagnosis guidance applied` below) before writing this up as noise.
