### The `experiments/` directory: layout, packaging, invocation

- **D-01 — `experiments/` is a real Python package at the repo root with an `__init__.py`,
  invoked as `python -m experiments.eN_name`.** Verified safe: `pyproject.toml:73-74` sets
  `[tool.setuptools.packages.find] where = ["src"]`, so a top-level `experiments/` package is
  never discovered and never ships in the wheel. No build-config change is needed — do not add
  an exclude rule "to be safe", it would imply the directory was at risk.

- **D-02 — Final layout, matching the brief's target with one addition:**
  ```
  experiments/
    __init__.py
    README.md                      # provenance table + one command per artifact + runtimes
    _io.py                         # paths, run-record write, CSV writer, shared argparse
    _render.py                     # CSV → LaTeX; recomputes nothing

    e2_real_rig.py
    e7_interface_ablation.py
    e4_benchmark_grid.py           # relocated benchmarks/sweep_runner.py (EXP-03)
    results/                       # committed CSV/JSON — the figure inputs
  ```
  `e3`, `e5`, `e6` are Phase 19.2's files and are not created here — an empty stub is worse
  than an absence, because a stub passes `--smoke` while measuring nothing.

- **D-03 — ⚠️ `benchmarks/aggregate.py` becomes `experiments/_render.py`; `benchmarks/sweep_runner.py`
  becomes `experiments/e4_benchmark_grid.py`; `benchmarks/` is deleted.** This is EXP-03's
  relocation clause, and it is what gives `_render.py` a real implementation instead of a
  placeholder: `aggregate.py` already has `write_csv`, `_latex_escape`, and
  `write_latex_fragment` (`benchmarks/aggregate.py:113,166,180`) and recomputes nothing, which
  is exactly P1/P3's contract. Flagged because it moves a *verified-complete* Phase 19
  deliverable and its tests; the roadmap and REQUIREMENTS.md both already sanction it as a
  scope transfer, not a correction. `e4_benchmark_grid.py` lands here as a relocated skeleton
  only — **running the grid is 19.2/EXP-08**, and it must not be run in this phase.

- **D-04 — `experiments/` is linted but not pytest-collected.** Ruff and pre-commit cover it
  (`pre-commit run --all-files` already runs repo-wide). Its tests live in
  `tests/unit/test_experiments_*.py` — schema, CLI parsing, and `--check` comparator logic are
  unit-testable without running a calibration, and that keeps the pytest layout convention in

### X1 — promoting the shared verbs (EXP-01)

- **D-05 — `src/aquacal/datasets/pipelines.py` holds `calibrate_synthetic`,
  `evaluate_reconstruction`, and `compute_per_camera_errors`, exported from

  becomes a thin re-export shim, mirroring what `tests/synthetic/ground_truth.py` already does.

- **D-06 — ⚠️ Three signature changes are required, not optional, and each is a behavior
  contract the planner must not skip:**

  1. **`seed` becomes a parameter.** `experiment_helpers.py:69` hardcodes `seed=42` inside
     `generate_synthetic_detections`. Part 4 Rule 1 (`--seed` threads through) is *currently
     violated* by the function EXP-01 promotes. Add `seed: int = 42`; the default preserves
     E1's reproduction bar (D-19).
  2. **Drop the `sys.path` hack and the `tests.` import.** `experiment_helpers.py:30-38`
     inserts the project root into `sys.path` and imports `SyntheticScenario` /
     `generate_synthetic_detections` from `tests.synthetic.ground_truth`. In `src/` both come
     from `aquacal.datasets.synthetic` directly. A `src/` module importing from `tests/` would
     be a hard defect, not a wart.
  3. **`compute_per_camera_errors` widens to cover the committed CSV schema.** It returns
     `focal_length_error_pct`, `z_position_error_mm`, `xy_position_error_mm`, `k1_error`,
     `k2_error` — but the committed `exp1_parameter_errors.csv` header (verified live) is
     `camera,model,focal_length_error_pct,z_position_error_mm,xy_position_error_mm,gt_x_m,gt_y_m,gt_z_m,est_x_m,est_y_m,est_z_m,reprojection_rms_px`.
     Ground-truth and estimated centers are missing from the promoted function, so the notebook
     must have assembled them at the call site. Add them to the returned dict rather than
     recomputing them in `experiments/` (P2: the library computes, the experiment orchestrates).

- **D-07 — The gauge-freedom mean-shift correction lives in `pipelines.py`, not in the
  experiment script, and is an explicit keyword.** It is a scientific quantity — the mean Z
  error across *free* cameras (excluding the reference), subtracted from every
  `z_position_error_mm` — so P2 puts it in the library. Signature:
  `gauge_correct_z: bool = False`, with the docstring stating what it corrects and why
  (a per-camera Z error is only meaningful up to the world frame's Z datum, which the reference

  `False` so no existing caller changes behavior; E1 passes `True`. **The reason `cam0`'s row
  reads `xy_position_error_mm = 0.0` must appear in the docstring and in
  `experiments/README.md`** — a reviewer reading the CSV will ask.

### The provenance record for experiments that bypass the pipeline

- **D-08 — BRIEF CORRECTION. E1 and E7 never produce a pipeline `benchmark.json`, because
  `calibrate_synthetic` does not call `run_calibration_from_config`.** Verified:
  `experiment_helpers.py:82-134` calls `build_pose_graph`, `estimate_extrinsics`,
  `optimize_interface`, and `joint_refinement` directly. Part 4 Rule 2 ("this is `benchmark.json`
  re-used rather than anything hand-rolled") is therefore false for E1 and E7 as written, and its
  carve-out — which the brief scopes to E3 tiers 1–2 — actually has to cover them too.

- **D-09 — But the fix is not a hand-rolled sidecar: E1 and E7 call
  `aquacal.io.assemble_benchmark_record` themselves.** It is a pure, keyword-only, already-public
  assembler (`src/aquacal/io/benchmark.py:310`, exported from `aquacal.io.__all__`) taking
  `problem_shape`, `timings`, `diagnostics`, `solver_config`, `accuracy`, `environment`, and
  optional `memory_readings`. A direct-call experiment can fill every block it has and follow
  D-15's established null-with-reason discipline for the rest. Consequences:
  - **One schema, `schema_version: 1`, across the whole suite.** No second sidecar format, no
    aggregator that has to branch on provenance. D-04 (Phase 19) and REQUIREMENTS.md
    cross-cutting #10 both said the schema is settled — this honors that instead of routing
    around it.
  - `experiments/_io.py` stays I/O only (P3): it wraps `assemble_benchmark_record` +
    `write_benchmark_json` + `capture_environment` and computes nothing.
  - The `timings` dict E1/E7 pass must use the Phase-18 settled stage keys
    (`stage3_interface_optimization`, `stage3_intrinsic_pass`) so `_resolve_stage_seconds`
    resolves them. Do not invent an experiment-local stage vocabulary.

- **D-10 — Solver diagnostics reach E7 through the existing out-parameter, not a refactor.**
  `optimize_interface` and `joint_refinement` both already accept
  `diagnostics_out: SolverDiagnostics | None = None`
  (`interface_estimation.py:147`, `:539`) and populate it in place via
  `capture_solver_diagnostics`. E7 constructs one per arm per stage and passes it down. This is
  why E7 gets BENCH-01's convergence evidence "for free" — the mechanism is a keyword, and no
  pipeline plumbing is needed. `calibrate_synthetic` gains an optional
  `diagnostics_out: dict[str, SolverDiagnostics] | None = None` to forward them.

- **D-11 — `capture_peak_memory()` is not called by the experiment layer in this phase.**
  It is available (`src/aquacal/io/benchmark.py:172`) but BENCH-02's opt-in discipline is
  pipeline-side. E1/E7 pass `memory_readings=None`, so no `memory` key appears at all — which
  is the assembler's documented behavior and honest about not having measured it. Memory
  numbers for the paper come from E4's grid in 19.2, on one machine.

### E7 — the interface ablation (EXP-05)

- **D-17 — Four arms, one CSV, one conditioning JSON, per-arm trace CSVs; RMSE is a recorded
  column and never the headline.** Arms: `shared_interface` ∈ {True, False} ×
  `refine_intrinsics` ∈ {False, True}, on identical scenario/noise/target/seed. The

  `save_conditioning_report` are Phase 16, and `OptimizerObserver` supplies the traces.

- **D-18 — The failure must be labeled height/distance, never focal/standoff, and the refine-ON
  arm must not be presented as "what CalibMar produces."** Carried verbatim from the brief's two
  framing disciplines because a code-reading reviewer will check: naive per-camera mode is N free
  `water_z_i` beside N free camera centers, reintroducing `C_z_i ↔ water_z_i`. CalibMar solves
  each camera in its own frame and has no such redundancy. This constrains the *wording* of the
  CSV column names, the docstrings, and `README.md` — it is not only a manuscript concern.

### E1 — the port (EXP-06)

- **D-19 — ⚠️ E1's reproduction bar is threatened by library drift, and the phase pre-registers
  which divergences are acceptable.** The committed CSVs date 2026-02-24, before v1.7 and v1.8.
  Mitigating fact, verified: `calibrate_synthetic` bypasses the pipeline (D-08), so
  `reject_outlier_frames` never applies to E1, and v1.8's seeded `cv2.calibrateCamera` is
  Stage-1 in-air intrinsics, which a synthetic scenario bypasses entirely. **The expectation is
  therefore that E1 reproduces the committed values closely, and a large divergence is a porting
  bug, not library drift.** Concretely:
  - Reproduce at `seed=42`, `create_scenario("realistic")`, `refine_intrinsics=True`,
    `n_water ∈ {1.333, 1.0}`, `TEST_DEPTHS = [1.10, 1.20, 1.30, 1.40, 1.50, 1.70, 2.00, 2.50]`.
  - Compare against the three committed CSVs **before deleting anything** (D-13's deletion is
    ordered after E1's comparison passes).
  - Any moved value gets a written explanation naming a mechanism. "Numerical noise" is only
    acceptable at the last-digit level; a moved headline number (focal drift 0.033%/5.7%, RMS
    0.498/1.376 px, 0.38–0.42 mm vs 0.96 mm, Z-RMSE 1.9 vs 257 mm, Z/XY 2.3 vs 0.4–5.8) is a
    finding to report, not a tolerance to widen.

- **D-20 — `exp2_spatial_errors.csv` has no committed baseline and is a new output.** Searched
  the figures repo: `data/aquacal/synthetic_validation/` contains only
  `exp1_parameter_errors.csv`, `exp2_depth_generalization.csv`, and
  `exp3_xy_vs_z_anisotropy.csv`. EXP-06's "every value in the committed `exp{1,2,3}` CSVs"

  input and `evaluate_reconstruction` already computes it via `include_spatial=True`), but there
  is nothing to reproduce and no existing heatmap panel consuming it. Do not manufacture a
  comparison for it.

### The CLI contract (EXP-02)

- **D-21 — One shared `argparse` parent in `_io.py`, giving every script the identical five
  flags:** `--seed` (default 42), `--out` (default `experiments/results/`), `--force`,
  `--smoke`, `--check`. `--check` and `--force` are mutually exclusive and error rather than
  silently preferring one.

- **D-22 — `--check` compares numerically against a per-script declared tolerance, not
  byte-for-byte.** P6 asks for byte-stability, and that is the right target *on one machine*,
  but a strict byte compare across platforms fails on BLAS-level last-digit differences and the
  predictable result is that the check gets disabled — which is the failure P6 exists to
  prevent. So: non-float columns compare exactly; float columns compare at a tolerance declared
  as a module constant in each script (`CHECK_RTOL`); `--check` never overwrites, prints the
  worst offending cell, and exits nonzero. Determinism itself is asserted separately by a unit
  test on the comparator plus sorted-key CSV writing.

- **D-23 — Timestamps, hostnames, and wall-clock never enter a committed CSV** (P6). They live
  in the run record, which is `assemble_benchmark_record`'s `environment` block — already the
  case, via `capture_environment()`.

- **D-24 — Resumability is per-configuration output files keyed by config, skipped unless
  `--force`** (P5). For 19.1 this genuinely matters only for E7's four arms and E1's two model
  runs; implement it in the shared runner in `_io.py` anyway, because 19.2's E4/E6 grids are the
  cases that need it and retrofitting it after a grid exists is the expensive order.

- **D-25 — `--smoke` gets its own CI job in `.github/workflows/test.yml`, on
  `ubuntu-latest` + Python 3.12 only, not the full 2×3 matrix.** It is a "does the suite still
  import and emit the right schema" gate, so one platform is sufficient and six are waste.
  **E2's smoke must not download the Zenodo dataset**: if the dataset is absent it reports
  `SKIPPED` with a reason and exits 0 — a smoke test that silently passes without running is the
  same failure P7 exists to prevent, so the skip must be visible in the job log.

## Existing Code Insights

### Reusable Assets
- **`assemble_benchmark_record()` is general, not pipeline-specific.** Keyword-only, pure, no
