## Why the wave-3 version of this table was wrong

The first delta table reported six of nine quantities as MOVED, including a +72% jump on the
auxiliary fisheye. **Every one of those deltas was an artifact of the comparison, not the
library.** Two independent defects, both since fixed:

**Defect 1 — frameset mismatch.** The first run used the published Zenodo archive, which is a
~4.3× frame-subsampled extraction of the capture that produced §3 (60 usable frames → 12
validation → 1,817 comparisons, versus 262 → 52 → 7,762). Every validation-driven row was
comparing different-sized samples. Fixed by the `--config` flag added 2026-07-27, which runs
against the release config over the local raw videos while leaving the published-archive path
as the default.

**Defect 2 — statistic mismatch.** `real_rig_metrics.json`'s `mean_reprojection_px` came from
`result.diagnostics.reprojection_error_rms` — the **pooled RMS over all observations** —
while §3's "mean reprojection error" is the **mean of the per-camera RMS values**. On the
release run those are 1.0191 and 0.8786 respectively. Row 1 compared one against the other
under a single label. Fixed in `eefeaa6`, which emits `mean_per_camera_reprojection_px`
alongside the pooled value, with provenance strings naming which quantity §3 quotes.

Neither defect was visible from the numbers alone; both required returning to
`diagnostics.json` and asking what each figure actually measures. The wave-3 table assigned
confident mechanisms and Δ% values to comparisons that were not valid. Recorded because the
failure mode generalises: **a plausible delta with a plausible mechanism is not evidence that
anything changed.**
