# Phase 19.1 — Validation Strategy

> Per-phase validation contract for feedback sampling during execution.
> Derived from `19.1-RESEARCH.md` § Validation Architecture, with three Wave-0 gaps closed
> by direct inspection on 2026-07-25 (noted inline).

**The defining constraint of this phase:** its deliverables are *scientific numbers*, and the
runs that produce them take 20–60 minutes each. Fast automated validation can prove the
**scaffold** (imports, CLI contract, schema, comparator, zero-numerical-change) but cannot prove
the **science**. So this contract splits validation into three tiers and is explicit about which
tier each requirement lands in — a phase gate that treated a green CI run as proof the
experiments are correct would be the exact failure mode this phase exists to eliminate.

| Tier | What it proves | Latency | Gate |
|---|---|---|---|
| 1 — unit | scaffold correctness | seconds | every task commit |
| 2 — smoke | the suite still runs end-to-end at trivial scale | seconds–minutes | every wave merge + CI |
| 3 — real run | the science | 20–60 min each | phase close, partly **human** |

## Sampling Rate

- **After every task commit:** quick run command above. All three files are pure-logic unit tests
  — no calibration, no downloads.
- **After every plan wave:** full suite (`pytest tests/ -m "not slow"`) **plus** the tier-2 smoke
  command. A wave that moves code between packages (EXP-03) is exactly where an import breaks
  silently, and only the smoke run catches that.
- **Before phase close:** full suite green, all three `--smoke` exit 0, the `--smoke` CI job green,
  **and** the tier-3 items below discharged.
- **Max feedback latency:** 15 s for tier 1, ~2 min for a wave merge.

**No 3-consecutive-task gap rule:** the sequencing means EXP-01's promotion tasks, EXP-02's
`_io.py` tasks, and EXP-03's relocation tasks each carry their own unit tests, so no run of three
tasks passes without an automated signal. The exception is the tier-3 execution tasks (E1/E2/E7
runs) — those are inherently un-unit-testable and are individually gated instead (see
Manual-Only Verifications).

## Known Open Risks Carried Into Execution

- **A3 (MEDIUM)** — the shipped Zenodo config may not produce `spatial_measurements.csv`, which
  E2's `reconstruction_errors.csv` depends on. First task in E2's plan resolves it.
- **Pitfall 3 (needs a planning decision)** — `calibrate_synthetic(refine_intrinsics=False)` uses
  **ground-truth** intrinsics, which is *not* the same as intrinsics independently estimated from
  air. E7's "fixed intrinsics" arm is supposed to demonstrate the height/distance degeneracy under
  realistically-fixed intrinsics; GT intrinsics may make the arm cleaner than it should be.
  **The planner must resolve this explicitly**, not inherit it.
- **A2 (LOW)** — E7's 20–40 min estimate is unmeasured. Replace with the first real measurement.
- **`_build_interface_spread_report` is private** (`pipeline.py:731`). RESEARCH.md recommends
  promoting it (drop the underscore, export it) rather than duplicating five lines of untested
  logic in the experiment — consistent with P2 (the library computes).
