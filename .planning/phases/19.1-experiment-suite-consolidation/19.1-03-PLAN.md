**1. `build_experiment_arg_parser() -> argparse.ArgumentParser`** — the shared parent, built with
`add_help=False` so each script can pass it via `parents=[...]`. Exactly five flags, exactly these
names and defaults (D-21):
  `--seed` (`type=int, default=42`), `--out` (`type=Path, default=Path("experiments/results")`),
  `--force` (`action="store_true"`), `--smoke` (`action="store_true"`),
  `--check` (`action="store_true"`).
Each with a `help=` string. Do not add a sixth flag; the contract is five, uniform across scripts.

**2. `validate_args(parser, args) -> None`** — calls
`parser.error("--check and --force are mutually exclusive")` when both are set (D-21: error, do not
silently prefer one). Scripts call this immediately after `parse_args()`.

**3. `resolve_out_dir(out: Path) -> Path`** — `Path(out).resolve()`, `mkdir(parents=True,
exist_ok=True)`, log the resolved absolute path at INFO before returning it. This is the entire
`--out` control: reuse `aquacal.io.internals`' existing discipline (resolve + log + warn on
overwrite) and do NOT add a `..`-traversal block. RESEARCH § Security Domain assessed that as
disproportionate for a local single-user CLI, and inventing a guard here would diverge from the
established in-repo pattern.

**4. `write_experiment_csv(df, path, *, key_columns, force) -> bool`** — sort `df` by
`key_columns` (ascending, `kind="stable"`), reset index, then write with
`df.to_csv(path, index=False)`. Before writing, call `warn_if_overwriting(path)` imported from
`aquacal.io.internals` — do not write a second file-exists check with different wording. Returns
`True` if it wrote, `False` if it skipped. Resumability (D-24): if `path` exists and `force` is
False, log a message naming the path and the `--force` flag, and skip the write, returning `False`.
Raise `ValueError` if any of `key_columns` is missing from `df.columns` — a silent unsorted write
is exactly what Pitfall 5 warns about.

**5. `compare_experiment_csv(fresh: pd.DataFrame, committed_path: Path, *, key_columns, rtol)
-> ComparisonReport`** — the `--check` comparator (D-22):
  - Read `committed_path` with `pandas.read_csv`.
  - Assert both frames carry the identical column set in the identical order; a header mismatch is
    a hard failure reported as such (the committed headers are pinned contracts).
  - Sort BOTH frames by `key_columns` and reset index before comparing (Pitfall 5).
  - Compare via `pandas.testing.assert_frame_equal(fresh_sorted, committed_sorted,
    check_exact=False, rtol=rtol, check_dtype=False)` wrapped in `try/except AssertionError`.
    Non-float (object/string/int) columns must compare exactly — pass `rtol` only where pandas
    applies it to floats, and additionally assert object-dtype columns with an equality mask.
  - On mismatch, compute the per-cell relative difference over float columns and report the single
    WORST offending cell: its key-column values, its column name, the committed value, the fresh
    value, and the relative difference. Return a dataclass
    `ComparisonReport(passed: bool, worst_cell: str | None, worst_rtol: float,
    n_mismatched_cells: int, message: str)`.
  - NEVER write to `committed_path` and never write anywhere else from this function.
  - Provide `exit_code_for(report) -> int` returning 0 when `passed` else 1, so scripts exit
    nonzero on a `--check` failure.

**6. `write_direct_call_benchmark(path, *, problem_shape, timings, diagnostics, solver_config,
accuracy, force=False) -> bool`** — the D-09 wrapper for E1/E7, which bypass
`run_calibration_from_config`. Fills `environment=capture_environment()` internally and calls
`assemble_benchmark_record(...)` then `write_benchmark_json(record, path)`. Always pass
`memory_readings=None` (D-11: BENCH-02's opt-in discipline is pipeline-side, so no `memory` key
appears at all, which is the assembler's documented behavior and honest about not having
measured it). Do NOT call `capture_peak_memory()`.
  - Validate that every key in `timings` and `diagnostics` is one of
    `stage3_interface_optimization` / `stage3_intrinsic_pass`, raising `ValueError` naming the
    offending key otherwise. This is the guard against inventing an experiment-local stage
    vocabulary (D-09), and it is the same class of drift the Phase 19 verifier caught when
    `stage3.seconds` was always null.
  - Honor `force` for resumability the same way `write_experiment_csv` does.
  - This function must not compute or derive any number; every block is caller-supplied.

**7. Nothing else.** No plotting, no statistics, no scenario construction, no calibration call.
If a helper would compute a scientific quantity, it belongs in `aquacal.datasets.pipelines` (P2),
not here.

D-23: nothing in this module may put `datetime`, `time.time()`, `socket.gethostname()`, or a
wall-clock duration into a DataFrame destined for a CSV. Wall-clock and hostname belong in the run
record's `environment` block, which `capture_environment()` already supplies.

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| CLI args → filesystem | `--out` is a user-supplied path that determines where CSV/JSON files are written. The user is the same trusted researcher who invoked the script. |
| filesystem → comparator | `--check` reads repo-committed baseline CSVs with `pandas.read_csv`. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-19.1-07 | Tampering | `--out` path handling in `resolve_out_dir` | mitigate | Resolve to an absolute path, log it at INFO before writing, and call the existing `aquacal.io.internals.warn_if_overwriting` before every write. This is the established in-repo pattern and RESEARCH § Security Domain assessed it as adequate; a `..`-traversal block is explicitly NOT added, because it would be disproportionate for a single-user local CLI and would diverge from how the rest of the codebase handles output paths. |
| T-19.1-08 | Tampering | `--check` silently overwriting the committed baseline it is supposed to compare against | mitigate | `compare_experiment_csv` performs no writes at all, and `test_check_never_writes` asserts the committed file's bytes and mtime are unchanged after a failing comparison. `--check` and `--force` are mutually exclusive at the parser level. |
| T-19.1-09 | Tampering | A drifted stage key writes a `benchmark.json` whose stage seconds resolve to null (the exact defect the Phase 19 verifier caught in BENCH-04) | mitigate | `write_direct_call_benchmark` raises `ValueError` naming any `timings`/`diagnostics` key that is not `stage3_interface_optimization` or `stage3_intrinsic_pass`; `test_record_rejects_unsettled_stage_key` asserts it. |
| T-19.1-10 | Information Disclosure | `capture_environment()` writes hostname/CPU/OS into a committed `benchmark.json` | accept | Intentional and required by Part 4 Rule 2 — provenance is the deliverable. The repo is the researcher's own public scientific artifact; the same information already ships in every Phase 19 `benchmark.json`. D-23 keeps it out of the CSVs, which is the part that matters for byte-stability. |
| T-19.1-11 | Denial of Service | `pandas.read_csv` on a large committed baseline | accept | Baselines are repo-committed files of tens of KB, under version control, produced by this same suite. |
| T-19.1-SC | Tampering | npm/pip/cargo installs | accept | No packages installed. RESEARCH § Package Legitimacy Audit: not applicable — pandas, numpy, scipy, pytest are already core dependencies (`pyproject.toml:29-41`); `psutil` stays the `[bench]` extra and is unused here (D-11). |
