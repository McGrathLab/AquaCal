<mechanism>
**Use scipy's native `least_squares(callback=...)`.** Added in scipy 1.16.0; 1.17.0 is
installed. Supported for `trf` and `dogbox` (not `lm`) — both target sites are `trf`.
Signature: `callback(intermediate_result: OptimizeResult)`, fired once per **accepted**
iteration.

`intermediate_result` contains **only** `x`, `fun`, `nit`, `nfev`, `cost`. It does NOT
contain `optimality`, `step_norm`, or `jac` — those exist only on the final result. So:

- `iteration` <- `nit`; `cost` <- `cost`; `n_fev` <- `nfev` — direct.
- `interface parameters` <- sliced out of `x` (see `<param_layout>`).
- `step_norm` <- **derived**: cache the previous callback's `x` and record
  `norm(x - x_prev)`. Exact, zero extra cost. First row is `0.0`.
- `optimality` <- **an approximate proxy**, computed as `norm(J.T @ f, inf)` — the
  unconstrained gradient infinity-norm. It will NOT bit-match the `optimality` scipy reports
  on the final result, which applies Coleman-Li bound scaling this proxy skips. Document
  that in the docstring, the CSV header comment, and the SUMMARY. Do **not** try to recover
  the exact value by parsing `verbose=2` stdout — that format is not a public API and the
  verbose stream is already the user's progress display.
</mechanism>

<optimality_proxy_design>
Getting `J.T @ f` without doubling peak memory requires care. The Jacobian is dense and can
be gigabytes; the residual vector is only `m` floats.

Do this:
1. `observer.wrap_fun(fun)` returns a wrapper that calls the inner `fun(x, *args)`, caches a
   **copy of the returned residual vector** and the `x` it came from, and returns the inner
   result unchanged.
2. `observer.wrap_jac(jac)` returns a wrapper that calls the inner `jac(x, *args)` to get `J`,
   and — **before returning, while `J` is already in hand** — computes
   `self._last_optimality = float(np.linalg.norm(J.T @ f_cached, np.inf))` when
   `np.array_equal(x, self._x_cached)`, else `math.nan`. It then returns `J` and keeps **no
   reference to it**. Handle a sparse `J` by using `J.T.dot(f)`.
3. The callback reads `self._last_optimality`.

Why this ordering is safe: scipy's `trf` evaluates `fun(x_new)` for the trial step, and calls
`jac(x)` only inside the `actual_reduction > 0` branch — i.e. only after the step is accepted
and `x` has been reassigned to `x_new` — immediately before firing the callback. So the most
recent cached residual is at the same `x` the Jacobian is evaluated at.

**Never store `J` on the observer.** Holding a stale Jacobian while scipy allocates the next
one would add a full Jacobian to peak memory (the 13-camera rig already peaks near 3.6 GB).
The `array_equal` guard costs one `m`-length comparison and prevents silently reporting a
mismatched pair.

If `jac` is the string `"2-point"` (the `use_sparse_jacobian=False` path), there is nothing
to wrap — record `optimality` as `nan` for every row and note it in the CSV header comment.
</optimality_proxy_design>

<param_layout>
From `_optim_common.pack_params`'s docstring — the parameter vector layout:

```
[ if not normal_fixed: ref tilt rx, ry            (2) ]
[ for each non-reference camera in camera_order: rvec(3), tvec(3) ]
[ water_z                                          (1) ]
[ for each frame in frame_order: rvec(3), tvec(3)      ]
[ if refine_intrinsics: for each camera: fx, fy, cx, cy (4) ]
```

So the interface parameters are a cheap direct slice:
- `tilt_offset = 0 if normal_fixed else 2`
- `water_z_index = tilt_offset + 6 * (len(camera_order) - 1)`
- when `normal_fixed=False`, `tilt_rx = x[0]`, `tilt_ry = x[1]`; otherwise both are `nan`

Do NOT call `unpack_params` per iteration — it rebuilds every board pose and is wasted work
in a hot loop. Compute the indices once at the call site and pass them to the observer.

**Mandatory test:** assert that the `water_z` in the observer's final trace row equals
`unpack_params(result.x, ...)`'s water_z for that stage, to within exact float equality. That
pins the slice arithmetic against the real packer.
</param_layout>
