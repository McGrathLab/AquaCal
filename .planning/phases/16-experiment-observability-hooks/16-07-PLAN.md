<signature>
```python
@dataclass
class HeldOutEvaluation:
    """Result of scoring a calibration against a held-out detection set."""
    reprojection: ReprojectionErrors            # existing type, unchanged
    reconstruction: DistanceErrors | None       # existing type, unchanged; None when not requested
    board_poses: dict[int, BoardPose]           # independently estimated, returned so callers can reuse them
    num_frames: int


def evaluate_calibration(
    calibration: CalibrationResult,
    detections: DetectionResult,
    board: BoardGeometry,
    min_corners: int = 8,
    cameras: set[str] | None = None,
    board_poses: dict[int, BoardPose] | None = None,
    include_reconstruction: bool = True,
) -> HeldOutEvaluation:
```

`HeldOutEvaluation` is a thin container, not a new metric type — the two metric fields are the
pipeline's existing `ReprojectionErrors` and `DistanceErrors`, which is what CONTEXT.md's "no
new result type to document" is protecting. The container exists only because the pipeline
needs the estimated poses handed back for its diagnostics.

Semantics that MUST match the current pipeline exactly:
- **Poses are estimated using the FULL calibration** (all cameras present in `calibration`),
  then `cameras` filters only which cameras the error metrics are computed over. The pipeline
  today estimates poses from `final_intrinsics`/`final_extrinsics` — which include auxiliary
  cameras — and only afterwards filters to primary for the metrics. Preserve that ordering.
- `board_poses`, when supplied, skips estimation and is used as-is. This lets the pipeline
  evaluate auxiliary cameras against the same poses it used for primary, instead of
  re-estimating them (which is both wasteful and would not match today's behaviour).
- `include_reconstruction=False` skips `compute_3d_distance_errors` and returns
  `reconstruction=None` — matching the pipeline, which computes 3D errors for primary cameras
  only.
- `n_air`, `n_water`, and the interface normal come from `calibration.interface`, never from a
  config. The docstring must say that scoring a calibration against detections generated at a
  different refractive index is exactly the intended WP4 usage.
</signature>

```python
def test_matches_legacy_inline_sequence():
    """evaluate_calibration must reproduce pipeline.py's inline held-out block bit for bit.

    Mirrors run_calibration_from_config lines ~1108-1235 as of phase 16.
    """
    # ... build scenario, detections, and a CalibrationResult (all cameras) ...

    # --- Legacy sequence, copied verbatim from the pipeline ---
    legacy_initial = _compute_initial_board_poses(
        dets, intrinsics, extrinsics, board,
        min_corners=8, n_water=1.333,
    )
    legacy_poses = _estimate_validation_poses(
        dets, legacy_initial, intrinsics, extrinsics, water_zs, board,
        interface_normal, 1.0, 1.333,
    )
    legacy_target = _filter_cameras(full_result, primary_names)
    legacy_reproj = compute_reprojection_errors(legacy_target, dets, legacy_poses)
    legacy_3d = compute_3d_distance_errors(legacy_target, dets, board, include_spatial=True)

    # --- New path ---
    ev = evaluate_calibration(full_result, dets, board, min_corners=8, cameras=primary_names)

    assert ev.reprojection.rms == legacy_reproj.rms          # exact, not approx
    assert ev.reconstruction.mean == legacy_3d.mean
    assert ev.reconstruction.std == legacy_3d.std
    assert ev.reconstruction.rmse == legacy_3d.rmse
    assert set(ev.board_poses) == set(legacy_poses)
    for idx in legacy_poses:
        np.testing.assert_array_equal(ev.board_poses[idx].rvec, legacy_poses[idx].rvec)
        np.testing.assert_array_equal(ev.board_poses[idx].tvec, legacy_poses[idx].tvec)
    np.testing.assert_array_equal(
        sorted(ev.reprojection.per_camera), sorted(legacy_reproj.per_camera)
    )
```

Use exact equality (`==`, `assert_array_equal`), not `pytest.approx` — the whole point is
bit-identity. Both paths run the same deterministic `lm` solves from the same inputs, so
exact equality is achievable; if it is not, the extraction changed something and must be
fixed rather than the tolerance loosened.

Add a module-level comment above the test explaining that this is the CONTEXT.md-mandated
regression guard for the phase's one deliberate refactor, and that it must be updated only if
the pipeline's held-out semantics are intentionally changed.
