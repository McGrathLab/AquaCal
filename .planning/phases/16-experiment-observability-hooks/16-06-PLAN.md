**Gap 1 — the pipeline's own split has no seed.** `split_detections` (`pipeline.py:442`)
takes `seed: int = 42`, but the call site at `pipeline.py:706-707` is:
```python
cal_detections, val_detections = split_detections(
    all_detections, config.holdout_fraction
)
```
No seed is passed, so a real calibration run's holdout assignment is always seed 42 with no
way to change it. Two sweep runs intending different seeds would get identical splits.

**Gap 2 — nothing records the seed.** There is no `"seed"` key anywhere in `schema.py` or in
any output artifact. Accepting a seed without recording it does not make a result
reproducible from the artifact.
</audit_findings>
