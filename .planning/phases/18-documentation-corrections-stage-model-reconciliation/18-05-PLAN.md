<objective>
Correct the code-side half of DOCS-02: the four `estimate_extrinsics` sites that call the
traversal "BFS", the two comments that describe a prioritisation the loop does not perform,
and the missing "finalised on first discovery" invariant — while leaving
`_find_connected_components` untouched.

Purpose: `estimate_extrinsics` runs a priority queue keyed by `(-num_corners, node)`, not a
FIFO breadth-first search, but four sites call it BFS. Worse, the two "Score each neighboring
... by corner count, pick best first" comments describe scoring that does not happen in those
loops at all — they filter unvisited neighbours into a list in adjacency order and push each
onto the shared heap; the heap prioritises globally. A reader following those comments would
"fix" a non-bug. Meanwhile `_find_connected_components` really is FIFO BFS (`deque` +
`popleft`) and is correctly named, so a file-wide find-and-replace would introduce two new
errors while fixing four.

Output: Docstring and comment corrections in one file. No numerics, no control flow.

This plan is gated on plan 18-02's manuscript-vocabulary checkpoint because the replacement
term is exactly what that checkpoint confirms. D-12 and D-13 are correct fixes under EITHER
outcome, because they describe behavior rather than terminology — if the checkpoint returns
"keep BFS", Task 1 is re-scoped and Task 2 still ships in full.
