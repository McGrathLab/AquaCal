<objective>
Replace the hand-authored `bfs_pose_graph.png` with a figure generated by a script that
replays the library's own priority-heap traversal, and correct the glossary's backwards
pose-graph definition (DOCS-03).

Purpose: The current figure hardcodes its edges in `EDGES` / `BFS_EDGES` constants, so it can
drift from the code arbitrarily — and the glossary describes the graph backwards, saying
"edges connect observations of the same board pose" (a frame-clique graph) when the real
structure is bipartite: camera nodes on one side, frame nodes on the other, with an edge from
a camera to each frame it observes. The non-drift property is the whole reason D-09 wants a
heap-replaying generator rather than a redrawn PNG.

Output: `docs/_static/scripts/pose_graph.py` (new, replacing `bfs_pose_graph.py`), a
regenerated `docs/_static/diagrams/pose_graph.png`, updated batch wiring, an updated image
reference in `optimizer.md`, and a corrected glossary definition.

This plan is deliberately independent of the manuscript-vocabulary checkpoint (plan 18-02).
The filename `pose_graph.png` and the in-figure wording chosen below are neutral and correct
under BOTH candidate vocabularies, so the figure work does not need to wait. The remaining
BFS-word corrections in `optimizer.md` and `glossary.md` (the `Why BFS?` heading, the "via BFS
traversal" phrase) are checkpoint-gated and belong to plan 18-08.

It depends on plan 18-01 only because both touch `docs/guide/optimizer.md` — 18-01 owns the
numeric section, this plan owns the image reference line.
</objective>

|----------|-------------|
| repo -> Sphinx build process | `docs/conf.py`'s `config-inited` hook executes `generate_all.py` as a subprocess on every docs build, including in CI — this plan adds a new module to that execution path |
| repo -> published docs site | A figure that misrepresents the algorithm is a correctness failure in a reviewer-facing artifact |

This is the one place in the phase where new code executes at build time, so the register
below is about that, not about padded web-app categories. No network access, no user input,
no new dependencies.
