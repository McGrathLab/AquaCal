## Objective

Add `ValidationReport`, `CameraDrift`, and `RefinementResult` dataclasses and implement the validation pipeline that wraps `refine_calibration()`. After this plan, callers receive a `RefinementResult` with structured validation metrics and an accept/reject recommendation.

## Must-Haves (Goal-Backward)

- [ ] `RefinementResult` dataclass contains `result: CalibrationResult`, `validation_report: ValidationReport | None`, `accepted: bool | None`
- [ ] `ValidationReport` contains `holdout_reproj_error: float`, `triangulation_consistency_before: float`, `triangulation_consistency_after: float`, `camera_drifts: dict[str, CameraDrift]`, `summary: str`, `accepted: bool`
- [ ] `CameraDrift` contains `translation_mm: float`, `rotation_deg: float`, `exceeded: bool`
- [ ] Holdout split is per-camera with configurable fraction and seed
- [ ] Triangulation consistency measures mean ray intersection residual (point-to-ray distance) before and after
- [ ] Extrinsics drift checks translation (mm) and rotation (deg) per camera against configurable thresholds
- [ ] `accepted=False` when ANY threshold is exceeded (any-fail rejects)
- [ ] Summary string names the specific camera(s) and metric(s) that caused rejection
- [ ] `refine_calibration()` returns `RefinementResult` (breaking change to return type)
- [ ] `validate=False` skips validation: `validation_report=None`, `accepted=None`
- [ ] New types exported from `aquacal` package `__init__.py` and `__all__`

## Context

### Current State
- `refine_calibration()` in `src/aquacal/calibration/point_refinement.py` currently returns `CalibrationResult`
- `triangulate_point()` in `src/aquacal/triangulation/triangulate.py` provides ray-based triangulation
- `point_to_ray_distance()` is already available for measuring ray intersection tightness
- `PointCorrespondence` has `observations: dict[str, Vec2]` mapping camera names to pixels

### Design Decisions (from CONTEXT.md — locked)
- Holdout fraction default: 0.2, per-camera split (not global), seeded (default seed 42)
- Thresholds: holdout reproj 1.0 px, translation drift 50mm, rotation drift 2 deg
- Any-fail rejects — binary accept/reject, no warning level
- `RefinementResult` is always returned regardless of `validate` flag
- Before/after values stored in `ValidationReport` for caller display
- `camera_drifts` maps camera_id to `{translation_mm, rotation_deg, exceeded}`

<task id="2">
<title>Create validation.py module</title>
<description>
Create `src/aquacal/calibration/validation.py` with the validation logic:

```python
"""Validation logic for calibration refinement results."""

from __future__ import annotations

import numpy as np
from numpy.typing import NDArray

from aquacal.config.schema import (
    CalibrationResult,
    CameraDrift,
    CameraExtrinsics,
    PointCorrespondence,
    ValidationReport,
)
from aquacal.triangulation.triangulate import triangulate_point, point_to_ray_distance
from aquacal.core.camera import Camera
from aquacal.core.interface_model import Interface
from aquacal.core.refractive_geometry import refractive_back_project, refractive_project_batch
from aquacal.core.camera import create_camera
from aquacal.utils.transforms import matrix_to_rvec
```

Implement these functions:

**`split_holdout(correspondences, holdout_fraction, seed) -> (train, holdout)`**
- Per-camera aware: for each camera, randomly select `holdout_fraction` of the correspondences that include that camera. Union of selected indices becomes the holdout set.
- Actually simpler approach (per CONTEXT.md "split applied per-camera"): For each correspondence, it belongs to holdout if randomly selected with probability `holdout_fraction`. Use `np.random.RandomState(seed)` for reproducibility.
- Return two lists of `PointCorrespondence`.

**`compute_holdout_reproj_error(calibration, holdout, interface_params) -> float`**
- For each holdout correspondence, reproject its `point_3d` through each observing camera using `refractive_project_batch`, compute pixel error vs observed.
- Return RMS of all pixel errors.

**`compute_triangulation_consistency(calibration, correspondences) -> float`**
- For each correspondence with 2+ observations, triangulate from pixel observations using `triangulate_point()`.
- For each ray used in triangulation, compute `point_to_ray_distance()` from the triangulated point.
- Return mean of all ray distances (meters). This measures how tightly rays converge.

**`compute_extrinsics_drift(before, after, translation_threshold_mm, rotation_threshold_deg) -> dict[str, CameraDrift]`**
- `before` and `after` are `dict[str, CameraExtrinsics]`.
- For each camera, compute translation magnitude: `||C_after - C_before||` in mm (multiply by 1000).
- For rotation: compute relative rotation `R_rel = R_after @ R_before.T`, convert to angle via `np.arccos((trace(R_rel) - 1) / 2)` in degrees.
- `exceeded = translation_mm > threshold_mm or rotation_deg > threshold_deg`.

**`build_validation_report(holdout_reproj, tri_before, tri_after, camera_drifts, reproj_threshold, trans_threshold_mm, rot_threshold_deg) -> ValidationReport`**
- Check all thresholds, set `accepted`.
- Build `summary` string naming failing cameras/metrics.
- Return `ValidationReport`.
