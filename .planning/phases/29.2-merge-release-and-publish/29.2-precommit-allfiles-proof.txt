--------------------------------------------------------------------------------
0. WHY A CLEAN RESULT HERE IS NEWS AND NOT ROUTINE
--------------------------------------------------------------------------------

THIS COMMAND HAS NEVER BEEN INVOKED ANYWHERE IN THIS PROJECT BEFORE. Every hook
run in Phase 29 and 29.1 was scoped to named files with `--files`; no whole-tree
sweep appears anywhere in the project's history. `.github/workflows/test.yml:57`
has been running exactly this command on every push to `main` and every pull
request into it for as long as that job has existed -- but no pull request has
ever been opened on this repository, and the results branch has never been pushed
to `main`, so the job has never fired against this tree. The sweep below is the
first execution, anywhere, of the seven-hook configuration against all 1,711
tracked files.

That is why the four assertions exist. Until this run, "the excludes look right"
was a reading of a regex. It is now a measurement.

And it is why EXIT ZERO IS NOT THE BAR. Two of the seven hooks
(trailing-whitespace, end-of-file-fixer) rewrite in place and then report
success on what they rewrote; a third (ruff, `args: [--fix]`) rewrites SOURCE
the same way. A sweep that silently normalised the 143 deliberate missing
newlines and the 439 trailing-whitespace advisories inside the 227-file
provenance commit 70e783f would have exited zero while destroying the record.
Assertions 2 through 4 are what catch that; assertion 1 alone cannot.

4. ASSERTION FOUR -- THE DRIVER-STATE FILE IS STILL FIVE-FIELD ON EVERY LINE
--------------------------------------------------------------------------------

  $ awk -F'\t' '{print NF}' experiments/run_experiment_suite_state.7005a27.tsv | sort -u

5

(exit code 0)

The distinct field count across all 40 lines is the SINGLE value 5. Asserted by
string equality against that single value, so a second distinct count appearing
would fail rather than pass unnoticed:

  $ [ "$(awk -F'\t' '{print NF}' experiments/run_experiment_suite_state.7005a27.tsv | sort -u | tr '\n' ',')" = "5," ]

NF: SINGLE VALUE 5
(exit code 0)

Supporting count, which is the specific thing that would have broken:

  $ grep -c $'\t$' experiments/run_experiment_suite_state.7005a27.tsv

20
(exit code 0)

20 of the 40 lines END IN A TAB. That trailing tab IS the empty fifth column --
the exit-code field, empty on the `start` rows. Had trailing-whitespace stripped
it, those 20 lines would have become 4-field while the other 20 stayed 5-field,
and the `sort -u` above would have printed TWO values instead of one. That is
schema corruption, not whitespace.

WHY THIS ASSERTION IS HERE WHEN ASSERTION TWO WOULD ALSO HAVE CAUGHT IT: because
assertion 2 catches it GENERICALLY -- it would report that a file changed --
while this one names WHICH INVARIANT was at stake. Only the named one survives
into this file, where a future reader can see what the exclude was protecting
and why stripping twenty trailing tabs was never a tidying operation. That is
the whole reason D-29.2-03 was amended on 2026-08-26 to require it.

7. SCOPE -- WHAT THIS PROVES, AND WHERE THE PROOF STOPS
--------------------------------------------------------------------------------

Scope: this proves the seven-hook configuration against THIS tree at THIS sha --
12291c695a65b91ae2563361f8cfa0759536b9d5 on results/rerun-freeze-02 -- with the
hook runner that resolved on 2026-08-27, pre-commit 4.6.2. CI runs the identical
command on a fresh checkout of the same commit, and a fresh checkout of a commit
is the same tree, so the prediction that the `pre-commit` job goes green is as
strong as a local measurement can make it. IT IS STILL A PREDICTION UNTIL THE JOB
REPORTS. Three things can differ on the runner and none is controlled from here:
the unpinned `pip install pre-commit` may resolve a newer version than 4.6.2; the
hook repositories are pinned by rev in the configuration but their environments
are rebuilt from scratch there; and the runner is ubuntu-latest rather than this
machine. Section 9 records what the job actually did, which is the only thing
that closes the gap.

The proof also does not extend forward. Any commit pushed to this branch after
this sha changes the tree, and this evidence would then describe a tree that no
longer exists -- which is why nothing has been pushed to the branch since.
