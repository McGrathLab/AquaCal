### CI — the `pre-commit` job (criterion 1)

- **D-29.2-01:** **The exclusion lives in `.pre-commit-config.yaml`, not in `test.yml`.** Add an
  `exclude:` to `end-of-file-fixer` and `trailing-whitespace`. Repo-wide, so a local
  `pre-commit run --all-files` also cannot silently rewrite the 143 deliberately-newline-less
  artifacts and break the two md5 anchors. CI-only scoping was rejected: it leaves the local hooks
  armed against the exact bytes Phase 29 proved.
  — **Reversibility:** reversible — a config-file pattern, undone by deleting two lines.

- **D-29.2-02:** **Mirror the detect-secrets pattern verbatim:**
  `experiments/(pre_rerun_baseline/|freeze01_run_output/)?results[^/]*/.*`. One shape, one
  reasoning, already documented directly above it in the same file. **Measured coverage: 593
  tracked files, 0 `.py` (ruff unaffected), 15 `.yaml`.** It catches `results/`, `results_e2_band/`,
  `results_e2_invocations/`, `results_e4_repeat/` and both archive-aside copies.

- **D-29.2-03:** **Prove it locally before the PR: run the exact CI command
  `pre-commit run --all-files`, then assert `git status --porcelain` is EMPTY and both md5 anchors
  are unmoved** — `real_rig_metrics.json` = `57279708f6106f411d1fe03ed2698291`,
  `interface_ablation_band.csv` = `b6515ed77ed04268608b74217716020b`. **This command has never been
  invoked anywhere in this project** — Phase 29 scoped every hook run with `--files`. Exit 0 alone
  is not the bar; nothing may have been rewritten.

- **D-29.2-04:** **The exclude carries a short documented rationale block** naming the 143
  deliberate missing newlines, the two md5 anchors, and `gate3_git_sha_consistency` resting on them.
  The reason lives at the constant, not in a commit message or a todo that will be archived.

### CI — the `test` job, and the D4 anchor (NOT in the ROADMAP's criteria)

- **D-29.2-05:** **`tests/unit/test_optim_common.py::TestPerObservationDetailSinks::test_detail_sink_recomputed_geometry_matches_projector`
  IS FIXED IN THIS PHASE.** It is **not** `@pytest.mark.slow`, so `test.yml`'s `test` job
  (`pytest -m "not slow"`, ubuntu+windows × 3.11/3.12) reddens two ubuntu cells on the PR. Measured
  here 2026-08-26: `assert 0.10681280743540097 == 0.10681280743540099`.
  — **Reversibility:** reversible — two assertion lines in one test file, zero `src/` change.

- **D-29.2-06:** **The D4 todo's framing is WRONG for this member and the plan must not inherit it.**
  This test has **no captured anchor**. It recomputes the geometry inline and compares to the sink.
  The library computes `r_q = np.sqrt(dx*dx + dy*dy)` **vectorized over N points**
  (`src/aquacal/core/refractive_geometry.py:676`); the test computes it **scalar** on one element
  (`tests/unit/test_optim_common.py:1490`). NumPy's SIMD array path and its scalar path differ by
  ≤1 ULP. **A same-machine dispatch difference, not a Windows-pinned constant** — invisible on
  Windows only because that numpy build dispatched differently. The cross-platform-anchor question
  the todo routes to Phase 30 does not arise here.

- **D-29.2-07:** **Measured cost, all 22 rows instrumented** — the fix touches 2 of 4 assertions:

  | Assertion | Mismatching rows | Worst ULP gap | Action |
  |---|---|---|---|
  | `h_c_m` | 0/22 | 0 | keep `==` |
  | `h_q_m` | 0/22 | 0 | keep `==` |
  | `r_q_m` | 6/22 | **1** | ULP-bounded |
  | `chord_incidence_deg` | 3/22 | **2** (inherits r_q via `arctan2`/`degrees`) | ULP-bounded |

- **D-29.2-08:** **`pytest.approx` is FORBIDDEN here.** Its default `rtol=1e-6` is ~10 orders of
  magnitude looser than needed, and the test's own docstring correctly warns that a tolerance
  "would pass on a sink that had drifted to a different (but nearby) formula". A hard ULP bound
  still catches formula drift. **The docstring must be updated** to state the scalar-vs-vectorized
  reason at the constant — it currently asserts `==`/"never pytest.approx" as policy.

- **D-29.2-09:** **The other two D4 members are UNTOUCHED.** `test_matches_frozen_anchor` and
  `test_matches_pre_change_anchor` do read constants from `tests/fixtures/`, are both
  `@pytest.mark.slow`, and stay with the Phase-30 todo. Do not `skip`, `xfail` or `--deselect`
  anything, per that todo and D-29-13.

- **D-29.2-10:** **Supersede D-29-15's count invariant in this phase's record; do NOT rewrite prior
  artifacts.** State the new invariant: `pytest tests/` reports **2 failed**, both
  `@pytest.mark.slow`, both fixture-constant readers; `pytest -m "not slow"` reports **0**. Amend
  the D4 todo to name the remaining two and record why the third left the set. The
  `rerun-freeze-02` tag message and `29.1-PREPUSH-AUDIT.md` §1 stay readable as what was true when
  written — the same provenance reasoning that declined to edit MF-12 in place.
  — **Reversibility:** one-way — "three is the expected count" is cited in an immutable annotated
  tag message; the superseding statement is the only correctable surface.

- **D-29.2-11:** **Run all seven `--smoke` invocations from `test.yml`'s `experiments-smoke` job
  locally before opening the PR.** That job has never been exercised against this branch's code.
  Turn the unknown into a measurement where a failure is cheap, not into a red check on the
  release PR.

### PyPI (a verified criterion, not an unwatched side effect)

- **D-29.2-12:** **Shipping aquacal 2.1.0 to PyPI IS in scope and must succeed.** PROJECT.md's core
  value is `pip install aquacal`; a v2.1.0 that exists only as a tag leaves the public install two
  minors behind the code the paper cites.
  — **Reversibility:** one-way — a PyPI upload cannot be replaced or re-uploaded at the same
  version; only yanked.

- **D-29.2-13:** **Measured state 2026-08-26 — PyPI's latest is `1.8.0`. Neither 2.0.0 nor 2.0.1
  ever reached PyPI.** v2.0.0's publish run **failed at the `test` job** (build/publish skipped).
  v2.0.1's run **`31543691065` has been `waiting` for 358 h** with `test`, `build` and
  `publish-testpypi` all **succeeded**.

- **D-29.2-14:** **The cause is not a bug: the `pypi` GitHub environment carries a
  `required_reviewers` protection rule (reviewer `tlancaster6`); `testpypi` carries none.** The
  final upload waits on a manual approval press — the same "the irreversible act is a deliberate
  human one" shape as D-29-01. So 2.1.0 reaching PyPI needs exactly two things, neither of them new
  engineering: a green `test` job (D-29.2-05 delivers it) and the author's approval.

- **D-29.2-15:** **CANCEL run `31543691065`. Do not publish 2.0.1.** It is v2.0.1-era code the paper
  does not cite, its `test` job passed 15 days ago against a tree that has since moved 429 commits,
  and approving it would drop a version into the gap below 2.1.0 for no consumer. Record why the
  2.0.x tags carry no PyPI artifacts.

- **D-29.2-16:** **Ordering: approve the PyPI upload of 2.1.0 FIRST, then publish Record B.** Record
  B's prose says "Produced by AquaCal 2.1.0" — having it installable when the DOI is minted makes
  the record true in the strong sense. Both are manual presses, so the ordering is free.

- **D-29.2-17:** **Build the sdist locally and inspect its member list before approving PyPI.**
  Assert `experiments/` and `.planning/` are absent and the size is in line with 1.8.0's. There is
  **no `MANIFEST.in`**; the wheel is clean via `[tool.setuptools.packages.find] where = ["src"]`,
  but setuptools' default sdist walk is easy to reason about wrongly and none of the four prior
  successful releases carried 227 committed result artifacts. PyPI uploads are permanent.

  and `publish.yml`, in that order, with no pause between them.

- **D-29.2-19:** **The ROADMAP's parser figures are STALE — re-derive them.** Measured 2026-08-26:

  certainly does not match — but **"almost certainly" is not a measurement**. D-29.2-18's exact
  `== 2.1.0` assertion is what settles it. Do NOT reword the commit: rewriting it changes every sha
  after it on a 429-commit branch, including ones the tag and phase records cite.

- **D-29.2-21:** **`secrets.RELEASE_TOKEN` EXISTS** (created 2026-07-09, verified via `gh secret

- **D-29.2-22:** **`main` is NOT branch-protected** (`gh api .../branches/main/protection` → 404).
  Red checks do not mechanically block the merge. This is context for judgment, **not a licence to
  merge red** — D-29.2-05 and D-29.2-11 exist so the PR goes green on its merits.

- **D-29.2-23:** **Keep both the `results/rerun-freeze-02` branch and the `rerun-freeze-02` tag.**
  The tag is immutable and names the frozen sha `7005a27` that Record B's provenance cites. Decline

  attempts.
