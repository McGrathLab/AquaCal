## Objective

Comprehensive tests for the validation pipeline, result contract, and updated `refine_calibration()` return type. Ensures all acceptance criteria from the phase are verified.

## Must-Haves (Goal-Backward)

- [ ] Tests for holdout split: correct fraction, per-camera coverage, seed reproducibility, disjoint train/holdout
- [ ] Tests for holdout reprojection error computation: known-good scenario returns low error, perturbed scenario returns high error
- [ ] Tests for triangulation consistency: measures ray intersection tightness, improves after good refinement
- [ ] Tests for extrinsics drift: correct mm/deg computation, threshold crossing detection, per-camera details
- [ ] Tests for ValidationReport and acceptance logic: any-fail rejects, all-pass accepts, summary contains camera names
- [ ] Tests for RefinementResult structure: validate=True returns full report, validate=False returns None/None
- [ ] Existing test_point_refinement.py tests updated for RefinementResult return type (access `.result` field)
- [ ] All existing tests continue to pass

## Context

### Test Fixtures
Reuse the synthetic calibration setup from `tests/unit/test_point_refinement.py`:
- 3 cameras (cam0, cam1, cam2) with known intrinsics and extrinsics
- water_z = 0.15m
- Known 3D points with projected 2D observations

### Key Modules Under Test
- `aquacal.calibration.validation` — all validation functions
- `aquacal.calibration.point_refinement.refine_calibration` — updated return type
- `aquacal.config.schema` — new dataclasses

<task id="1">
<title>Create test_validation.py with unit tests for validation functions</title>
<description>
Create `tests/unit/test_validation.py` with these test groups:

**Imports:**
```python
from aquacal.calibration.validation import (
    split_holdout,
    compute_holdout_reproj_error,
    compute_triangulation_consistency,
    compute_extrinsics_drift,
    build_validation_report,
)
from aquacal.config.schema import (
    CameraDrift,
    CameraExtrinsics,
    PointCorrespondence,
    RefinementResult,
    ValidationReport,
)
```

**Test: `test_split_holdout_fraction`**
- Create 100 correspondences, call `split_holdout(corrs, 0.2, seed=42)`.
- Assert `len(holdout) / len(corrs)` is approximately 0.2 (within reasonable variance).
- Assert `len(train) + len(holdout) == len(corrs)`.
- Assert train and holdout are disjoint (no shared objects).

**Test: `test_split_holdout_seed_reproducibility`**
- Call `split_holdout` twice with same seed, assert identical split.
- Call with different seed, assert different split.

**Test: `test_split_holdout_empty_and_edge`**
- Empty list returns empty train and holdout.
- Single correspondence with fraction=0.5: either in train or holdout (not both).
- fraction=0.0: all in train, none in holdout.
- fraction=1.0: all in holdout, none in train.

**Test: `test_compute_extrinsics_drift_identity`**
- Same extrinsics before and after: translation_mm=0, rotation_deg=0, exceeded=False.

**Test: `test_compute_extrinsics_drift_known_shift`**
- Create before/after extrinsics where camera center shifts by exactly 100mm.
- Assert `translation_mm` is approximately 100.
- With threshold 50mm: `exceeded=True`. With threshold 200mm: `exceeded=False`.

**Test: `test_compute_extrinsics_drift_rotation`**
- Create before/after where rotation differs by ~5 degrees around Z axis.
- Assert `rotation_deg` is approximately 5.
- With threshold 2deg: `exceeded=True`.

**Test: `test_build_validation_report_all_pass`**
- Provide metrics that are all within thresholds.
- Assert `accepted=True`, summary indicates acceptance.

**Test: `test_build_validation_report_any_fail_rejects`**
- Provide one camera drift that exceeds threshold.
- Assert `accepted=False`, summary names the failing camera.

**Test: `test_build_validation_report_reproj_fail`**
- Holdout reproj error exceeds threshold.
- Assert `accepted=False`, summary mentions reprojection.

**Test: `test_validation_report_summary_names_cameras`**
- Two cameras exceed drift: assert both camera names appear in summary string.

Use the same `calibration_result` fixture pattern from test_point_refinement.py for tests that need a CalibrationResult. For pure unit tests of `compute_extrinsics_drift` and `build_validation_report`, construct inputs directly.

<task id="2">
<title>Update test_point_refinement.py for RefinementResult return type</title>
<description>
The existing tests in `tests/unit/test_point_refinement.py` call `refine_calibration()` and assert on the returned `CalibrationResult`. Since the return type changes to `RefinementResult`, update all assertions:

1. Scan for patterns like:
   - `result = refine_calibration(...)` — keep as-is
   - `result.cameras` — change to `result.result.cameras`
   - `result.diagnostics` — change to `result.result.diagnostics`
   - `result.interface` — change to `result.result.interface`
   - `result.board` — change to `result.result.board`
   - `result.metadata` — change to `result.result.metadata`

2. For tests that call `refine_calibration()`, add `validate=False` to avoid the overhead of validation (these tests focus on optimization correctness, not validation). This keeps them fast and avoids needing holdout-compatible correspondence counts.

3. Add a new test `test_refine_returns_refinement_result`:
   - Call `refine_calibration()` with `validate=False`.
   - Assert return type is `RefinementResult`.
   - Assert `result.validation_report is None`.
   - Assert `result.accepted is None`.
   - Assert `result.result` is a `CalibrationResult`.

4. Add a test `test_refine_with_validation`:
   - Call with `validate=True` (default), sufficient correspondences.
   - Assert `result.validation_report` is a `ValidationReport`.
   - Assert `result.accepted` is a `bool`.
   - Assert `result.validation_report.holdout_reproj_error >= 0`.
   - Assert `result.validation_report.camera_drifts` has keys matching camera names.

5. Run all existing tests to verify they still pass:
```bash
python -m pytest tests/unit/test_point_refinement.py -v
```
